# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
Until 1.0.0 the public API may change in any version.

A change of the result or of the error of an expression that was valid in an earlier version is listed under `Behavior changes` of its version.

## [Unreleased]

### Added

- Evaluation of field selection and `has()` on maps, `&&`, `?:` and the standard macros `all`, `exists`, `exists_one`, `map` and `filter`, with the errors `EvalNoSuchField`, `FieldSelectionNotSupported` and `EvalInvalidComprehensionRange`.
- `CelEvalOptions.CostLimit`: the cost limit of one evaluation; an operation whose cost would exceed it does not run, and the evaluation ends with `CostLimitExceeded`. Without a limit no cost is counted.
- Cancellation of an evaluation: a token that can be canceled is checked before the first call of an application function or macro step and then every 64; `CancellationToken.None` counts nothing.
- Checks of the values that enter and leave an evaluation, at any depth: a binding of another type than its variable is `BindingTypeMismatch`, an argument of an application function that does not fit its parameter is `EvalNoMatchingOverload`, and a result of another type than declared is `ImplementationResultMismatch`. An exception of application code is `ApplicationException`, an exception of the library `InternalError`, and a stack without room `InsufficientStack`.
- Compilation and evaluation of an expression: `CelEnvironmentBuilder`, `CelEnvironment.Compile<T>` and `CelProgram<T>.Evaluate`, with the result converted to the requested .NET type.
- Literals of the types `int`, `uint`, `double`, `string`, `bytes`, `bool` and `null`, list literals and map literals; a map is enumerated in the order of its literal.
- The standard library functions of logic, equality, arithmetic, ordering and conversion: `!`, `&&`, `||`, `?:`, `==` and `!=`; `+`, `-`, `*`, `/`, `%` and negation of `int`, `uint` and `double`, and `+` of strings, bytes and lists; `<`, `<=`, `>` and `>=` of `bool`, numbers, strings and bytes, also across `int`, `uint` and `double` when an operand is `dyn`; `type`, `dyn`, `bool`, `bytes`, `double`, `int`, `string` and `uint`; and the type identifiers such as `int` and `list`. Integer overflow is the error `Overflow`, a zero divisor `DivisionByZero` or `ModulusByZero`, a conversion outside the range of its type `ConversionRange`, and a text that does not parse `InvalidArgument`; numbers are parsed and written without the culture of the process.
- The standard library functions of lists, maps and strings: indexing of lists and maps, `in`, `size` of strings, bytes, lists and maps, and `contains`, `startsWith` and `endsWith`. A list index outside the list is the error `IndexOutOfRange`, an index of the type `double` that is not an integer `InvalidArgument`, and a missing key `NoSuchKey`; a map finds a key of another numeric type with an equal value, so `{1: 'a'}[dyn(1.0)]` is `'a'`. An index of an operand of the type `dyn` is chosen by the kind of its value, so `dyn([7])[0u]` is `7`. The size of a string counts code points, and `contains` finds a substring in time linear in the lengths of the string and the substring.
- Variables declared in code or in an environment description in JSON (`CelEnvironmentJson`).
- Parse, type and evaluation errors as results, not exceptions, each with its code of `CelErrorCode`, its stage and its place in the expression.
- Parsing of the complete CEL syntax: the conditional operator `?:`, `&&`, comparisons and `in`, subtraction, multiplication and remainder, logical not, field selection, also of escaped field names in backticks, indexing, receiver-style calls, message literals and names with a leading dot. A message literal is parsed, but its type name is reported as `UndeclaredReference` until object types are available.
- The parse errors `ReservedIdentifier`, for a reserved word such as `if` used as a name, and `SyntaxNotEnabled`, for the optional syntax `.?`, `[?` and `?` without its extension set and for `decimal` literals such as `1.5m`.
- Parsing of the standard macros `has`, `all`, `exists`, `exists_one`, `map` with two or three arguments and `filter`, with the parse error `InvalidMacroCall` for a call that a macro cannot expand, such as `xs.all(1, true)` or `has(x)`.
- The limits of parsing for untrusted text, on the new page [Limits](docs/limits.md): 65,536 UTF-8 bytes of text (`ExpressionTooLong`), a nesting and a syntax tree depth of 250 (`NestingTooDeep`), 100 errors (`TooManyErrors`), and `InsufficientStack` instead of a stack overflow on a thread with a small stack.
- Parsing reports every error of a text, up to the limit, in the order of the text: after a syntax error it goes on at the next comma or closing bracket. An unexpected exception inside the parser becomes the error `InternalError` with the original exception.
- `CelCompileOptions.SourceLocation`: the position at which an expression starts in its source document. Every compilation and evaluation error of the expression then has its position in the document in `CelError.SourceLocation`.
- The type model of CEL: `CelType.WrapperOf`, `CelType.TypeOf`, `CelType.ObjectNamed` and `CelType.TypeParameter`; wrappers are written `wrapper(int)` in messages.
- Type values: `CelValue.FromType` and `CelValue.TryGetType`; a type value compares by the kind and the name of its type, so the type value of `list(int)` equals that of `list`.
- `CelValue.CelEquals`, the CEL equality: `int`, `uint` and `double` on one number line, a NaN equal to nothing, strings by code units, lists and maps by their elements.
- Variables and bindings of enumerations, `[Flags]` included, as `int`; of nullable value types as wrappers such as `wrapper(int)`; and of `CelValue`, `CelList`, `CelMap` and `object`. An enumeration on `ulong` above the range of `int` is the evaluation error `ConversionRange`.
- Functions of the application declared with `CelEnvironmentBuilder.AddFunction` — from a .NET delegate, or as a `CelFunctionDecl` of overloads called globally or on a receiver, with type parameters and a cost function (`CelOverloadDecl.WithCost`) — and implemented with `AddFunctionImplementation`. A typed delegate gets its arguments converted to its .NET types; an argument that does not convert is the evaluation error `ArgumentConversion`.
- Build errors of an environment, all reported by `CelEnvironmentBuilder.Build` in an order that does not depend on the order of the calls: `DuplicateVariable`, `OverlappingOverloads`, `StandardLibraryConflict`, `MissingImplementation`, `TypeNotDeclared`, `UnusedImplementation`, `ImplementationSignatureMismatch`, `DuplicateOverloadId`, `DuplicateImplementation`, `InvalidFunctionName`, `InvalidVariableName` and `ContainerConflict`. The same declaration repeated is one declaration.
- `CelEnvironmentBuilder.UseContainer`, the name resolution container of an environment; `CelEnvironment.ToBuilder`, a builder with the declarations of an environment; `CelStandardLibrary.Version`.
- Type checking of the complete syntax by the gradual type checking of the CEL language definition: type parameters of overloads deduced at each call, also through type values, receiver-style calls, field selection on maps and `dyn`, indexes, the standard macros and their variables, the type identifiers such as `int` and `list`, and names resolved in the container, the longest qualified name first. A compilation returns every check error, ordered by place, with the new errors `TypeMismatch`, for an operand of `&&` or `||` that is not a `bool`, `NoSuchField`, for a selection on a type without fields, and `InvalidComprehensionRange`, for a macro over a value that is not a list or a map; `InsufficientStack` and `InternalError` end type checking instead of an exception.
- `CelCompileOptions.ExpectedType`, and the expected type that `T` of `Compile<T>` implies: an expression whose type is not assignable to it is the compilation error `ExpectedTypeMismatch`, and an expected type that `T` cannot hold throws `ArgumentException` before the text is read.
- `CelEnvironment.Evaluate<T>`: compilation and evaluation in one call, with the result and the errors of `Compile<T>` followed by `CelProgram<T>.Evaluate`; the token is checked before the compilation and between the two steps.
- `CelCompilationCache`: a bounded, thread-safe cache of compilations of one environment, with a capacity of entries and of the total text length; unsuccessful compilations are kept too, and `CelCompilationCache.Evaluate<T>` is the one-step call through the cache.
- Results of the types `IReadOnlyList<X>`, `IReadOnlyDictionary<XK, XV>`, `CelList`, `CelMap`, `CelType`, `Nullable<X>` and `object`: a list or a map is a lazy view when no element can fail its conversion, and an immutable copy otherwise. Before a lazy view the value is checked against the type that `T` reads, with `null` allowed where the view reads a null reference, such as an element of `IReadOnlyList<string>`, so a view and a copy give the same result. A `T` outside the type mapping, such as `short` or `Guid`, throws `ArgumentException`.
- Parameters of typed delegates of the types `IReadOnlyList<X>` and `IReadOnlyDictionary<XK, XV>` in `AddFunctionImplementation`. The CEL type of a parameter is the one the expected type of `Compile<T>` gives its .NET type and must be the declared one: `Guid`, `short`, `float` or an enumeration, also in the delegate form of `AddFunction`, is `ImplementationSignatureMismatch` when the environment is built. A declared `wrapper(string)` or `wrapper(bytes)` also takes a `string` or `byte[]` parameter or result, with `null` as a null reference. With a cost limit, a parameter that is a copy is charged before the call: a list of n elements 1 + n, a map of n pairs 1 + 2n and ⌈L/10⌉ for each string key of length L, and a `byte[]` of L bytes 1 + ⌈L/10⌉; a lazy view and `ReadOnlyMemory<byte>` cost nothing.
- The new pages [Standard library](docs/standard-library.md), [Cost](docs/cost.md) and [Type mapping](docs/type-mapping.md) with the tables of the functions, the cost units and the conversions of values; the page [Limits](docs/limits.md) now also has the limits of evaluation, the recommended capacities of `CelCompilationCache` (80,000 entries and 900,000 code units of text) and the ranges of values.
- The targets `net10.0` and `net11.0`, under JIT and Native AOT.
