# Objects: type providers and object values

An application gives expressions its own object types through type sources: `CelTypeProvider` with `CelObjectType` and `CelEnumType` descriptions. This page covers the descriptions, the builders of types described at run time — `CelObjectTypeBuilder<TCarrier>` over a carrier class and `CelObjectTypeBuilder` over a dictionary carrier — the type index of an environment, object values, field numbers, presence, `null` and the equality of objects. Type checking of fields is in [checking](checking.md), the evaluation nodes in [evaluation](evaluation.md), collections and `JsonElement` in [values](values.md). Descriptions of .NET types come from the source generator and the protobuf package with their parts; the rules below already hold for them where they say so.

| File | Content | Core |
| :- | :- | :- |
| `src/Great.Parts.Cel/Values/CelObjectType.cs`, `CelObjectField.cs`, `CelEnumType.cs`, `CelTypeProvider.cs` | the public descriptions and the provider | no |
| `src/Great.Parts.Cel/Values/CelObjectTypeBuilder{TCarrier}.cs`, `CelObjectTypeBuilder.cs` | the builders and the internal sealed descriptions they build | no |
| `src/Great.Parts.Cel/Values/CelValue.Objects.cs` | `FromObject`, `TryGetObject` | no |
| `src/Great.Parts.Cel/Values/TypeIndex.cs` | the type index of an environment | no |
| `src/Great.Parts.Cel/Values/ObjectRules.cs` | the description of an object value, the place rule, the field value of a type described at run time, the default equality of objects | yes |

The descriptions keep no logic that decides a value or an error: the internal descriptions of the builders and the public default members (`CelObjectType.CelEquals`) delegate to `ObjectRules`, as [core](core.md) requires of rule files.

## Descriptions

- **`CelObjectType`** — `Name`, a full CEL name: identifiers of the language definition separated by `.`; `ClrType`, `null` for a type described at run time; `Type`, `CelType.ObjectNamed(Name)`; `Fields`, the field at position i has the number i. The constructor checks the name, the numbers and that field names are distinct; `TryGetField` finds a field by name through a frozen dictionary built once. `IsConstructible` is `false` and `GetExcludedFieldReason` returns `null` by default; generated code and the protobuf package override them with their parts. `FieldError(number, code, detail)` creates the error value of a field that cannot be read or set: its text is the template of the code in the error table and nothing else — the field and the type stand only where the template names them, `detail` fills the free part of the template, and there is no prefix that names the field, which the position of the selection names. So 3017 `UnexpectedNull` is `member '{member}' of type '{type}' is null, but its CEL type does not allow null` without `detail`; 3007 `ConversionRange` is `{value} is out of the range of {targetType}`, given by `detail`, as the refusal of `FromEnum` for a value above `long.MaxValue`, `18446744073709551615 is out of the range of int`; 3008 `InvalidArgument` is `invalid argument to '<type>.<field>': {detail}`; 3012 `TypeNotAccessible`, the refusal of `FromDynamic`, names the .NET type.
- **`CelObjectField`** — number, name, type. The name is an identifier, a reserved word included, or for a protobuf extension a dotted name; the type is any `CelType` except a type parameter.
- **`CelEnumType`** — a full name and its constants, name and `long` value, aliases allowed. A constant is the identifier `<type>.<constant>` of the type `int`.
- **`CelTypeProvider`** — `SourceName`, not empty, and immutable arrays of object and enumeration types. `Create(sourceName, objectTypes)` is a provider of types described at run time without enumerations; it does not check names against each other, `Build` does.

A description is immutable; every member can be called from any number of threads at once.

## Types described at run time

`CelObjectTypeBuilder<TCarrier>(name)` collects fields: `AddField(name, type, read, has)` gives the field the next number; a repeated name, a name that is not an identifier of the language definition (reserved words allowed: `in`, `as`, `true`, `null`, selected in backticks, `` deal.`in` ``; a name with `-`, `.`, `/` or a space is refused, though backticks allow it) and a type parameter are `ArgumentException` at once. `Build()` returns a new internal sealed description over a copy of the fields with `ClrType` `null` and the carrier class `TCarrier`; later `AddField` calls do not change it. `CelObjectTypeBuilder.ForDictionary(name)` is the same over the carrier `IReadOnlyDictionary<string, object?>`, where the field `f` is the entry with the key `f`.

Reading the field number i of a carrier `c` — `GetField(c, i)`, by `ObjectRules`:

1. **Presence.** With a `has` delegate, `has(c)` is `false` → `FieldNotSet` (3018) `field '{field}' of type '{type}' has no value`. Without one, the value of `read(c)` is taken once, and the value `null` is not present → 3018. Over a dictionary the field is present when the key is.
2. **Value.** `read(c)`; over a dictionary the value of the entry, in this order:
   1. the declared type of the field is an object type `T` whose description has the carrier class `IReadOnlyDictionary<string, object?>` — a type of `ForDictionary`, or of `CelObjectTypeBuilder<IReadOnlyDictionary<string, object?>>` — and the entry value is an instance of that interface: it is a bare carrier of `T`, which step 3 pairs with `T` by the place rule;
   2. otherwise the entry value converts as a value of the .NET type `object` ([values](values.md), "Conversions"): a boxed `CelValue`, a `CelList` and a `CelMap` as they are, a `JsonElement` by its section, any other instance as a bare object value, a .NET collection included. The field node then reads it by the steps of "Reading a value of the application" below: an instance of the collection feature — `System.Collections.IEnumerable` except `string`, `byte[]`, `CelList` and `CelMap` — that the type index describes, by its exact type or a base class, is an object value of that description; one that it does not describe does not convert — in a field of type `dyn`, `list(…)`, `map(…)` or an object type whose carrier is not a dictionary, and a dictionary of another type than `IReadOnlyDictionary<string, object?>` in any field: it is `FieldTypeMismatch` with the actual type written as its .NET type, `Type.ToString()`.
3. **Declared type, top level only.** The value must fit the declared type of the field at the top level: the kind for a primitive, `list(…)`, `map(…)` and `type(…)`; `null` or the primitive for `wrapper(P)`; `null` or an object value of the type for an object type, by the place rule below; anything for `dyn`. Otherwise `FieldTypeMismatch` (3019) `field '{field}' of type '{type}' has a value of type '{actualType}', expected '{declaredType}'`, `{actualType}` the name of the type of the value without parameters ([values](values.md), "Runtime type"). The check does not descend into a list or a map: reading a field costs 1 unit whatever the size of its value ([evaluation](evaluation.md), "Cost"), and the elements of a collection of the application are checked where an operation reads them. An error value that `read` returns is the value of the field.

`has(e.f)` is step 1 alone. An exception of `read` or `has` is not caught here; evaluation turns it into `ApplicationException` ([evaluation](evaluation.md), "Fields of objects"). So for `has()` and `null` the field types of a type described at run time behave as follows: `wrapper(P)`, an object type, `dyn` and `null_type` take `null` as a value of a present field, any other type does not (3019), and `has()` is the presence of step 1. Object literals of these types are not supported: `IsConstructible` is `false` (2008, [checking](checking.md)).

## Descriptions of .NET types from the generator

A type context that the source generator completes is a `CelTypeProvider` whose descriptions derive from `CelObjectType` with a `ClrType`: `GetField` and `HasField` are a `switch` on the number over a direct access to the member, `GetExcludedFieldReason` answers for the members that the generator left out, and `CelEquals`, `IsConstructible` and `CreateInstance` keep their defaults ([generator-output](generator-output.md)). An application adds the context with `AddTypes(OrderContext.Default)`; the source name is the name of the context class. The rules of this page hold for these descriptions as they are written: a bare instance is described by its exact .NET type, then its base classes; a field of an object type takes the description of its declared type by the place rule. A field of an excluded member is not a field, and selecting it is `FieldNotAccessible` (2007) with the reason of the generator in the text.

**Place rule inside collections.** An element or a value of a collection that the created code reads is paired with the description of its declared element type when its exact type is another, so it fits `list(Animal)`; the converter does it by the static type of the element ([generator-output](generator-output.md), "Place rule inside collections"). A list that the application builds itself and declares `list(Animal)` holds values that are `Animal` by `CelValue.FromObject`; a bare subclass instance in it does not fit, and the library does not widen the fit. This holds in a context whose description of the element type was dropped by the rule of the next paragraph too: its pair names the dropped description, which the index keeps as an alias. It supersedes the sentence of "Object values" that says elements pair with the generator, until it exists.

**Types that two generated contexts share.** Two type sources of the environment that are both `CelTypeContext` and describe one .NET type are one declaration, not `DuplicateType`, when the descriptions have *equal form*: the same `Name`, the same `ClrType`, the same number of fields and, field by field, the same name and an equal `CelType`; for an enumeration, the same name and the same constants in the same order. The description of the source whose name is smaller, ordinal, stays in the index, and the other is dropped, so the environment does not depend on the order of the calls. Descriptions of one .NET type that differ — in a field name, a type, a `Name` — are `DuplicateType` with the two sources named, as for any two descriptions; so are two descriptions with one name for two .NET types, and a description from a source that is not a `CelTypeContext` (a type described at run time has no `ClrType`; two providers of protobuf are `DuplicateType` whatever their form). The reasons of excluded members are not part of the form: they change the text of one error only. **The dropped description is an alias.** The created code of the context that lost still names its own description of the type: `CelValue.FromObject(Description, e)` for an element of a list of a class that is not sealed or of an interface ([generator-output](generator-output.md), "Place rule inside collections"). The description that is dropped therefore does not vanish: `TypeIndex` keeps a map from each dropped description, by reference, to the description that stays, and the map is empty when nothing was dropped. A pair whose description is a dropped one is described as the one that stays: `ObjectRules.Describe` of a pair resolves the alias through the index, so it fits `T`, answers `type()` with the name, and compares equal to a pair or a bare instance of the one that stays, in either order of the two contexts. The field numbers agree, since equal form means the same fields in the same order, so a read through either description gives the same value. A planned selection of a field takes its fast path when the pair carries the description of the plan, and the by-name path otherwise, which resolves the alias and gives the same value, the same error and the same charge; the tests of the rule compare both paths. The map is not part of the public API and is not shown: only the index and the environment know it, and an environment of one context has none. The rule is in `Declarations/DeclarationChecks.cs`, where the descriptions are collected, in `Values/TypeIndex.cs` where the index is made and the alias is kept, and in `Values/ObjectRules.cs` (`Describe`, one function) where the alias is resolved; `DuplicateType` of the sources that stay is reported as it is. This supersedes the sentence of "Type sources of an environment" that leaves the rule to the generator.

## Type sources of an environment

`CelEnvironmentBuilder.AddTypes(provider)` collects providers as a set: adding the same provider twice adds nothing. `Build` merges them into one `TypeIndex` with the declarations of [declarations](declarations.md) and reports, with the other build errors and in their order:

| Code | When | Message |
| :- | :- | :- |
| `DuplicateType` (4001) | two descriptions that are not the same instance with one CEL name, in one source or in two; a name of an object or enumeration type equal to a type identifier of the standard library version (`int`, `list`, `google.protobuf.Timestamp` …); two descriptions that are not the same instance with one .NET type, in one source or in two, `{name}` then the .NET type by `Type.ToString()`: the index finds a description by its .NET type, which must be unique. The same description instance in two providers is one declaration | `type '{name}' is declared by both {source1} and {source2}` |
| `TypeNotDeclared` (4008) | an object type named in the type of a field that no source describes; `{declarationKind}` `field`, `{name}` `<type>.<field>` | as in [declarations](declarations.md) |

A provider is the source `type source '<SourceName>'`. Of the two sources, the standard library comes first, otherwise the smaller text, ordinal, so the message does not depend on the order of the calls; two descriptions of one source name it twice. Identical descriptions of one .NET type from two generated contexts are one declaration by the fingerprint of their form.

`TypeIndex` holds, frozen: object types by name; enumeration constants by full name; descriptions that have a .NET type by that type; and the aliases of descriptions that were dropped as equal to another ("Types that two generated contexts share"). A variable or overload type `ObjectNamed(n)` is declared when the index has `n`. The [checking](checking.md) index takes type names and constants from it as identifiers.

## Object values

A value of the kind `Object` holds either the instance itself — a *bare* instance, which `CelObjectType.FromInstance` and the conversions create without allocating — or an internal *pair* of a description and the instance, which `CelValue.FromObject(type, instance)` creates. `FromObject` throws `ArgumentException` for an instance that does not belong to the type: not an instance of `ClrType`, or not of the carrier class. `TryGetObject` returns the instance of either form. .NET equality of object values compares the instance and the description of a pair by reference.

**Description of a value** — `ObjectRules`, during an evaluation, with the type index of the environment, which the frame holds:

- a pair — its description;
- a bare instance — the description of its exact .NET type in the index, else of its nearest base class there; interfaces are not considered. None: the value is not accessible, and the node that needs its description gives `TypeNotAccessible` (3012) `.NET type '{clrType}' is not available to expressions: no type source of the environment describes it` at its position. A carrier of a type described at run time is never in the index.

**Reading a value of the application.** The node that reads a value from the application with the type index — the identifier at the first read of a variable, the field selection for the value of a field, the call for the result of an application function — takes the value that the conversions gave ([values](values.md), "Conversions": the `object` row rejects no instance) and decides, in this order:

1. The place is declared with an object type `T` — a variable or a field, by the place rule below — and the value belongs to `T`: a bare instance of its `ClrType` or of its carrier class, `IReadOnlyDictionary<string, object?>` included, or a lazy view of the input rows whose source is such an instance. It is the value of `T` by the place rule.
2. Otherwise a bare instance of the collection feature — `System.Collections.IEnumerable` except `string`, `byte[]`, `CelList` and `CelMap` — that the index describes, by its exact .NET type, then its base classes, is an object value of that description, though it is enumerable.
3. Otherwise a bare instance of the collection feature is `TypeNotAccessible` (3012) with its .NET type at the reading node: the identifier, the selection, the call. In a field of a dictionary carrier it is `FieldTypeMismatch` (3019) with its .NET type ("Types described at run time", step 2).
4. Otherwise a bare instance stays as it is: an object value without a description, which the node that needs the description resolves lazily, as above.

Steps 2 and 3 concern only an instance of the collection feature, so the read looks up the index only for it; any other bare instance passes on at once. The check against the declared type of the place — 3011 for a variable, 3019 for a field, 3028 for a result — follows the steps; an error of step 3 is already the result. An element or a value of a collection of the application that an operation of the library reads — an index, a key lookup, an enumeration, equality — takes none of the steps: it is the value of the `object` row, described lazily where its description is needed. So a .NET collection as an element of an `IReadOnlyList<object>` is a bare object without a description: `v[0].f` is 3012, `size(v[0])` is `EvalNoMatchingOverload`, and `v[0] == [1]` is `false`, as an object and a value of another kind are.

A node needs the description to work only to select a field or test presence by name, for `type()` and to compare two object values (with `==`, `!=`, `in` and the equality of collections). Reading or passing a value on does not need it, so an inaccessible instance inside a list or in a `dyn` binding fails only where it is used. Checking a value against a type never gives 3012: a mismatch there names the .NET type of an inaccessible instance ("Fits"). The result conversion is an instance test of the requested .NET type — a refusal is `ResultConversion` with the same name — and the `object` and `CelValue` rows return the instance as it is.

**Place rule.** Where a value enters from the application at the top level of a place declared with an object type `T` — the first read of a variable, the value of a field — a bare instance that belongs to `T` (an instance of its `ClrType`, or of its carrier class) is the value of `T`, as the type mapping table says of a place with a static type. The rule looks through a lazy view that the input rows made from the static type of a binding — the rows `T[]`, `IReadOnlyList<T>`, `IList<T>`, `IReadOnlyDictionary<K, V>` and `IDictionary<K, V>` ([values](values.md), "Input rows of objects and collections"): such a view at the top level of the place is its source. So a dictionary bound as `IReadOnlyDictionary<string, object?>` or `IDictionary<string, object?>` to a variable of a type whose carrier class is `IReadOnlyDictionary<string, object?>` — a type of `ForDictionary`, which the application may know only by its name in the JSON description of the environment — is a carrier of that type, as is the same dictionary bound as `object`; a view whose source does not belong to `T`, such as `IReadOnlyDictionary<string, string>`, stays a `map`. A view that the application created — `CelList.CreateView`, `CelMap.CreateView`, `CelValue.FromMap` — is a value of the application whose converter decides the values, and the rule does not look through it. In a place of type `dyn`, `list(…)` or `map(…)` a view stays a view. When the description of the instance by the index is not `T`, which for a type described at run time is always so, the node pairs the instance with `T`: one allocation of at most 64 bytes, inside the unit of the read. A pair fits `T` only when its description is the description of `T` in the index, the same instance, or a description that the index dropped as equal to it ("Types that two generated contexts share"); another instance with the same name does not fit, since its field numbers are its own. The rule holds with and without type checking. Places inside collections of a declared element type pair with the generator, which knows them; until then an element is described by the index. An application that binds `CelValue.FromObject(type, carrier)`, or whose read delegates return pairs created once, avoids the allocation.

**Fits.** `ValueTypeRules.Fits` takes for an object type `T`: `null`; a value whose description is the description of `T`. At the top level of a place of the place rule — a variable, a field — a bare instance that belongs to `T`, or a lazy view of the input rows whose source belongs to `T`, fits, and the place pairs the instance as above. Elsewhere — an element at any depth, an argument and a result of an application function — the description of a bare instance is the one of the index, so an application returns or puts into a collection a value of a type described at run time as a pair. The check needs no description to exist: a bare instance that the index does not describe and that does not belong to `T` is a mismatch of the place — `BindingTypeMismatch` for a variable, `FieldTypeMismatch` for a field, `EvalNoMatchingOverload` for an argument, `ImplementationResultMismatch` for a result, `ResultConversion` before a lazy view — never `TypeNotAccessible`, as the type mapping page says of a carrier of the wrong class; a .NET collection that no source describes is decided before the check, by step 3 of "Reading a value of the application". A mismatch names the type of the value: the name of its description, or the .NET type of an instance without one, by `Type.ToString()`.

**Runtime type.** `type(v)` of an object value is its object type; type values compare by kind and name, so `type(deal) == acme.crm.Deal`.

## Equality of objects

`EqualityRules`, for `==`, `CelValue.CelEquals` and the equality of lists and maps that contain objects:

1. An object value and a value of another kind are not equal, without a description. Of two object values each gets its description; an inaccessible one is the result, 3012, at the call.
2. Two different descriptions — not the same instance — are not equal, without reading fields.
3. One description: the fields in the order of their numbers. A field present in one instance only makes them unequal; a field absent from both is skipped; present in both, the two values, read as in "Types described at run time", compare by CEL equality, and an error value read is the result. There is no shortcut for the same reference: a field NaN makes an instance unequal to itself, as the language definition says.

The cost is that of the equality of two objects in the cost table: 1, then for each field compared the reads of both sides and the comparison of the values, charged pair by pair. `CelObjectType.CelEquals` is the same rule without a meter. `CelValue.CelEquals` outside an evaluation has no type index: a bare instance there has no description and gives 3012. For descriptions that override `CelEquals`, as protobuf messages will, the call and its cost come with their part.

## Members for protobuf messages

The package for protobuf messages derives from `CelObjectType` and uses its public and protected members only. Two virtual members join the class, with defaults that leave every other description as it is; the skeleton gets them with their XML documentation and these lines of the API snapshot:

```text
protected internal virtual long FieldReadCost(object instance, int number)
protected internal virtual long? EqualityCost(object left, object right)

virtual Great.Parts.Cel.Values.CelObjectType.EqualityCost(object! left, object! right) -> long?
virtual Great.Parts.Cel.Values.CelObjectType.FieldReadCost(object! instance, int number) -> long
```

- **`FieldReadCost`** — the units that reading the field `number` of `instance` costs beyond the 1 unit of the selection, known from the instance before it is read. The default is 0. A field selection charges it after its own unit and before `GetField`, only when the evaluation has a cost limit, so without a limit it is never called; `has(e.f)` does not call it. It is called inside the exception boundary of "Fields of objects" ([evaluation](evaluation.md#fields-of-objects)). The package returns the units of unpacking a `google.protobuf.Any` for the fields that hold one ([protobuf](protobuf.md#cost-of-a-read)); the units are the rows of the cost table for application data, charged as the cost function of an application function is.
- **`EqualityCost`** — `null` for a description that compares its instances by the default rule above. Another value means that the description compares them itself: the core charges that many units, once, before the comparison, and calls `CelEquals(left, right)` instead of the default rule; the result is its `bool` value, or its error value, and any other value is `InternalError`. The core always calls `EqualityCost`, because only it tells whether the description compares by itself; with a cost limit the number is charged once, without one it is discarded, and `CelEquals` is called either way. The call is inside the exception boundary, so an exception of `CelEquals` is `ApplicationException`. The package returns `1 + ⌈(Sₗ + Sᵣ)/10⌉` for the two messages ([protobuf-messages](protobuf-messages.md#equality)), which replaces the row of two objects in the cost table for them: the work of `CelEquals` is bounded by that charge and not charged by pair. The dispatch is in `ObjectRules.AreEqual`, so the equality of two lists, two maps, `in` and the equality of two values made with `CelValue.FromObject` use it too; `CelEquals` of the class is called only for a description that returned a number.
- **`CreateInstance`** — the default throws `NotSupportedException`, as its documentation says; the skeleton threw `NotImplementedException`. The core calls it only when `IsConstructible` is `true` ([evaluation](evaluation.md#message-literals)).
- **`FieldError(number, code, detail)`** — the argument `detail` is the whole text of the message, as it is for `ConversionRange`, for `InvalidAny` (3020), `FieldTypeMismatch` (3019) and `ConversionRange` (3007); for `InvalidArgument` (3008) it is the free part, as before. The package forms the text from the template of the code in the error table. The number names the field of the failed read or write; for the creation of a literal of a known type, which reads no field, it is the number of the field that failed, or 0.

## Descriptions of well-known types

A description whose `Name` is one of the thirteen names of [types](types.md#well-known-names) is described by the protobuf package so that its literal can be written and `google.protobuf.Any` is declared; none of them describes a value. Its `Type` is the CEL type of the name, not an object type, so the type identifier of the name has the static type `type` of that type; its `IsConstructible` is `true`; its `ClrType` is a marker class of the package, which no object is an instance of, so the type index never finds the description from a .NET value: a .NET `Int32Value`, `Struct` or `Any` is not described, a variable of that type is `TypeNotDeclared`, and the value in a `dyn` place is `TypeNotAccessible` ([protobuf](protobuf.md#the-known-types)). A marker is a distinct .NET type for each description, so the rule that a .NET type has one description holds.

`Any` is the one of the thirteen that must be declared. A declaration whose type contains `CelType.Any` at any depth — a variable, a field of a description, a parameter or a result of a function, a record `any` — is `TypeNotDeclared` (4008) when the type index has no object type named `google.protobuf.Any`, with the text of the code, `{declarationKind} '{name}' has type '{type}', which no type source or extension of the environment declares`, `{type}` written `any`. So `any` in an environment description is `TypeNotDeclared` without the package and a type of the package with it; the records and the types of the other twelve need no source. Two providers that describe the known types — two protobuf providers in one environment — are `DuplicateType` for each name, as the type mapping page says.
