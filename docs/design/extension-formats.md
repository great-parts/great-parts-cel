# The extension set formats and ordering between numeric types

The set `formats`, version 1, gives CEL six checks of text formats: `isEmail`, `isHostname`, `isHostAndPort`, `isIpPrefix`, `isUri` and `isUriRef`; the builder flag `EnableCrossTypeNumericComparisons` lets type checking order values of different numeric types. Both are core ([core](core.md)): they decide the value of an expression. The overloads and their identifiers are in `docs/extensions.md`, the costs in `docs/cost.md`.

## Where the code is

`src/Great.Parts.Cel/Library/Extensions/Formats/` in the namespace `Great.Parts.Cel.Library.Extensions.Formats`, which may reference `Library`, `Declarations`, `Values`, `Types` and `Diagnostics`, like `Library.Extensions.Network` (`eng/layers.txt`); the facade `Great.Parts.Cel` references it, `Library.Extensions` does not, because the set is not a row of `ExtensionCatalog` (as `decimal` and `calendar`: cel-go has no such set, so an environment description in JSON cannot name it, error 4009). One file per format: `EmailFormat.cs`, `HostnameFormat.cs`, `IpAddressScanner.cs` (the address scanner shared by `isIpPrefix` and `isHostAndPort`, internal, not a function), `IpPrefixFormat.cs`, `HostAndPortFormat.cs`, `UriFormat.cs` (URI and URI reference); `FormatChars.cs` has the character classes, `FormatsFunctions.cs` the implementations, `FormatsExtension.cs` the table of nine overloads, the descriptions and the costs; `StepCounting.cs` the step counter below. `CelExtensions.Formats(version)` is in `CelExtensions.Formats.cs` and returns the set like `Decimal`. The set has no macros, no syntax flags and no errors of its own: a function returns `false` for a string of another format, never an error.

## Formats

Each format is a hand-written scanner over the UTF-16 code units of the string, one pass from left to right, without recursion, regular expressions or the parsers of the platform: `System.Uri`, `UriBuilder`, `System.Net.IPAddress`, `IPNetwork` and `System.Net.Mail.MailAddress` accept what the formats reject and differ between versions of .NET, so the types are in the shared `eng/BannedSymbols.txt`, for every package of the library (the library uses none of them). A code unit outside ASCII is rejected wherever the format is ASCII (e-mail, host name, IP, port); in a URI it is rejected outside a percent-encoding, as RFC 3986 has no raw non-ASCII characters. The scanners return `bool` and never throw for any input. Each scanner is generic in a counter of steps (`IStepCounter`): the call of a function passes the empty `NoSteps`, which the compiler removes, and the tests pass `StepCount` and check that the steps on strings up to 64 KB, random and the worst for the format, stay within a constant times the length plus one.

- **E-mail** — the "valid e-mail address" of the HTML standard: a local part of `atext` characters and dots, `@`, then labels of 1 to 63 letters, digits and hyphens, not starting or ending with a hyphen, where a label may be all digits; the lengths of the local part and of the whole domain are not limited; no quoted strings, comments or IP literals.
- **Host name** — labels of 1 to 63 letters, digits and hyphens, not starting or ending with a hyphen, separated by dots; the last label not all digits; at most 253 characters, not counting one trailing dot, which is allowed.
- **IP address (internal)** — IPv4 as four decimal octets 0–255 without signs and leading zeros; IPv6 as RFC 4291 text: eight groups of 1–4 hexadecimal digits, one `::` at most, an IPv4 tail in the last 32 bits; a zone `%` followed by at least one character, which only the host and port check allows.
- **IP prefix** — an address without a zone, `/` and a decimal length up to 32 or 128 without a sign and leading zeros. The version argument 0 means either family, 4 or 6 only that one, any other value gives `false`; the strict form also requires the bits after the length to be zero.
- **URI** — RFC 3986 `URI` (scheme required) and `URI-reference` (`URI` or `relative-ref`): scheme, authority with user information, IP literal (`[v…]` and IPv6), registered name and port, path forms, query and fragment, each with its character set and percent-encodings of two hexadecimal digits. The port is any number of digits, as the grammar says. A percent-encoded sequence in the host name or in the zone of an IPv6 literal that decodes to invalid UTF-8 is rejected; in the user information, path, query and fragment every octet is allowed.
- **Host and port** — a host name, an IPv4 address or a bracketed IPv6 address, then optionally `:` and a port 0–65535 in decimal; with the argument `true` the port is required. The bracket closes at the last `]`; the zone of an IPv6 address is one or more characters other than NUL, including `]`, `%` and non-ASCII ones.

Where RFC 3986, RFC 4291 or the HTML standard leave a choice, the reference is the behaviour that the rules of protovalidate v1.2.2 define for the same format: its `validate.proto` and its conformance cases `cases_is_*.go` are read for comparison, not copied, and are not a dependency. The tests of the step are the examples and the developer tests; where a developer test and the reference differ, the developer asks the architect.

## Ordering between numeric types

The standard library version 1 already declares the 24 ordering overloads between `int`, `uint` and `double` and evaluates them as it evaluates a `dyn` operand — `int` with `uint` exactly, an integer with a `double` as the integer rounded to the nearest `double`, as cel-go does; type checking only filters them out unless an operand is `dyn` (`docs/standard-library.md`, "Ordering"). The flag `EnableCrossTypeNumericComparisons` is a field of the builder, stored in `DeclarationSet` and `DeclarationIndex`; `Checker.Resolve` does not filter the overloads that are only for `dyn` when the flag is set. The evaluator does not change, and equality between numeric types is not touched. `ToBuilder()` copies the flag; the environment description in JSON has no key for it; the manifest of the differential run does not set it, except in a class of cases of its own that sets `CrossTypeNumericComparisons(true)` on both sides.

## Tests and costs

The examples (`Examples/Library/FormatsExtensionTests.cs`, `Examples/Checking/CrossTypeNumericComparisonTests.cs`) cover each function and the flag with named rows; the developer tests (`Library/Extensions/Formats/`, `Checking/CrossTypeNumericOverloadTests.cs`) cover the boundaries of each format, the linear-time property and the 24 overloads at the edges of `int64` and `uint64` and with NaN. A function costs 1 and adds ⌈L/10⌉ for the length of the receiver, by the rule of the string functions (`docs/cost.md`).
