# eng/analyzers

The architecture analyzer: Roslyn rules that check namespaces, the public API list and names in every build — in the IDE, in the containers and in CI. It reports ordinary compiler diagnostics with the codes `ARCH001`–`ARCH008`, so a violation shows a file, a line and a column like any compiler error.

## Project

| Item | Value |
| :- | :- |
| Project | `eng/analyzers/Great.Parts.Cel.Eng.Analyzers.csproj`, part of the solution |
| Target | `netstandard2.0`, `LangVersion` 14 written as a number |
| Packages | `Microsoft.CodeAnalysis.CSharp` 5.0.0 and `Microsoft.CodeAnalysis.Analyzers` 3.11.0, both with `PrivateAssets="all"` |
| Settings | `EnforceExtendedAnalyzerRules=true`, so the rules for analyzer authors forbid file, environment and other banned APIs; `IsPackable=false` |

The analyzer reads only the compilation and its additional files and keeps no state between compilations, so the result depends only on the input.

## Connection

`Directory.Build.props` adds the project as an analyzer to every C# project of the repository except itself: a `ProjectReference` with `OutputItemType="Analyzer"`, `ReferenceOutputAssembly="false"` and `PrivateAssets="all"`. The analyzer never becomes a dependency of a package.

| Additional file | Added to | Used by |
| :- | :- | :- |
| `eng/layers.txt` | projects under `src/` | `ARCH005` |
| [docs/api-concepts.md](../api-concepts.md) | the two package projects | `ARCH002`–`ARCH004` |

The analyzer finds an additional file by the end of its path. The rules for the public API of packages — `ARCH002`–`ARCH004`, `ARCH006` and `ARCH007` — run only in a compilation that has `docs/api-concepts.md`. The source generator, tests and `eng/` therefore keep their own public types without rows in the list.

## Rules

| Code | Analyzer class | Applies to | Place | Message |
| :- | :- | :- | :- | :- |
| `ARCH001` | `NamespaceGraphAnalyzer` | every C# project | one reference of an edge of a cycle | `namespace cycle A -> B -> A; other edge: <path>(<line>,<column>)` |
| `ARCH002` | `ApiConceptListAnalyzer` | package projects | type declaration | `public type '<full name>' is missing from the API concept list` |
| `ARCH003` | `ApiConceptListAnalyzer` | package projects | row of the list | `API concept list row '<full name>' has no public type` |
| `ARCH004` | `ApiConceptListAnalyzer` | package projects | row of the list | `row '<full name>': <empty cell or malformed row>` |
| `ARCH005` | `NamespaceGraphAnalyzer` | assemblies with a section in `eng/layers.txt` | reference; namespace declaration; line of the table | `<namespace> must not reference <namespace> (layer table eng/layers.txt)` |
| `ARCH006` | `PublicNameAnalyzer` | package projects | type declaration | `public type name '<name>' is reserved` |
| `ARCH007` | `PublicNameAnalyzer` | package projects | member or type declaration | `public member '<name>' is marked <attribute>` |
| `ARCH008` | `QualifiedNameAnalyzer` | every C# project | the name | `qualified name '<name>' must use a using directive or global::` |

Public means visible outside the assembly: the type or member and every type that contains it are `public`, `protected` or `protected internal` — the same set as the public API snapshot.

Every rule has the category `Architecture` and the level `Error`. Generated code is not analyzed: every analyzer turns off the analysis of generated code, and Roslyn decides what is generated by the signs of [Generated code](eng-checks-source.md#generated-code). Messages are English and name both places, the namespaces or the type.

## Namespace graph: ARCH001, ARCH005

At the start of a compilation the analyzer reads the section of `eng/layers.txt` for the name of the assembly. For every name in source code whose symbol is a type of the same assembly, or a member of such a type, it takes two namespaces: of the referring code, the innermost namespace declaration, and of the type. When they differ, the pair is an edge with the place of the reference. The root namespace and nested namespaces are different nodes. The keyword `var` and names in `using` directives are not references; the uses of an alias or of a `using static` member are. In `Type.Member` and `Outer.Nested` the edge comes from the name on the left. Names in documentation comments (`cref`) are not references: a documentation link is not a dependency. Edges are kept per compilation in thread-safe collections; the analyzer allows concurrent execution.

- `ARCH005`, when the assembly has a section. An edge that the row of its source namespace does not list is reported at the reference. A namespace declaration without a row is reported at the declaration. A line of the table that does not parse is reported at that line of `eng/layers.txt`. An assembly without a section is not checked by this rule.
- `ARCH001`, where `<path>` is the path of the reference as the compiler has it, the same form as the place of the diagnostic. At the end of the compilation the analyzer finds the strongly connected components of the graph. For every edge inside a component it reports one error at the first reference of the edge; the message names the shortest cycle through this edge and the place of the next edge of that cycle.

## API concept list: ARCH002–ARCH004

The analyzer reads the table of `docs/api-concepts.md`. Columns: the type as in a C# declaration, the namespace, the concept, the explanation of the name. The full name is the namespace, a dot and the type; generic parameters match by their number.

- `ARCH002` — a public type, nested types included, without a row.
- `ARCH003` — a row without a public type. A row is checked by the compilation that declares types in the row's namespace, so each row is checked in each target of its own assembly. A row whose namespace has no types in either package assembly is checked by no compilation; a type whose row names a wrong namespace is still reported by `ARCH002`.
- `ARCH004` — an empty concept cell, an empty explanation cell, or a row without four cells. Every type of the list starts with `Cel`, so its name differs from the term and the explanation is always required.

## Names and attributes: ARCH006–ARCH008

- `ARCH006` — a public type named exactly `Great`, `Parts`, `Cel`, `Policy`, `Filtering` or `Protobuf`. Types that are not public are not affected.
- `ARCH007` — a public type or member marked `RequiresUnreferencedCodeAttribute` or `RequiresDynamicCodeAttribute`. The public API works under Native AOT as a whole.
- `ARCH008` — a qualified name whose first identifier is `Cel` without `global::`. Inside any namespace under `Great.Parts.Cel`, such a name binds to `Great.Parts.Cel` instead of the generated cel-spec types `Cel.Expr…` that tests and `eng/` use. A name in a `using` directive is the allowed other form. The rule covers type names and member access in expressions, unless `Cel` there is a local, a parameter, a range variable or a member. The name of a namespace declaration is not a reference.

## Releases of rules

`AnalyzerReleases.Shipped.md` and `AnalyzerReleases.Unshipped.md` in the project directory are additional files of the analyzer project. They list every rule with its ID, category and level; a new rule is added to `Unshipped`. The compiler reports a rule that is missing from them. The code registry test reads the rule IDs from the same files.

## Tests

Every rule is tested on violating examples in an in-memory compilation, see [eng-tests.md](eng-tests.md).
