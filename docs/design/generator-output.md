# Source generator: the created code

What `src/Great.Parts.Cel.Generator/Emit/` writes for a type context, and what of it an application may rely on. How the generator decides what to write is on [generator](generator.md). The created code is the hot path of every evaluation that reads an object of the application: one `GetField` call per field selection. It reads a member by a direct access, never by reflection, and allocates only where this page says.

## The model

The emitter gets a `ContextModel` and nothing else. The model, written by the pipeline, holds:

| Model | Holds |
| :- | :- |
| `ContextModel` | the namespace; the containing types, outermost first, each by name; the name of the context; the source name (the simple name of the context class); the hint name; the object types and the enumerations, sorted by CEL name. The facts of the compilation (`Decimal128`) are already in the shapes of the members, so the emitter reads no fact of its own |
| `ObjectTypeModel` | the CEL name; the name of the .NET type as C# writes it with `global::` (for `typeof`, casts); the kind (class, structure, interface); whether the class is sealed; the name of the description class; the fields, sorted by CEL field name; the excluded members |
| `FieldModel` | the number (the position among the sorted fields); the CEL field name; the member access (`Name`, `@event` for a keyword); the *shape* of the value; the CEL type |
| `ExcludedMemberModel` | the CEL field name and the reason |
| `EnumModel` | the CEL name; the .NET name with `global::`; the constants in declaration order, name and `long` value; the underlying type |
| shape | a small tree: a scalar of the input rows, an enumeration, an object (`Class`, `Struct`, `Interface`, `Message`), a collection (array or `IReadOnlyList`, `IList`, set, other, with the element shape), a dictionary (key shape, value shape), plus the *nullability* of each position: not null, nullable, or oblivious (read as nullable); for a structure (an object type, a collection, `JsonElement`) its size `S` of "Charges of a read" and, for a collection, whether its type is a structure, so that the emitter writes no test for `null` for it |
| CEL type | a tree that writes a `CelType` expression: primitives, `dyn`, `list`, `map`, an object by name or by the expression of a message, `wrapper` of a primitive, `timestamp`, `duration`, `decimal` |

Which of the two kinds of `string` — the plain `string` or `wrapper(string)` — a position has comes from the nullability alone, by the rule "Presence and null" of `docs/type-mapping.md`, and the rule is the same at every depth: a position whose annotation is `?`, or that has no annotation because the nullable context of the project is off, is nullable; a position annotated as not null is not. Dictionary keys are never nullable. The generator reads the annotation of a position from the symbol (`NullableAnnotation`), so the project of the application decides, not the created file.

## The file

One file per context, named as in [generator](generator.md) ("Pipeline"):

```text
// <auto-generated/>
// Created by the Great.Parts.Cel source generator. Changes to this file are lost.
#nullable enable

namespace Acme.Sales
{
    partial class OrderContext
    {
        private static readonly global::Great.Parts.Cel.Values.CelEnumType Enum_Acme_Sales_Status = new(
            "Acme.Sales.Status",
            [new("Draft", 0L), new("Approved", 1L)]);

        /// <summary>The only instance of the context.</summary>
        public static OrderContext Default { get; } = new OrderContext();

        private OrderContext()
            : base(
                "OrderContext",
                [Type_Acme_Sales_Order.Description, Type_Acme_Sales_OrderLine.Description],
                [Enum_Acme_Sales_Status])
        {
        }

        [global::System.CodeDom.Compiler.GeneratedCode("Great.Parts.Cel.Generator", "<version>")]
        private sealed class Type_Acme_Sales_Order : global::Great.Parts.Cel.Values.CelObjectType
        {
            ...
        }
    }
}
```

- **Header.** The first comment contains `<auto-generated/>`, so the compiler and the analyzers treat the file as generated ([eng-checks-source](eng-checks-source.md)); `#nullable enable` makes the nullable context of the file the same in every project. The created file has no `using`: every type is written with `global::`, so a name of the application cannot collide with one of the file; the exception is the type that C# has a keyword for (`bool`, `byte`, `sbyte`, `short`, `ushort`, `int`, `uint`, `long`, `ulong`, `nint`, `nuint`, `float`, `double`, `decimal`, `char`, `string`, `object`), which is written as the keyword, since a keyword cannot be hidden by a name of the application. There is no `#pragma` and no `[SuppressMessage]`: the code is written so that the compiler gives no warning for it; a warning that a created file gets is a defect of the generator.
- **Namespace and containing types.** A block `namespace X { ... }` for a context in a namespace (none for the global namespace), and each containing type of a nested context as `partial class Outer { ... }`, with its modifiers left out: the parts of a partial type may leave out what another part states.
- **The context.** `partial class OrderContext` with no modifier and no base list: they come from the application's part. `Default` is a `public static` property with `{ get; } = new OrderContext()`, a thread-safe single instance by the rules of static initialization, with the one documentation line above so that `CS1591` does not fire in a project that documents its public API. The constructor is `private`, and passes to `CelTypeContext` the source name — a string literal with the simple name of the class — the object descriptions and the enumerations, each as a collection expression of the `Description` fields and of the enumeration fields, both in the order of "Order". A context that declares its own constructor or its own `Default` gets the compiler's duplicate member error; the generator does not report it. The accessibility of `Default` is `public`: when the context is `internal` or nested `private`, the property is still reachable only as far as the class is.
- **Initialization order.** The static fields of the enumerations come first in the file and `Default` after all of them: the initializers of one part run in the order of the text, and the constructor reads the enumeration fields, so a field that came after `Default` would still be `null` when the constructor ran. The nested classes need no place: a `Description` is created by the initializer of its own class, when the constructor first names it. The created file depends on no other part of the class: the order of the parts of a `partial` class is not defined by the language, so the created code reads no static member of the application's part, and the application's part must not read `Default` from a static initializer of its own.
- **Descriptions and enumerations** are `private` members of the context: nested sealed classes and static fields. Nothing of the created code is visible to the application except `Default` and what `CelTypeProvider` already shows, `SourceName`, `ObjectTypes` and `EnumTypes`. Each nested class carries `[GeneratedCode("Great.Parts.Cel.Generator", "<version>")]`, with the version of the generator assembly; the version is the only text of the file that changes with a release of the library, and the snapshots write it as `<version>` (see [tests](tests.md)).
- **Names of the nested classes and fields** are the CEL name with every dot written as `_`, behind a prefix: `Type_` for a description class (`Type_Acme_Sales_Order`) and `Enum_` for an enumeration field (`Enum_Acme_Sales_Status`); `_2`, `_3` are appended when two names would collide after that (`Acme.A_B` and `Acme_A.B`). The prefix is there because a CEL name is the name of the application's type, and a bare one can equal a member that the context already has: a type `Default` of the global namespace would be CS0102 against the property `Default`, a type with the name of the context itself is CS0542, and `Create`, `SourceName`, `ObjectTypes` and `EnumTypes` are members of `CelTypeProvider`. A member of the application's part that begins with `Type_` or `Enum_` and has the same name gets the compiler's duplicate member error, as `Default` does. The names are not part of the contract.

## A description class

For each object type, one nested `sealed` class that derives from `CelObjectType`:

```text
private sealed class Type_Acme_Sales_Order : global::Great.Parts.Cel.Values.CelObjectType
{
    internal static readonly Type_Acme_Sales_Order Description = new();

    // one field for each converter that has to name the field in an error: see "Collections"
    private readonly global::System.Func<global::Acme.Sales.Status, global::Great.Parts.Cel.Values.CelValue> _convert3;

    private Type_Acme_Sales_Order()
        : base(
            "Acme.Sales.Order",
            typeof(global::Acme.Sales.Order),
            [
                new(0, "currency", global::Great.Parts.Cel.Types.CelType.String),
                new(1, "lines", global::Great.Parts.Cel.Types.CelType.ListOf(global::Great.Parts.Cel.Types.CelType.ObjectNamed("Acme.Sales.OrderLine"))),
                ...
            ])
    {
        _convert3 = e => FromEnum(3, e);
    }

    protected override global::Great.Parts.Cel.Values.CelValue GetField(object instance, int number)
    {
        var value = (global::Acme.Sales.Order)instance;
        switch (number)
        {
            case 0: return ...;
            ...
            default: throw new global::System.ArgumentOutOfRangeException(nameof(number));
        }
    }

    protected override bool HasField(object instance, int number) { ... }

    protected override string? GetExcludedFieldReason(string fieldName) { ... }
}
```

- **`Description`** is the one instance, a `static readonly` field of the class. The descriptions refer to each other by the CEL name in the types of fields (`CelType.ObjectNamed`) and by the field `Description` where a description is needed at run time ("Collections"), so no description needs another at construction and the static initializers cannot form a cycle.
- **Base constructor.** Name, `typeof` of the type written with `global::`, and the fields as a collection expression of `new(number, name, type)`, in the order of "Order"; the number of a field is its position. `CelObjectField` is the target type of `new(...)`. The checks of the constructor — name, numbers, distinct names — hold by construction.
- **`GetField`.** The instance is cast once, before the `switch`: a class or an interface by a reference cast, a structure by unboxing (a copy of the value; a `readonly struct` is not changed by it). A `case` for each field, in the order of the numbers, returns the value by the row of "Reading a member". The `default` branch throws `ArgumentOutOfRangeException`; the library calls the method with the number of one of the fields only. The method has no loop, no lookup by name, no LINQ, no closure created at the call and no `try`: an exception of the application's getter is turned into an error by the evaluation.
- **`HasField`.** The same `switch`; the instance is cast once, and only when a `case` reads the member (a type whose members are all value types and objects that are never `null` casts nothing). Each case returns the presence of the member by "Presence", and the cases that return `true` are written together, `case 1: case 2: return true;`. The `default` branch throws as above.
- **`GetExcludedFieldReason`.** A `switch` on the field name with a `case "name": return "reason";` for each excluded member, in the order of the names, ordinal, and `default: return null;`. A type without an excluded member does not override the method. Hidden members are not named here.
- **`FieldReadCost`.** `protected override long FieldReadCost(object instance, int number)`, written only for a type that has a member whose read does work that grows with the data or with the size of a structure ("Charges of a read"); the other types keep the default, 0. The same `switch` by the number, `case` only for those members, `default: return 0;`; the instance is cast once, as in `GetField`, and only when a `case` needs it.
- **Not overridden.** `CelEquals` (the default compares the fields by their numbers with CEL equality, which is the rule the application's types need, and writing it again would only add code), `IsConstructible` and `CreateInstance` (an expression does not create an object of a .NET type: `TypeNotConstructible`, 2008), and `EqualityCost` (the default).
- **A type with no fields** (every member excluded or hidden) still has a description: `base(name, typeof(T), [])`, and a `GetField` that throws as its `default`.

## Order

What does not depend on the order of the source: the object types of the context are sorted by CEL name, the enumerations by CEL name, the fields of a type by CEL field name, the excluded members by field name, all with `string.CompareOrdinal`; the constants of an enumeration stay in declaration order, which a file defines. The reason is that the order of members across partial parts, base classes and files is not defined by the language, and a file that is renamed must not change the text or the numbers. The order of the members *inside* the created file is fixed by the generator and does not depend on the other parts of the class: the enumeration fields, sorted by CEL name, then `Default`, the constructor and the nested classes, sorted by CEL name; where the order of execution matters, it is the one of "Initialization order" in "The file". Equal inputs give equal bytes, which a test checks by running the generator twice and by running it over the same source in two compilations.

## Reading a member

The value of a member `v` (`value.Name`) becomes a `CelValue` by the row of its shape. `n` is the number of the field; `Null` is `CelValue.Null`; `Unexpected` is `FieldError(n, global::Great.Parts.Cel.Diagnostics.CelErrorCode.UnexpectedNull, null)`. The CEL type is that of `docs/type-mapping.md`.

| Member | CEL type | Created code | Allocation |
| :- | :- | :- | :- |
| `long`, `int`, `short`, `sbyte`, `nint` | `int` | `CelValue.FromInt64(v)` | none |
| `ulong`, `uint`, `ushort`, `byte`, `nuint` | `uint` | `CelValue.FromUInt64(v)` | none |
| `double`, `float`, `Half` | `double` | `CelValue.FromDouble((double)v)` | none |
| `bool` | `bool` | `CelValue.FromBoolean(v)` | none |
| `string`, not null | `string` | `v is null ? Unexpected : CelValue.FromString(v)` | none |
| `string`, nullable | `wrapper(string)` | `v is null ? Null : CelValue.FromString(v)` | none |
| `Guid` | `string` | `CelValue.FromString(v.ToString("D"))` | the string, 36 characters; the cost table counts it |
| an enumeration | `int` | `FromEnum(n, v)` | none |
| `byte[]`, not null | `bytes` | `v is null ? Unexpected : CelValue.FromBytes(v)` | none |
| `byte[]` nullable, `ReadOnlyMemory<byte>?` | `wrapper(bytes)` | `v is null ? Null : CelValue.FromBytes(v)` | none |
| `ReadOnlyMemory<byte>` | `bytes` | `CelValue.FromBytes(v)` | none |
| `CelTimestamp`, `CelDuration` | `timestamp`, `duration` | `CelValue.FromTimestamp(v)`, `FromDuration(v)` | none |
| `DateTimeOffset` | `timestamp` | `CelValue.FromTimestamp(CelTimestamp.FromDateTimeOffset(v))` | none |
| `DateTime` | `timestamp` | `FromDateTime(n, v)`; a kind other than `Utc` is `InvalidArgument` | none |
| `TimeSpan` | `duration` | `FromTimeSpan(n, v)`; out of range is `ConversionRange` | none |
| `Decimal128` (a compilation that has it) | `decimal` | `FromDecimal(n, v)`; NaN and infinity are `ConversionRange` | none |
| `System.Decimal` (the same) | `decimal` | `FromDecimal(v)` | none |
| `Nullable<T>` where the CEL type of `T` has a wrapper (`bool`, `bytes`, `double`, `int`, `uint`, `string`; an enumeration, `Guid` and `Half` by their CEL types) | `wrapper(…)` | `v.HasValue ? <row of T applied to v.Value> : Null` | as the row of `T` |
| `Nullable<T>` otherwise (`DateTimeOffset?`, `DateTime?`, `TimeSpan?`, `Decimal128?`, `System.Decimal?`, `CelTimestamp?`, `CelDuration?`) | the CEL type of `T` | `v.HasValue ? <row of T> : Unexpected` | as the row of `T` |
| `Nullable<T>`, `T` a structure of the context | the object type | `v.HasValue ? FromInstance((object)v.Value) : Null` | one box |
| `CelValue?`, `JsonElement?` | `dyn` | `v.HasValue ? <row of T applied to v.Value> : Null`: `dyn` takes `null`, so no value is an error here | as the row of `T` |
| `CelValue` | `dyn` | `v` as it is | none |
| `object` | `dyn` | not null: `v is null ? Unexpected : FromDynamic(n, v)`; nullable: `v is null ? Null : FromDynamic(n, v)` | none for the types of the input rows; a box for a structure |
| `JsonElement` | `dyn` | `FromDynamic(n, v)` (an undefined element is `InvalidArgument`) | one box, 32 bytes |
| `CelList`, `CelMap` | `list(dyn)`, `map(dyn, dyn)` | `v is null ? Unexpected : CelValue.FromList(v)`, `FromMap(v)` | none |
| an object type: class, `record class`, interface | the object type | not null: `v is null ? Unexpected : FromInstance(v)`; nullable: `v is null ? Null : FromInstance(v)` | none |
| an object type: structure, `record struct` | the object type | `FromInstance((object)v)` | one box |
| a message of protobuf | the type of the message | as a class | none |
| a collection or a dictionary | `list(E)`, `map(K, V)` | "Collections" | "Collections" |

`FromInstance`, `FromEnum`, `FromDateTime`, `FromTimeSpan`, `FromDecimal`, `FromDynamic` and `FieldError` are the protected members of `CelObjectType`; the rest are the public factories of `CelValue`, `CelList` and `CelMap`. `DateTime` follows the input table of `docs/type-mapping.md` ("Input: a .NET type to a CEL type") and the `DateTime` and `TimeSpan` error values name the type and the field, as the helpers do. `decimal` shapes exist only for a compilation that has `Decimal128`: in another compilation the member is excluded with `GPCEL007` and its reason is `the CEL type decimal requires .NET 11 (System.Numerics.Decimal128)`. The `CelType.Decimal` expression is written without `#if`: the generator writes it only for a compilation that has the type.

**Where the decimal members end.** The generator writes everything that is in the generator for `System.Decimal` and `Decimal128`: the field type `CelType.Decimal`, the reads `FromDecimal(number, value)` and `FromDecimal(value)` and their `Nullable<>` forms in the rows above, the finding of `System.Numerics.Decimal128` in the compilation ([generator](generator.md), "Pipeline"), the exclusion of the member with `GPCEL007` and the text of `GetExcludedFieldReason` when the type is not there (`net10.0`), and the snapshots of the text. What the created code calls and what meets it in the environment belongs to the decimal part of the library and is not written here: the bodies of the two `FromDecimal` of `CelObjectType` and of `CelValue.FromDecimal`; the refusal of a decimal field in an environment without the extension set `decimal`, `FieldNotAccessible` (2007) at the selection, which the type checker gives whoever described the type; and error 3012 for a boxed decimal in the place of `dyn`, so an `object` member that holds a `decimal` is read by the `object` row and the library decides. Both parts use one function, `CheckErrors.FieldNotAccessible(field, type, reason, location)`, whose text is `field '{field}' of type '{type}' is not available to expressions: {reason}`; for a member that the generator excluded, `{reason}` is the text of `GetExcludedFieldReason`. The test that reads a decimal member of a sample type, in `Great.Parts.Cel.Generator.Samples` under `#if NET11_0_OR_GREATER`, is written by whichever of the two tasks reaches `main` later; the earlier one leaves the sample with checks of the created text only.

A reference-type object read this way is the bare instance; the evaluation pairs it with the description of the declared type when that is needed ([objects](objects.md), "Place rule"): the created code does nothing for it. A message of protobuf and a structure follow the same rule.

## Presence

`has(e.f)` is whether the member is not null:

| Member | `HasField` |
| :- | :- |
| a value type that is not `Nullable<T>` | `true` |
| `Nullable<T>` | `v.HasValue` |
| a reference type, a collection that is a reference type, `object`, `CelList`, `CelMap` | `v is not null` |
| `string` | `v is not null`; an empty string is present |
| `ReadOnlyMemory<byte>` | `true` |
| `ImmutableArray<T>` | `!v.IsDefault`; `default` is absent and reads as `UnexpectedNull` ("Collections") |
| `ImmutableArray<T>?` | `v.HasValue && !v.Value.IsDefault` |
| a structure that is a collection, other than `ImmutableArray<T>` (it has no `null` and no `default` that means absent) | `true` |
| `CelValue` | `true` |

A member that is not null by annotation and null at run time reads as `UnexpectedNull` and has `has()` false, as the table of "Presence and null" in `docs/type-mapping.md` says.

## Collections

The collection rows of `docs/type-mapping.md` ("Objects and collections"), by the family that [generator](generator.md) ("Which types are read") chose. The element converter and the value converter are *created once*: each is a `static` lambda, which the compiler caches in a static field, or, when it has to call a protected member of `CelObjectType` that names the field in an error (`FromEnum`, `FromDateTime`, `FromTimeSpan`, `FromDecimal`, `FromDynamic`, `Unexpected`), a delegate that the constructor of the description stores in a `private readonly` field, `_convertN`, where `N` is the number of the member (a member that needs two, such as a dictionary whose value is a list of objects, stores the converter of the value as `_convertN_2`). No converter is created while a field is read, and nothing of a converter is reached through a captured variable of `GetField`. Each family below writes the member `v`; a collection that is `null` is `UnexpectedNull` whatever its annotation, because the CEL type `list` or `map` takes no `null` (the row "collection" of the table of "Presence and null" in `docs/type-mapping.md`), and `has()` is `v is not null`. A collection that is a structure has no state "null" of its own, and its absent state is read the same way: `ImmutableArray<T>` that is `default` is `UnexpectedNull` and `has()` is `false` (`!v.IsDefault`). The same holds for an element, and for the value of a dictionary, of that type at any depth, where the error is the element error value of "Elements and values" below. `ImmutableArray<T>?` is the `Nullable<T>` row of a type that has no wrapper: `v.HasValue && !v.Value.IsDefault` is present, anything else is `UnexpectedNull`.

| Family | Created code |
| :- | :- |
| array, `IReadOnlyList<T>`, `List<T>`, `ImmutableList<T>`, `ReadOnlyCollection<T>`, any class that implements `IReadOnlyList<T>` | `CelValue.FromList(CelList.CreateView(v, convert))`. A view, no copy: one view object is allocated |
| `ImmutableArray<T>` | `v.IsDefault ? Unexpected : CelValue.FromList(CelList.CreateView(ImmutableCollectionsMarshal.AsArray(v)!, convert))`. `default` is an array that was never made: it has no length, and the view over a box of it would throw `InvalidOperationException` at the first use, so it is checked first and read as an absent collection (below). `AsArray` returns the array that the structure holds, with no copy and no box, so the read allocates the view only |
| a structure other than `ImmutableArray<T>` that implements `IReadOnlyList<T>` | as the first row over `(IReadOnlyList<T>)v`: the structure is boxed, so the read allocates the box and the view |
| `IList<T>`, and no `IReadOnlyList<T>` in the declared type | `CelValue.FromList(CelList.CreateView(v as IReadOnlyList<T> ?? new ReadOnlyCollection<T>(v), convert))`: the wrapper is made only for an instance that is not an `IReadOnlyList<T>`; a `List<T>` or an array declared as `IList<T>` is passed as it is |
| set: `IReadOnlySet<T>`, `ISet<T>`, `HashSet<T>`, `SortedSet<T>`, `ImmutableHashSet<T>` | `CelValue.FromList(CelList.CreateSorted(v as IReadOnlyCollection<T> ?? new List<T>(v), convert))`: a sorted copy at every read; the copy is the cost row of the set |
| other `IReadOnlyCollection<T>` (`Queue<T>`, `Stack<T>`, `LinkedList<T>`) | `CelValue.FromList(CelList.CreateCopy(v, convert))` |
| `IReadOnlyDictionary<K,V>`, `Dictionary<K,V>` and every class that implements it | `CelValue.FromMap(CelMap.CreateView(v, convert, false))` |
| `IDictionary<K,V>` and no `IReadOnlyDictionary<K,V>` in the declared type | `CelValue.FromMap(CelMap.CreateView(v as IReadOnlyDictionary<K,V> ?? new ReadOnlyDictionary<K,V>(v), convert, false))` |

- **A structure that is a collection of another family** — a structure that implements only `IList<T>`, a set, a dictionary or only `IReadOnlyCollection<T>`, as `ImmutableArray<T>` and the structure with `IReadOnlyList<T>` above are the two that this page names — is read as the class of its family over the box of the structure: the box is made once, and the rows above apply to the boxed value (`v as IReadOnly… ??` and the wrapper take the box). It has no `null`, so the created code writes no test for `null` and `has()` is `true`; the structure that is the element or the value of a collection is read in the same way, and a structure that is a collection never gives `UnexpectedNull` for being `null`. The read allocates the box and what the family allocates.
- **Wrappers only without the read-only interface.** The check `as IReadOnly… ??` is made at run time on the instance, so a `Dictionary<K,V>` that is declared as `IDictionary<K,V>` is passed as it is, the view then sees a `Dictionary`, and the order of its entries is the order of the dictionary; a class that implements only `IDictionary<K,V>` gets `ReadOnlyDictionary`, which is no type whose order is the source order, so the map is ordered by the ascending key, a rule that does not depend on hash codes. This is why the call passes `keepSourceOrder: false` in every case: the library decides the order by the type of the source, `Dictionary`, `OrderedDictionary`, `SortedDictionary`, `SortedList` and `ImmutableSortedDictionary` in the order of enumeration and every other in ascending key order, as the section "Objects and collections" of `docs/type-mapping.md` says. A member declared by a type that always implements the read-only interface (an array, `List<T>`, `Dictionary<K,V>`, `IReadOnlyList<T>`) has no check in the created code.
- **Keys** are `string`, the integer types, `bool`, enumerations and `Guid`; the library converts them (an enumeration key as `int`, a `Guid` as a string). The CEL key type is `string`, `int`, `uint` or `bool`. A key that cannot be a CEL key (an enumeration over `ulong` above `long.MaxValue`) is an error of the operation that meets it: the library decides, the created code does not.
- **Elements and values** follow the rows above at every depth: `List<List<int>>` converts each element with `CelValue.FromList(CelList.CreateView(e, convertInner))`, `Dictionary<string, List<Order>>` converts each value with the converter of a list of objects. An element that is a reference type with no value is `Null` when its position is nullable (oblivious included) and an error value `UnexpectedNull` otherwise, except an element that is itself a collection, which is `UnexpectedNull` in both cases; the error names the member that holds the collection and, being a value that an element converter returns, it is allowed by `CelList.CreateView`. `Nullable<T>` elements follow the `Nullable<T>` rows. The CEL element type of a nullable string is `wrapper(string)`, of a not-null one `string`; of an object, the object type.
- **Sets** need elements that CEL orders; the generator decides that by the element type, the rule being a type from the input table of `docs/type-mapping.md` that has an order: numbers, `bool`, `string`, `byte[]`, `ReadOnlyMemory<byte>`, `Guid`, enumerations, times and `decimal`. What the type cannot say is decided at run time by `CelList.CreateSorted`: a `NaN` element, a `null` element, two elements that CEL calls equal (`0.0` and `-0.0` cannot be both in a `HashSet<double>`, since .NET calls them equal) make `CreateSorted` throw `ArgumentException`. The created code does not catch it: the evaluation turns the exception into `ApplicationException` (3014) at the field selection, with the `ArgumentException` as its inner exception, as for any exception of the code of the application. A set with such elements is a data error of the application, not a property of the type, and so no diagnostic could name it.
- **Elements that are objects** — see "Place rule inside collections" below.

## Place rule inside collections

An element or a value of a collection that the created code reads has the declared element type of the member, so `List<Animal>` is `list(Animal)` and an instance of `Dog` in it must be an `Animal`, as `type()` and the fields say ([objects](objects.md), "Place rule"). The converter of an object element does that by the *static* type of the element, which it knows:

| Element type | Converter |
| :- | :- |
| a `sealed` class, a `record struct`, a structure | `FromInstance((object)e)`: the exact type is the declared one; the index finds the description by the exact .NET type |
| a message of protobuf | `FromInstance(e)`: the C# classes of protoc are sealed |
| a class that is not sealed | `e.GetType() == typeof(T) ? FromInstance(e) : CelValue.FromObject(Description, e)` |
| an abstract class or an interface | `CelValue.FromObject(Description, e)` always: the exact type is never the declared one |

`Description` is the field of the description of `T` in the same context. The pair costs one allocation of at most 64 bytes, inside the unit of the read; the first two rows allocate nothing for a class. A null element follows the rule of "Collections". An element that is itself a collection is converted by the rows above.

This is the rule that the created code gives, and the lists that the created code builds fit their declared type: the pair names the `Description` of the declared element type of the same context. When two contexts of one environment share the type and this context's description lost, the index resolves the pair to the description that stays (the alias of [objects](objects.md), "Types that two generated contexts share"), so the list fits whichever context wins; the converter is the same in both contexts and takes nothing from the environment. An application that builds a `CelList` itself, with `CelList.Create` or `CreateView`, and binds it to a variable or returns it from a function declared `list(Animal)`, has to put in it values of the type that it declares: `CelValue.FromObject(animalType, dog)`, the description taken from the context (`OrderContext.Default.ObjectTypes`). A bare `Dog` in such a list is described by the index as `Dog` and does not fit `Animal`: the check against the declared type fails, as it does for any other value of another type, and the library does not widen the fit: widening would make the type of an element depend on where the list was made. The rule needs no change in the library.

## Messages of protobuf

A type that is a message class of `protoc` — it implements `Google.Protobuf.IMessage` and has a public static property `Descriptor` of the type `Google.Protobuf.Reflection.MessageDescriptor`, both found by full name, so no package is referenced — is not described by the context. A member, an element or a value of such a type:

- has the CEL type `CelType.ObjectNamed(global::Acme.Pb.Order.Descriptor.FullName)`: the full name of the protobuf message, which `Great.Parts.Cel.Protobuf` uses for its descriptions. The expression is evaluated when the description is constructed, a read of a static property of generated code, which uses no reflection;
- is read by `FromInstance(v)` like a class, as a bare instance. The description of the message comes from the environment: a provider of `Great.Parts.Cel.Protobuf` that the application adds with `AddTypes`; the place rule pairs the instance with it, and an element is found by the exact .NET type, the class being sealed;
- is not in the closure and not counted in the limit.

An environment that adds the context without a provider for the message is `TypeNotDeclared` (4008) at `Build`, for the field that names the message. No public member is added to the library for this: `CelObjectType.FromInstance` is already there, and the description of the message already has the .NET type of its class. `RepeatedField<T>` and `MapField<K,V>` are collections by the rows above (`IReadOnlyList<T>`, `IReadOnlyDictionary<K,V>`). The order of a `MapField` read by the created code is by ascending key, not the order of insertion that the provider of protobuf gives to the fields of its own descriptions: the created code asks the library to order by the type of the source, and `MapField` is not one of the types whose order is kept.

## Enumerations

An enumeration that the closure reaches, or a root that is an enumeration, is `new CelEnumType(name, constants)`: the CEL name is the default name of the type, and the constants are the names of the members with their values as `long`, in declaration order, aliases included. A constant over `ulong` whose value is above `long.MaxValue` is left out, silently: `CelEnumType` keeps `long`, and the member that holds such a value reads as `ConversionRange` through `FromEnum`. The names of the constants are the names in C#; the naming policy does not touch them. An enumeration described by two contexts is one declaration when the two are equal ([objects](objects.md), "Types that two generated contexts share").

## What is contract

The form of the created code is a contract for the minor versions (the generator's snapshots pin it), but not all of it:

- **Does not change in a minor version:** `Default`, the private constructor, the base class, the source name, the CEL name of each type, the CEL name and the CEL type of each field, the constants of each enumeration, the `ClrType` of each description, what `has()` and `null` mean for each row, the order of a dictionary and of a set, the text of each reason, the code and the place of each error that a read gives, the units that a read charges.
- **May change in a minor version, with the snapshots updated and reviewed:** the names of the nested classes and fields, the text of comments and layout, how a row is written in C# as long as it gives the same values, errors and allocations, and the order of `case` labels. A change that adds an allocation to a read, or a call that is not on this page, is a change of behavior and goes through review, not through the update of a snapshot.

## Charges of a read

The evaluation charges 1 unit for the selection of a field. The rows of "Data of the application" of `docs/cost.md` that charge more for the read of a member are charged by `FieldReadCost`, which the evaluation calls after the unit of the selection and before `GetField`, and only when the evaluation has a cost limit ([objects](objects.md), "Members for protobuf messages"). So a limit stops a read before the copy or the sort that it would pay for. The created code overrides `FieldReadCost` for a type that has a member of the rows below and returns the units *beyond* the unit of the selection, the formula of the row as it is written there; a member of any other row costs the unit of the selection only, and `has()` calls neither member. The charges of one member add.

| Member | Units returned |
| :- | :- |
| a structure that the read boxes: an object type that is a structure or a `record struct`, `Nullable<T>` of it, a structure that is a collection other than `ImmutableArray<T>`, `JsonElement` | 1 + ⌈S/64⌉, `S` the size of the structure in bytes: a constant that the generator computes |
| a set (`IReadOnlySet<T>`, `ISet<T>` and the types of that family), `n` elements | 1 + c · n · ⌈log₂(n + 1)⌉ |
| a collection without an index (`Queue<T>`, `Stack<T>`, `LinkedList<T>` and the types of that family), `n` elements | 1 + n |

- **`n` and the second read.** `n` is the `Count` of the instance that the member holds now: `FieldReadCost` reads the member through its getter, so with a cost limit the getter of a set and of a collection without an index is called once more for each selection. A member that is `null` returns 0, since the read is `UnexpectedNull` and copies nothing. `⌈log₂(n + 1)⌉` is the number of bits of `n`.
- **`c`** is 1 for elements that are numbers, `bool`, enumerations, times and `decimal`, and for `string`, `bytes` (`byte[]`, `ReadOnlyMemory<byte>`) and `Guid` elements 1 + ⌈2 · Lmax/10⌉, `Lmax` the length of the longest element: UTF-16 units for a string, bytes for bytes, 36 for a `Guid`. `Lmax` is found by one pass over the elements, only for the elements of those types, and a `null` element counts 0. A sum that does not fit a `long` is `long.MaxValue`, without an exception; the created code does that sum in one `private static` helper of the description class, `SortCost(count, unit, box)`, written only into a class that has a set member (`System.Numerics.BitOperations.LeadingZeroCount` for `⌈log₂(n + 1)⌉`, `System.Math.BigMul` for the overflow); the helper is not a contract.
- **`S`** is the sum of the sizes of all instance fields of the structure, private ones included, without padding: 1 byte for `bool`, `byte` and `sbyte`; 2 for `short`, `ushort`, `char` and `Half`; 4 for `int`, `uint` and `float`; 8 for `long`, `ulong`, `double`, `nint`, `nuint`, `DateTime`, `TimeSpan` and every reference type; 16 for `Guid`, `decimal`, `Decimal128`, `DateTimeOffset`, `Int128` and `UInt128`; an enumeration by its underlying type; `Nullable<X>` as `X` and one byte more; a field that is a structure by its own `S`, at any depth, including a structure of a referenced assembly. An empty structure is 1. The generator reads the fields from the symbols and writes the result as a number; it is an estimate of the box, as the cost table says, not a measurement.

- **A structure that is a collection.** A structure that implements only a set interface, or only `IReadOnlyCollection<T>` without an index, is read by two rows: the box of the structure and the copy of its family. Both are charged, each with its own `1 +`, so the value is `(1 + ⌈S/64⌉) + (1 + c · n · ⌈log₂(n + 1)⌉)` for a set and `(1 + ⌈S/64⌉) + (1 + n)` for a collection without an index. The sum is a sound over-estimate by one unit, and the rows are not merged.
- **Elements and values.** The rows charge members only. A set, a collection without an index or a structure that is a collection (other than `ImmutableArray<T>`) is not read as an element, a key or a value of a collection, at any depth: such a member has the reason of [generator](generator.md), "The reasons", and is left out with `GPCEL002`. The copy of such an element would be made at each read of an element, where no charge exists, and the limit would not bound it. An element that is an object type that is a structure is boxed at each read of an element for the unit of the index: the size of the box is fixed by the type, it does not grow with the data, and it is not charged.

For example, a member `HashSet<long>` with 7 elements returns 1 + 1 · 7 · 3 = 22, `Queue<string>` of 4 elements returns 5, and a member that is a structure of 24 bytes returns 2.

## Cost and allocation

The cost of a read is that of the table of `docs/cost.md` for the row, charged as "Charges of a read" says; the created code charges nothing else and charges only through `FieldReadCost`. At most one object of at most 64 bytes is allocated by a read of a member, beyond the string of a `Guid`, the copy of a set or of a collection without an index and the one exception below: a view (a list or a map, `ImmutableArray<T>` included, which is read without a box), a box (a structure, a `JsonElement`), a pair (an element that is not of its declared type). The exception is a structure that implements `IReadOnlyList<T>` and is not `ImmutableArray<T>`: the read boxes it and allocates the view, two objects. A read of a scalar, of a `string`, of bytes, of a time and of an object of a sealed class allocates nothing. No converter is created at the read. The allocation test of [tests](tests.md) pins this for the type of the order that the samples give.
