# Generator of call sites: anonymous data of `CelExpression.Evaluate`

The second pipeline of the source generator of the package `Great.Parts.Cel`. For each anonymous type passed as `data` to `CelExpression.Evaluate<T>(string, object, …)` it writes one file that registers the type with `CelAnonymousData.Register` from a module initializer, so that the simple entry ([simple-entry](simple-entry.md)) reads the properties without reflection and works under Native AOT. The rules of the property types are `docs/type-mapping.md` ("Data of the simple entry"); the diagnostics are `GPCEL010` and `GPCEL011` of `docs/generator-diagnostics.md`, and `GPCEL008` for the language version.

| File | Content |
| :- | :- |
| `src/Great.Parts.Cel.Generator/CelAnonymousDataGenerator.cs` | the `IIncrementalGenerator`: predicate, transform, output |
| `src/Great.Parts.Cel.Generator/CallSites/CallSiteModel.cs` | the value records of the pipeline |
| `src/Great.Parts.Cel.Generator/CallSites/CallSiteReader.cs` | the predicate and the transform: the call found by the symbol of the method, the argument `data` by position or name |
| `src/Great.Parts.Cel.Generator/CallSites/PropertyRules.cs` | the allowed property types and the CEL type of each |
| `src/Great.Parts.Cel.Generator/CallSites/RegistrationEmitter.cs` | the text of a created file |
| `src/Great.Parts.Cel.Generator/Diagnostics/Descriptors.cs` | two more descriptors, beside the existing ones |
| `src/Great.Parts.Cel.Generator/AnalyzerReleases.Unshipped.md` | `GPCEL010`, `GPCEL011` |

The generator is `[Generator(LanguageNames.CSharp)] public sealed class CelAnonymousDataGenerator` — public, as `CelTypeContextGenerator`: the generator tests create it directly and the generator assembly gives no `InternalsVisibleTo`; the analyzer assembly is not referenced by the code of the application, so the class is not a public API of a package, beside `CelTypeContextGenerator` in the same assembly and package (`analyzers/dotnet/cs`). The two pipelines share nothing but the helpers of names, the `LocationInfo` record and the facts of the compilation (`Model/CompilationFacts.cs`: the language version).

## The pipeline

1. **Predicate** (syntax only): an `InvocationExpressionSyntax` whose expression is a name `Evaluate` — a simple name, a generic name or a member access ending in one — with at least two arguments.
2. **Transform** (semantic model): the symbol of the invocation is the method `Great.Parts.Cel.CelExpression.Evaluate<T>(string, object, ulong, CancellationToken)` (compared with the symbol of the compilation, not by text), so a full name, `using static` and a `using` alias are found and a method `Evaluate` of another type is not. The argument bound to the parameter `data` (by position or by name) gives the static type by `GetTypeInfo(…).Type`.
3. The static type gives one of three results:
   - an anonymous type: its properties in declaration order, each with the CEL type from `PropertyRules`, or a `GPCEL011` for each property that is outside the list, at the property — the result is a registration model or the diagnostic models;
   - a dictionary of the list (`IReadOnlyDictionary<string, X>`, `Dictionary<string, X>`, `X` of the list, found through the interfaces of the type): nothing;
   - anything else — a type parameter, `object`, a named class or structure, a dictionary outside the list: a `GPCEL010` model.
4. **Model**: records with value equality, no `ISymbol`, `SyntaxNode` or `Location`: `AnonymousShape(EquatableArray<PropertyModel>)` with `PropertyModel` with the name and the C# type of the property (the declaration and the binding of a variable are derived from them by the emitter, so they are not stored); a diagnostic model with the id, the arguments and a `LocationInfo` kept apart (the same record as in the type context pipeline), so an edit above a call that moves it does not change the shape. The steps `CallSite`, `Shapes` and `CallSiteDiagnostics` are named for tracking.
5. **Output**: the shapes are collected, made distinct by value (names, types, order: the key of C# for one anonymous type), and numbered in the order of their first call site by file path and position; each distinct shape gives `CelAnonymousData_{n}.g.cs`. Diagnostics are reported from their own models.
6. **Language version**: the created files use file-local classes, which need C# 11. Below C# 12 — the threshold of the type context pipeline — the pipeline writes no file and reports `GPCEL008` once for the compilation, at the first call it found (by file path and position), with `{0}` `CelExpression.Evaluate`.

## The created file

```text
// <auto-generated/>
#nullable disable
file static class CelAnonymousData_1
{
    [global::System.Runtime.CompilerServices.ModuleInitializer]
    internal static void Register() =>
        global::Great.Parts.Cel.CelAnonymousData.Register(
            new { x = default(long), name = default(string) },
            static builder => builder.AddVariable<long>("x").AddVariable<string>("name"),
            static (data, bindings) => bindings.Add("x", data.x).Add("name", data.name));
}
```

The example expression uses `default(T)` with the C# type as the compiler displays it with `global::`, so the created anonymous type is the type of the call site (same names, types, order). `#nullable disable` lets `default(string)` stand for `string?` and `string` alike. A property name that is a C# keyword is written with `@` (`data.@class`), and the CEL name is the property name without `@`; a name that is not a CEL identifier is `GPCEL011` with the reason "not a CEL identifier": the generator has its own copy of the rule of `CelSyntax.IsIdentifier`, since the analyzer cannot call the library. The variable is declared with `AddVariable<TProperty>`, which gives the CEL type through the input table of the core, so the generator writes no CEL type itself.

## Diagnostics

| Code | When | Place | Text arguments |
| :- | :- | :- | :- |
| `GPCEL010` (Warning) | the static type of `data` is not anonymous and not a listed dictionary | the argument `data` | `{0}` the type as C# displays it; `{1}` the advice: for a named class or structure "build an environment with a type source and UseInput<T>", for a type parameter or `object` "pass the anonymous object at the call or pass a dictionary", for a dictionary outside the list "pass a dictionary with string keys and values of the list, or an anonymous object" |
| `GPCEL011` (Error) | a property of an anonymous type has a type outside the list, or a name that is not a CEL identifier | the property in the anonymous object creation expression | `{0}` the property name; `{1}` the type as C# displays it; `{2}` the reason (`an object of the application`, `a nested anonymous object`, `object`, `not accessible from the created file`, `a type outside the list`, `a type parameter of the enclosing method`, `a collection outside the list`, `not a CEL identifier`) and the advice "; build an environment with a type source", or "; rename the property" for a name that is not a CEL identifier |
| `GPCEL008` (Error) | the language version of the project is below C# 12 | the first call found | `{0}` `CelExpression.Evaluate`; `{1}` the version |

A shape with a `GPCEL011` property gives no file. A call through a method group (`Func<string, object, long> f = CelExpression.Evaluate<long>;`) is not an invocation of the method and is not seen; at run time it works when the same anonymous type is registered by another call of the assembly, and otherwise it is `TypeNotDeclared`.

## Tests

The examples (`tests/Great.Parts.Cel.Generator.Tests/Examples/CallSites/CallSiteTests.cs`, `tests/Great.Parts.Cel.Tests/Examples/Generated/AnonymousDataTests.cs`) fix one file per shape, the created text, both diagnostics with place and message, and the call at run time under the JIT and Native AOT: the generator is an analyzer of `tests/Great.Parts.Cel.Tests`. The developer tests take the rest: the cached steps (`trackIncrementalGeneratorSteps`, an edit above the call keeps the step of the shapes `Unchanged`), every row of `PropertyRules`, the escaping of keywords, `using static` and an alias, named arguments, the numbering across files, the language version, and the absence of reflection in the created text.
