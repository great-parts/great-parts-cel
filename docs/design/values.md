# Values: the value model and the value rules

`Great.Parts.Cel.Values` holds the public value model — `CelValue`, `CelValueKind`, `CelList`, `CelMap` and the types that later parts implement — and, in rule files, the value rules that evaluation relies on. This page covers every kind except `decimal`, which arrives with its part under the same rules; the kind `optional` is in its own section below; object values, type descriptions and their sources are in [objects](objects.md), the zone database and the calendar in [time zones](time-zones.md).

## Kinds

`CelValue` is a `readonly struct` of 32 bytes: a reference, 16 bytes of payload and an explicit `CelValueKind` (the layout that the measurement of the kind tag chose; it is not part of the public contract, and no code outside `CelValue.cs` reads the fields).

| Kind | Storage | Runtime type |
| :- | :- | :- |
| `Null` | `default` | `null_type` |
| `Bool`, `Int`, `UInt`, `Double` | payload | `bool`, `int`, `uint`, `double` |
| `String` | the `string` | `string` |
| `Bytes` | the array or memory manager under a `ReadOnlyMemory<byte>`; payload: offset and length | `bytes` |
| `List` | a `CelList` | `list(dyn)` |
| `Map` | a `CelMap` | `map(dyn, dyn)` |
| `Type` | the `CelType` it denotes | `type(dyn)` |
| `Timestamp` | payload: Unix seconds in the first word, nanoseconds 0–999 999 999 in the second | `timestamp` |
| `Duration` | payload: the nanoseconds as one `long` | `duration` |
| `Object` | the instance, or a pair of a description and the instance ([objects](objects.md)) | the object type of its description |
| `Error` | the `CelError` | — |

**Runtime type** — `ValueTypeRules.TypeOf(value)`, the value of the function `type` and the type names of evaluation messages: parameters are erased, as the language definition says for type values, so `type([1]) == list`. A type value holds the full `CelType` (`int`, `list(dyn)` for the identifier `list`), but CEL compares type values only by kind and `Name`. The text of a message names a runtime type without parameters, as `ValueTypeNames` writes it — `list`, `map`, `type`, `null_type`, and for time the short names `timestamp` and `duration` — so `no such field 'missing' in map`; an object value is named by the full name of its description, an inaccessible bare instance by its .NET type ([objects](objects.md)), resolved when the error value is created.

**Fits a type** — `ValueTypeRules.Fits(value, type, meter)`, at any depth: `dyn` and type parameters take any value; a primitive type takes a value of its kind, and `timestamp` and `duration` are primitive types here: a timestamp takes a value of the kind `Timestamp` and nothing else, `null` included, since a static `null` is assignable to them but a value is not; `wrapper(P)` takes `null` and a value of `P`; `null_type` takes `null`; `type(…)` takes a type value, whatever type it denotes, since type values compare by kind and `Name` only; an object type takes `null` and an object value of that description ([objects](objects.md), "Fits"); an error value fits nothing. `list(E)` takes a list whose every element fits `E`, and `map(K, V)` a map whose every key fits `K` and every value fits `V`; the check descends only into a parameter that is neither `dyn` nor a type parameter, so `list(dyn)` and `map(string, dyn)` cost the top level and the keys only. Before it descends into a list of n elements or a map of n entries it charges n units to the meter (the cost table of the documentation, row "check against a declared type"); with no meter nothing is counted. On a mismatch it returns the type that the messages of 3011, 3015 and 3028 name as the actual type: at the top level the name of the type of the value (`string`, `list`); deeper the checked type with the parameter at the path of the first element, key or value that does not fit, in the order of enumeration, replaced by the name of the type of that element — `list(string)` for a list with a string checked against `list(int)`, `map(string, dyn)` for `{'a': 1}` against `map(int, dyn)`, `map(string, list(string))` for `{'a': ['b']}` against `map(string, list(int))`. A caller may let `null` also fit the positions that it names, as the facade does before a lazy view; the type that a mismatch returns is then written without that addition.

Evaluation uses it where a value comes from outside the expression or leaves it: bindings against the declared type of a variable (`BindingTypeMismatch`, 3011); the arguments of application functions against the declared parameter types, and their results against the declared result type, type parameters as `dyn` (`EvalNoMatchingOverload`; `ImplementationResultMismatch`, 3028); the arguments that a static type does not cover (see [evaluation](evaluation.md), "Calls"); and the value of the root before a lazy view, against the expected type of `T`, which names what the view reads, with `null` also fitting the positions that the view gives as `string`, `byte[]`, `CelList`, `CelMap` or `CelType` ([facade](facade.md), "Result conversion"). **A static type is no guarantee of the value.** Gradual type checking lets a `dyn` value into a position whose type a type parameter, bound by another argument, gives, and nothing generalizes the parameter ([types](types.md), "Assignability", rule 3): `[1] + dyn(['a'])` has the type `list(int)` and the value `[1, 'a']`, and `([1] + dyn(['a']))[1]` the type `int` and the value `'a'`, as in cel-go v0.32.0. So no code relies on a static type for the kind of a value it reads: library implementations check the kinds they read ([library](library.md)), application code gets checked arguments, and the result conversion checks a collection before it returns a lazy view. A view that the conversions create from a typed .NET collection records the CEL type its .NET type gives, such as `list(int)` for an adapter of `IReadOnlyList<long>`; when that type is assignable to the checked one without `dyn`, the view already fits, and the check does not descend into it and charges nothing. Other views — those of `CelList.CreateView` and `CelMap.CreateView`, whose converters return any value, and JSON — are checked like the lists of this part, reading the elements; an error element met there is the result of the check, with the position of the node that checks, not the mismatch code.

## Lists and maps

`ValueArrayList` is a `CelList` over an array that only it holds: list literals, `CelList.Create`, concatenation and the results of `map` and `filter` fill an array once, and nothing changes it afterwards. `EntryTableMap` is a `CelMap` over an array of entries in the order of insertion; enumeration walks the array, so the order never depends on hash codes. Keys compare by `EqualityRules`. A map of n entries takes at most 64 · (1 + 2n) bytes, the bound of its cost ([evaluation](evaluation.md), "Cost"), and finds a key in constant time: the empty map is one instance for the process; a map of up to 8 entries has no index and compares the key with each entry; a larger map has an index of positions with open addressing by `KeyHashRules`, not a `Dictionary`, whose entry alone takes 48 bytes. The hash of an integral key has a random seed for the process, as that of a string has, so that keys chosen to collide do not make a lookup linear. A key of a kind that cannot be a map key is refused first, then a key equal to one already present: a map literal turns the refusals into evaluation errors (see [evaluation](evaluation.md)), `CelMap.Create` into `ArgumentException`. `CelList.Create` and `CelMap.Create` also throw `ArgumentException` for an error value among the elements or values — an error is a result, not a value of a CEL type, as for `CelList.CreateSorted` — so no list or map of the library contains an error value: literals, concatenation, `map` and `filter` are strict and never put one in.

## Collections of the application

The collection rows of the type mapping table, by `ConversionRules.Collections.cs`. Each adapter is immutable and serves any number of threads at once; it reflects its source, and a source changed during an evaluation gives an undefined result.

| API | Count, index, lookup | Order | Errors |
| :- | :- | :- | :- |
| `CelList.CreateView(source, converter)` | `source.Count`; an element is `converter(source[i])` at each read, in O(1); nothing is copied | the order of `source` | an error value returned, or an exception of `source` or of the converter other than `OutOfMemoryException`, which becomes `ApplicationException` with the callee `a list of the application`, is the element |
| `CelList.CreateCopy(source, converter)` | converts and copies now, in the order of enumeration | that order | as for the view, kept as elements |
| `CelList.CreateSorted(source, converter)` | converts and copies now, then sorts by `OrderingRules`, strings by code points | ascending | `ArgumentException` for `null`, an error value, two kinds, a NaN or two elements equal in CEL; exceptions pass to the caller |
| `CelMap.CreateView(source, converter, keepSourceOrder)` | `source.Count`; a lookup converts the CEL key back to `TKey` and makes one lookup in `source`; a value is `converter(value)` at each read | `keepSourceOrder`, or `source` a `Dictionary`, `OrderedDictionary`, `SortedDictionary`, `SortedList` or `ImmutableSortedDictionary`: the order of `source`; otherwise ascending CEL keys, sorted at each enumeration | values as for the list view; a key of an enumeration over `ulong` above `long.MaxValue` is `ConversionRange` when an operation meets it |

**Keys** to CEL: `string` as is; `Guid` as the string of format `D`, lower case; signed integers and enumerations as `int`; unsigned integers as `uint`; `bool`. Any other `TKey` is `ArgumentException` of `CreateView`. **Keys back** to `TKey`, for a lookup, `in` and `has`: a CEL key of another kind than the one `TKey` gives, or out of the range of `TKey`, finds nothing, without an error; the numeric keys meet on one number line as in "Map keys", so the key `1` of a dictionary over `int` is found by `1`, `1u` and `1.0`. A `Guid` key is found only by the canonical string — 36 characters, format `D`, lower case — exactly the string the enumeration gives: `Guid.TryParseExact` alone would also take upper case, so `{…}` braces, upper case and the formats `N`, `B`, `P` find nothing, and a map of `Guid` keys behaves as a map of its canonical strings.

**Error elements.** An element or a value of a collection of the application may be an error value, unlike a collection of the library. An operation that reads it — an index, a key lookup, a comprehension over it, `in`, equality, the check against a declared type, the result conversion — gets it as the value read: an index or a lookup returns it, a comprehension puts it into the iteration variable, equality and `in` return it. An error value that application data gives has no position of its own; the node that read it gives it its position. When several element errors meet in the check against a declared type or in the result conversion, the first one in the order of the check walk is returned (a list — by index, a map — in the order of iteration). `size` reads no element.

**Input rows of objects and collections** — the conversions of bindings, of `AddVariable<T>` and of the delegate forms of `AddFunction`, by the static type:

| .NET | CEL type | Value |
| :- | :- | :- |
| `T[]`, `IReadOnlyList<T>`, `IList<T>`, `List<T>`, `ImmutableArray<T>`, `ImmutableList<T>`, `ReadOnlyCollection<T>` | `list(E)`, `T` → `E` by these rows | a typed view, lazy |
| `IReadOnlySet<T>`, `ISet<T>` | `list(E)` | sorted as by `CreateSorted` at the conversion; elements that `CreateSorted` refuses are `ArgumentException` of `CelBindings.Add`, and in the result of an application function `InvalidArgument` (3008) at the call ([evaluation](evaluation.md), "Application functions") |
| other `IReadOnlyCollection<T>` | `list(E)` | copied as by `CreateCopy` at the conversion |
| `IReadOnlyDictionary<K, V>`, `IDictionary<K, V>`, `Dictionary<K, V>` | `map(K', V')`, keys as above | a typed map view, lazy; another key type is `TypeNotDeclared` at `Build` and `ArgumentException` of `CelBindings.Add`. Bound to a variable of an object type `T` whose carrier class the source is an instance of — `IReadOnlyDictionary<string, object?>` for a type of `ForDictionary` — the view is its source, a carrier of `T`, by the place rule ([objects](objects.md)) |
| `JsonElement` | `dyn` | "`JsonElement`" below; `default(JsonElement)` is `ArgumentException` of `CelBindings.Add` |
| a class, record, struct or interface outside `System` | the object type that a type source describes for it by the type index ([objects](objects.md)), resolved at `Build`; none is `TypeNotDeclared` | a bare instance, a struct boxed once at the conversion; the carrier of a type described at run time too, which the place rule pairs at the first read of a variable of that type |

A typed collection nests one step deep, as the result rows do: `IReadOnlyList<IReadOnlyList<long>>` is outside the rows. A view of these rows keeps its source and records that the rows made it, which a view of `CelList.CreateView` or `CelMap.CreateView` does not: the place rule looks through the first only. The `object` row rejects no instance: a boxed `CelValue`, `CelList` or `CelMap` is taken as it is, and any other instance outside the rows, a .NET collection included, is a bare object value. `CelBindings` knows no environment, so the node that reads the value decides with the type index, by the steps of [objects](objects.md), "Reading a value of the application": a carrier of the declared object type of the place; else a described instance, though enumerable; else a .NET collection — `System.Collections.IEnumerable` except `string`, `byte[]`, `CelList` and `CelMap` — is `TypeNotAccessible` (3012) with its .NET type at the identifier, the selection or the call; else a bare object described lazily. An element or a value of a collection of the application takes none of these steps and is described lazily. Objects in a `dyn` place are described by their .NET type ([objects](objects.md)).

## `optional`

The kind `Optional` is the value of the type `optional_type(T)` of the set [optional](extension-optional.md). Its members are the ones that the skeleton declares; the part gives them bodies, and the kind takes the rows below in the rule files of this page. This section supersedes the sentences of this page that leave `optional` to a later part.

**Storage.** A `CelValue` of the kind `Optional` has no payload; the reference field tells the two states:

| State | Reference | Memory |
| :- | :- | :- |
| empty | `null` | none: `CelValue.FromOptional(default)` and `optional.none()` return one static value |
| holds a value | one `OptionalBox` | one object of 48 bytes: the header and one `CelValue`, which is 32 bytes; inside the 64 bytes of the unit that `optional.of` costs |

`OptionalBox` is an internal sealed class of `Values` with the one field `CelValue Value`, set by the constructor; the value it holds is any value but an error: `null` is a value, a list and a map are references, an optional is a value too, so `optional.of(optional.none())` holds an empty optional. A box is immutable and shared by any number of threads, as the value it holds is.

**`CelOptional<T>`.** A `readonly struct` of one `T` and a flag; `default` has no flag and is empty. The constructor takes any `T`, `null` included, and sets the flag; `HasValue` is the flag; `Value` is the field when the flag is set, otherwise `InvalidOperationException` with the text `The optional is empty.`. `Equals(CelOptional<T>)` is true when both are empty, or both hold values that are equal by `EqualityComparer<T>.Default`; an empty and a non-empty optional are never equal, so `new CelOptional<string?>(null)` differs from `default`. `GetHashCode` is 0 for an empty optional and the combination of a constant with the hash of the value, 0 for `null`, otherwise; the two operators call `Equals`; `Equals(object?)` is true for a `CelOptional<T>` that is equal. This is .NET equality, which a NaN satisfies with itself; it is not the CEL `==` of the row below.

**`CelValue.FromOptional(CelOptional<CelValue> value)`** returns the static empty value for an empty `value` and a new box for a non-empty one; `ArgumentException` when the held value has the kind `Error`, since an error is a result and no value of CEL ("Lists and maps" says the same for a list and a map). **`TryGetOptional(out CelOptional<CelValue> value)`** is true for the kind `Optional`, and `value` is then `default` or the constructed optional; for any other kind it is false and `value` is `default`. Neither allocates but the box of `FromOptional`.

| Rule | For the kind `Optional` |
| :- | :- |
| `ValueTypeRules.TypeOf` | `optional_type(dyn)`, one static type, whatever the held value is: parameters are erased, as for lists. `type(optional.of(1)) == optional_type` and `type(optional.none()) == type(optional.of(1))` are `true` |
| `ValueTypeNames` | `optional_type` |
| `ValueTypeRules.Fits` | `optional_type(E)` takes an optional whose held value fits `E`, and the empty optional always; `E` equal to `dyn` or a type parameter takes any optional without looking at the held value. It descends only into a parameter that is neither, and charges what the descent into the held value charges, nothing for the optional itself. `null` and every other kind do not fit: a `null` value is no optional, though the type `null_type` is assignable to `optional_type(T)` statically |
| `EqualityRules` | CEL equality: two empty optionals are equal; an empty and a non-empty one are not; two non-empty ones are equal when their held values are equal by CEL equality, so an error of the comparison — an error element of an application collection — is the result, a NaN is not equal to itself, and `optional.of(1) == optional.of(1.0)` is `true`. An optional and a value of another kind are not equal, without an error; `optional.of(null) == null` is `false`. eq(a, b) is 1 when either is empty or the kinds differ, and 1 + eq of the held values when both hold one |
| `OrderingRules` | none: no overload orders optionals, and a `dyn` pair is `EvalNoMatchingOverload` |
| `KeyHashRules` | an optional is no map key: `UnsupportedMapKeyType` (3027), `unsupported map key type 'optional_type'` |
| `CelValue.Equals`, `GetHashCode` | .NET equality: the same kind and both empty, or both held values equal by `CelValue.Equals`; the hash is the kind combined with 0 or the hash of the held value |
| conversion to .NET | [below](#conversion-of-optional-values) |
| conversion from .NET | `CelOptional<X>` converts into the optional of the converted held value; the type `optional_type(E)` of the input rows. [below](#conversion-of-optional-values) |
| `string()`, `json.encode`, `format` | no overload of `string` takes an optional; `json.encode` and the clauses of `format` refuse the kind with the errors that they give for the kind `Abstract` ([extension-library](extension-library.md#encoders), [extension-format](extension-format.md)) |
| `dyn` | an optional passes `dyn()` as any value does; `dyn(optional.of(1)).value()` is 1, by dispatch on the value |

### Conversion of optional values

*From .NET*: the input row of the type mapping table, `CelOptional<X>` to `optional_type(E')` with `E'` the type of `X` by these rows. The empty `CelOptional<X>` is the empty optional, and a non-empty one the box of the converted value. A held value that the conversion refuses is an error value where the variable or the result of the function is read, as for any other value, never an exception of `CelBindings.Add`. The type `optional_type(E')` needs the set `optional` in the environment: a declaration that infers it from `CelOptional<X>` is `TypeNotDeclared` without it ([extension-optional](extension-optional.md#the-type-optional_typet)). A `CelOptional<X>` in a place of type `dyn` or as an `object` has the type `optional_type(dyn)` and a held value converted by the row of its runtime type. The structure knows its type argument and the conversion does not, so `CelOptional<T>` implements the internal interface `IOptionalSource` explicitly, with the one member `TryToCelValue`, and the input rows read a boxed `CelOptional<X>`, or a generic `T` that is one, through it. The interface is internal and the implementation explicit, so no public member is added and `PublicAPI.Unshipped.txt` does not change. The read is a cast of a boxed structure and uses no reflection, so it holds under Native AOT; the box lives for one conversion and is no memory that a unit pays for.

*To .NET*: the result row `optional_type(E)` to `CelOptional<X>`, `X` by the result rows for `E`. The conversion first checks the value at depth against the expected type that `T` gives, `optional_type(E')`, with `null` also fitting the positions that the held value takes as `string`, `byte[]`, `CelList`, `CelMap` or `CelType`, the addition that the check before a lazy view makes ([facade](facade.md), "Result conversion"; the type mapping page): an optional has no view, but its held value is read as an element of a copy is, so `optional.of(null)` read as `CelOptional<string>` has a value, `null`, and differs from `optional.none()`, which is `default`. A position of `ReadOnlyMemory<byte>`, `long`, `int` or another value type does not take `null`, `long?` and the other `Nullable<X>` take it as `wrapper(P)` does, and the `{celType}` of a mismatch names the checked type without the addition. The optional itself never takes `null`: a `null` value is no optional, as the row `Fits` above says. Then it converts the held value by its own row, `ResultConversion` (3015) with the place of the root when that row refuses it. The held value is converted at evaluation and never lazily: a `CelOptional<X>` is a struct that holds an `X`, so there is no view of an optional. When `X` is a collection the held value is a lazy view or an immutable copy by the rule of the collection rows, which decides by the static type of the root; neither is charged. `T = CelValue` gives the value as it is, and `T = object` a `CelOptional<object?>` whose held value is the natural mapping of its kind.

*The expected type* that `T` gives is the row of the expected-type table: `CelOptional<X>` gives `optional_type(E')` with `E'` the expected type of `X`, and `CelOptional<CelValue>` and `CelOptional<object?>` give `optional_type(dyn)`. A program whose root has the static type `optional_type(R)` reports that type as `ResultType` — a free type variable of `R` is bound by the check against the expected type, so `optional.none()` read as `CelOptional<long>` has `optional_type(int)` and, read as `CelValue` or `CelOptional<object?>`, `optional_type(dyn)` ([checking](checking.md#expected-type)) — and passes an expected `optional_type(E')` when `R` is assignable to `E'` by the rules of [types](types.md#optional-types-in-the-rules); a root of type `dyn` passes any expected type, and its optional value is converted, or refused, at evaluation. `CelCompileOptions.ExpectedType` may name `optional_type(int)` with `T = CelValue`, since `CelValue` is in the column of the types that take every CEL type.

## `JsonElement` — `JsonRules`

The JSON data conversion of the language definition, read lazily: the conversion looks at the kind of the element it reads, and only there.

| `JsonValueKind` | Value |
| :- | :- |
| `Null`, `True`, `False` | `null`, `bool` |
| `Number` | `double` by `TryGetDouble`, integers included; a number that is not a finite `double` is `ConversionRange` `{text} is out of the range of double`, `{text}` the number as written in the document |
| `String` | a new `string` at each read |
| `Array` | a `CelList` adapter of the element: count, index, enumeration in document order |
| `Object` | a `CelMap` adapter of the element, `map(string, dyn)`, enumeration in document order |
| `Undefined` (`default(JsonElement)`) | only from the application, never inside a document: a field value or the result of an application function is `InvalidArgument` (3008) `invalid argument to '{name}': undefined JSON element`, `{name}` `<type>.<field>` or the overload identifier, at the selection or the call |

**Repeated names.** A key lookup — an index, a selection, `has` — compares the key ordinally with every property name of the object, escape sequences decoded, and counts the matches: 0 is no key, 1 the value, 2 or more `DuplicateMapKey` (3010) with that key. `size`, enumeration, `in` and equality check every name for a repeat, by hashing with the random seed of `KeyHashRules`, before their result; a repeat is 3010 with the first name, in document order, that repeats an earlier one. The key of the text of 3010 is written as a string literal ([evaluation](evaluation.md)). A key that is not a `string` finds nothing. A JSON object equals a map by the rule of maps, with this lookup.

An `ObjectDisposedException` of an element whose document the application disposed is `ApplicationException` with the callee `a JSON element`. `JsonElement` is never a result: a JSON value converts by the `list`, `map` and primitive result rows.

## Collections read by created code

The members of .NET types that the source generator describes come through the same factories as the collections of an application: `CelList.CreateView` for an array and every `IReadOnlyList<T>`, `CreateSorted` for a set, `CreateCopy` for a collection with a size and no index, `CelMap.CreateView` with `keepSourceOrder` `false` for a dictionary, so the order of a map is decided by the type of its source, as the collection rows above say. The generator knows the static types, so it nests without the limit of one step that the input rows of a binding have: `List<List<int>>` and `Dictionary<string, List<Order>>` are instantiated in the created code ([generator-output](generator-output.md), "Collections"). A converter of an element is created once and is not created at a read. Wrappers are made only for an instance that does not implement `IReadOnlyList<T>` or `IReadOnlyDictionary<K,V>`, by a check at run time, so the order of a `Dictionary` that is declared `IDictionary<K,V>` is the order of the dictionary. An element of `CreateSorted` that CEL cannot order — `null`, a `NaN`, two equal elements — is the `ArgumentException` of that method, which evaluation turns into `ApplicationException` (3014) at the field selection.

## Time — `CelTimestamp`, `CelDuration`, `TimeTextRules`

**Structures.** `CelTimestamp` keeps `Seconds`, a `long` of Unix seconds from −62 135 596 800 to 253 402 300 799, and `Nanoseconds`, an `int` from 0 to 999 999 999: the range of `timestamp` is 0001-01-01T00:00:00Z to 9999-12-31T23:59:59.999999999Z, and the nanoseconds of an instant before the epoch count forward from the whole second below it (the seconds −1 and the nanoseconds 999 999 999 are one nanosecond before the epoch). The constructor checks both and throws `ArgumentOutOfRangeException`; `default` is the epoch. `CelDuration` keeps one `long`, the nanoseconds, and accepts any. Both are `readonly struct`s without references. `CelValue.FromTimestamp` and `FromDuration` copy the fields into the two payload words, without allocation; `TryGetTimestamp` and `TryGetDuration` rebuild the structure by a private constructor that skips the check, since the payload was checked when it was made. No code makes a `CelValue` of time outside the range: the operations of the library check their results ([library](library.md)) and every conversion from .NET checks its input. `CelType.Timestamp` and `CelType.Duration` are static instances: `Kind` `Timestamp` or `Duration`, no parameters, `Name` `google.protobuf.Timestamp` or `google.protobuf.Duration`, text form `timestamp` or `duration`.

**.NET equality and hash.** Two `CelValue`s of time are equal when the kind and the payload are; the hash combines the kind with the seconds and the nanoseconds, or with the nanoseconds. `CelTimestamp` and `CelDuration` have equality, comparison and the six comparison operators over the same payload, and `ToString` gives the text below; none reads a culture.

**`DateTimeOffset`, `DateTime`, `TimeSpan`** count in ticks of 100 ns from 0001-01-01.

- To a timestamp: `DateTimeOffset` by `UtcTicks`, `DateTime` of the kind `Utc` by `Ticks`. With `t` the ticks, `Seconds = t / 10 000 000 − 62 135 596 800` and `Nanoseconds = (t % 10 000 000) · 100`. Every `DateTimeOffset` converts exactly, and no property of the clock or of a zone is read.
- From a timestamp to a `DateTimeOffset` with offset 0: when `Nanoseconds` is a multiple of 100, `UtcTicks = (Seconds + 62 135 596 800) · 10 000 000 + Nanoseconds / 100`; otherwise the conversion is refused, never rounded.
- `DateTime` of the kind `Local` or `Unspecified` is refused, since its meaning would depend on the zone of the process.
- To a duration: `TimeSpan.Ticks · 100` when `Ticks` is within `long.MinValue / 100` and `long.MaxValue / 100`, else refused. From a duration: `Ticks = nanoseconds / 100` when the nanoseconds are a multiple of 100 (the result is always within the range of `TimeSpan`), else refused.

A refusal is, by where it happens: in `CelBindings.Add`, a `DateTime` that is not `Utc` throws `ArgumentException` naming its kind, also when the `DateTime` is boxed as `object`, because the value becomes a `CelValue` at once; a `TimeSpan` outside the range becomes the error value `ConversionRange` `{ticks} ticks is out of the range of duration`, which the node that reads the variable gives its position, like an enumeration above `long.MaxValue`. Read lazily — a field, an element or a value of a collection of the application, the result of a typed delegate — a `DateTime` that is not `Utc` is the error value `InvalidArgument` (3008) `invalid argument to '{name}': a DateTime of the kind {kind} is not an instant in UTC`, with `{name}` `<type>.<field>`, the overload identifier, `a list of the application` or `a map of the application`, at the node that reads it, as for an undefined JSON element. For the public structures it is `ArgumentOutOfRangeException` (the constructors, `FromTimeSpan`) or `false` (`TryGet…`).

**Nullable forms.** `DateTimeOffset?`, `DateTime?`, `TimeSpan?`, `CelTimestamp?` and `CelDuration?` have the CEL type of the value, since CEL has no wrapper of time: `AddVariable<DateTimeOffset?>` declares `timestamp`. A `null` binding of such a variable is the `null` value, which fits neither `timestamp` nor `duration` ("Fits a type"): `BindingTypeMismatch` with the actual type `null_type` at the first read of the variable. A typed delegate that returns such a `null` is `ImplementationResultMismatch` with `null_type`.

**At any depth.** A time value is a scalar. An element of a list or a value of a map comes through `CelList.Create`, `CelMap.Create` and the converters of `CreateView` and `CreateCopy`, which return `CelValue`; through `IReadOnlyList<object>` or `IReadOnlyDictionary<K, object>` whose elements are boxed `DateTimeOffset`, `DateTime`, `TimeSpan`, `CelTimestamp` or `CelDuration`, which the `object` row converts by the runtime type; and through `dyn` and `CelValue`. A typed collection of time, `IReadOnlyList<DateTimeOffset>` or `IReadOnlyDictionary<string, TimeSpan>`, is outside the closed list of elements ([facade](facade.md), "Typed nesting is one step"): `AddVariable<T>` is `TypeNotDeclared` and `CelBindings.Add<T>` `ArgumentException`. A field of an object with the CEL type `timestamp` or `duration` takes a value of that kind at the top level ([objects](objects.md), "Types described at run time"); its read delegate returns `CelValue.FromTimestamp(…)`, which allocates nothing, and the members of .NET classes that a generator reads in a later part use the rows above. A time value in a place of type `dyn` is read as the kind it is, and `type(v)` is `google.protobuf.Timestamp` or `google.protobuf.Duration`.

**Error elements and the check of the type.** A time value has no elements and is never an error element, so the three outcomes of the check — fits, does not fit, an element error met — never come from it: a timestamp fits `timestamp` and `dyn` and nothing else, a duration likewise. The result conversion is the same: at the root, `T = DateTimeOffset` or `TimeSpan` can fail on the nanoseconds, `ResultConversion` at the root; no collection row of time exists, so a failing time narrowing never decides between a lazy view and a copy, and the rule that an element error wins over a failed narrowing is not touched.

**Text of time.** `TimeTextRules` reads and prints with its own code over `ReadOnlySpan<char>` and `Span<char>`, without a culture and without `DateTime.Parse`, `TimeSpan.Parse`, `DateTimeOffset.Parse` or floating-point formatting; a string is created only for a result.

- *Timestamp from a string*, `timestamp(string)`: exactly `YYYY-MM-DD`, `T`, `hh:mm:ss`, an optional `.` with one or more digits, and `Z` or `±hh:mm`; ASCII digits only; `T` and `Z` upper case. This is the cel-go pattern followed by `time.Parse` of Go 1.27.3. The month is 01–12; the day is 01 up to the length of the month by the Gregorian rule, year 0000 being a leap year; the hour is 00–23, the minute 00–59, the second 00–59 (60 is refused); the offset hour is 00–23 and its minute 00–59. Digits of the fraction after the ninth are dropped without rounding, fewer are padded with zeros on the right. The instant is the local time minus the offset; `-00:00` is `Z`. A string that is not of this form is `InvalidArgument` (3008) `cannot parse {text} as timestamp`; one that is, but whose instant is before 0001-01-01T00:00:00Z or after 9999-12-31T23:59:59.999999999Z — year 0000, `0001-01-01T00:00:00+01:00` — is `ConversionRange` (3007) with the string as `{value}`. The syntax is checked first, then the day of the month, then the range.
- *Timestamp to a string*, `string(timestamp)`: `YYYY-MM-DDThh:mm:ssZ` in UTC with a four-digit year, and when the nanoseconds are not 0 a `.` and the nine-digit nanoseconds without trailing zeros: 20 characters, or 21 plus the digits of the fraction, at most 30. The length is computed from the nanoseconds before the string is made. The offset of a parsed string is not kept: `2023-01-01T00:00:00-07:00` is `2023-01-01T07:00:00Z`.
- *Duration from a string*, `duration(string)`: the algorithm of `time.ParseDuration` of Go 1.27.3, with the code of each failure, in the order of the algorithm; the first failing check decides:
  1. an optional `+` or `-`;
  2. the rest `0` is zero; an empty rest is `InvalidArgument`;
  3. repeated until the string ends: the next character must be a digit or `.`, else `InvalidArgument`; the digits are read as an unsigned integer `v`, and more than 2⁶³ is `ConversionRange`; after a `.` the digits are read as `f`, and `scale` is ten to the power of the number of digits kept in `f`; a digit is kept while `f · 10 + digit` is at most 2⁶³, so `f` can reach 2⁶³ itself (`leadingFraction` of Go); the first digit that would take `f` above 2⁶³ and every later digit of the same fraction are skipped, without an error and without a factor of ten in `scale`; neither a digit before nor one after the `.` is `InvalidArgument`; the unit is the text up to the next digit or `.`, and an empty unit is `InvalidArgument`; a unit other than `ns`, `us`, `µs` (U+00B5), `μs` (U+03BC), `ms`, `s`, `m`, `h`, compared ordinally, is `InvalidArgument`; `v` above 2⁶³ / unit is `ConversionRange`; `v = v · unit`; when `f > 0`, `v = v + (ulong)((double)f · ((double)unit / scale))` — the only floating-point step, kept as Go has it so that a fraction is cut the same way, and IEEE 754 operations give the same result on every platform — and `v` above 2⁶³ is `ConversionRange`; `d = d + v`, and `d` above 2⁶³ is `ConversionRange`. `v`, `f` and `d` are unsigned 64-bit numbers, and the sum wraps at 2⁶⁴ as the `uint64` of Go does: both terms are at most 2⁶³ there, so it wraps only when both are 2⁶³, and then `d` is 0 and passes the check — `9223372036854775808ns9223372036854775808ns` is `0s`, as `time.ParseDuration` and cel-go give it, and a later group adds to that 0;
  4. a negative string gives `−d`, so `-9223372036854775808ns` is valid; a positive `d` above 2⁶³ − 1 is `ConversionRange`.

  The text of 3008 is `cannot parse {text} as duration`; `{value}` of 3007 is the string.
- *Duration to a string*, `string(duration)`: the magnitude `m` as an unsigned 64-bit number, so `long.MinValue` is no special case; a `-` for a negative value, `m / 10⁹` in decimal, when `m % 10⁹` is not 0 a `.` and the nine-digit remainder without trailing zeros, then `s`; zero is `0s`. So `1.5s`, `-1.5s`, `60.001s`, `9223372036.854775807s`, `-9223372036.854775808s`: at most 22 characters, known from the value before the string is made. No `double` is used, unlike cel-go.

## `decimal`

The kind `Decimal` is the value of the type `decimal` of the set [decimal](extension-decimal.md), on `net11.0` only: every member below is under `#if NET11_0_OR_GREATER`, and `net10.0` has neither the kind nor a row for it. The members are the ones that the skeleton declares; the part gives them bodies, and the kind takes the rows below in the rule files of this page. This section supersedes the sentences of this page, of [facade](facade.md) and of [objects](objects.md) that leave `decimal` to a later part, and the marker "of a later part" of `ConversionRules` for `decimal` and `System.Decimal` goes in both targets.

**Storage.** A `CelValue` of the kind `Decimal` has no reference, except for one mark that only the text of an error reads ([evaluation](evaluation.md#decimal-in-a-dyn-place)); the payload holds the BID bits of the value, `Decimal128.EncodeBinary`, the low 64 bits in the first word and the high 64 bits in the second. Nothing is allocated, and the parts of the value — sign, coefficient, exponent — are read from the bits by `DecimalParts` only where a function needs them ([decimal-text](decimal-text.md#the-parts-of-a-value)); arithmetic and comparison take the `Decimal128` back with `DecodeBinary` and work on it.

**`CelValue.FromDecimal(Decimal128 value)`** returns the value with the bits as they are, so the digits, the exponent and the sign of a zero are kept: `1.50` and `1.5` are different bits, and `-0` stays negative. A NaN and an infinity, which `Decimal128.IsFinite` refuses, are `ArgumentException` with the text `A decimal must be finite: a NaN and an infinity are not values of CEL.`. **`TryGetDecimal(out Decimal128 value)`** is true for the kind `Decimal`, with the value of the bits, and false for any other kind, with the zero `Decimal128`. A bit pattern that is not canonical — a coefficient above 10³⁴ − 1, which only a `Decimal128` made from raw bits can have — is stored and read as a zero by both `Decimal128` and `DecimalParts`, so the two never disagree.

## Equality — `EqualityRules`

CEL equality, `==` of the library and `CelValue.CelEquals`, by the language definition, "Equality", and the cases of cel-spec:

- `int`, `uint` and `double` compare on one number line: two numbers are equal when neither is less than the other by the ordering below. So `1 == 1u == 1.0`, and an `int` and a `double` compare as the `double` and the `int` rounded to the nearest `double` — the cel-spec cases `comparisons/…_lossy_double` require it. A NaN equals nothing, itself included.
- Values of different non-numeric kinds are not equal, without an error; `null` equals only `null`.
- `bool` by value; strings by their UTF-16 code units, which is equality of code points; bytes by content.
- Type values by kind and `Name`.
- Timestamps when the seconds and the nanoseconds are equal, durations when the nanoseconds are equal. A timestamp is never equal to a duration, a number or a string, and the comparison is never an error for that.
- Lists: the same count and the elements pairwise equal. Maps: the same count, and each key of the left map is found in the right one by the key lookup below with an equal value; a JSON object checks its names for repeats first and is searched by its counting lookup ("`JsonElement`"). An error element of a collection of the application is the result when the comparison reaches it.
- Objects: by their descriptions and fields ([objects](objects.md), "Equality of objects").
- An error value as an operand is the result. Nested lists and maps check the stack before each level; `false` is `InsufficientStack` (`insufficient execution stack to continue comparing values`) at the call.

## Ordering — `OrderingRules`

The result is less, equal, greater or unordered; the library turns it into the `bool` of `<`, `<=`, `>`, `>=`, and unordered into `false`, as the standard library page says. Types that have no ordering — lists, maps, `null`, types — never reach it: the library has no overload for them.

- `bool`: `false < true`. `int`, `uint`, `double` among themselves as numbers. `string` by code points. `bytes` by unsigned byte values, a prefix first.
- Across numeric kinds, as cel-go v0.32.0 `common/types/compare.go` and the cel-spec cases `comparisons/…_big_…` require: `int` with `uint` exactly; `int` with `double` — a `double` below −2⁶³ is less, above 2⁶³ greater, otherwise the `int` rounded to `double` is compared; `uint` with `double` — a negative `double` is less, above 2⁶⁴ greater, otherwise the `uint` rounded to `double` is compared.
- `timestamp` by the pair of seconds and nanoseconds, `duration` by the `long`; a timestamp and a duration, or either of them and a number, have no ordering between them.
- A NaN on either side is unordered.
- **Strings by code points.** Compare UTF-16 code units up to the first difference; when both differing units are at least U+D800, first map a unit at U+E000 or above to itself minus U+0800 and a surrogate to itself plus U+2000 (the code point order fix-up of the Unicode Standard, section 5.17). `string.CompareOrdinal` alone orders U+E000–U+FFFF after supplementary characters, against the language definition and cel-go.

## Map keys — `KeyHashRules`

Keys are `int`, `uint`, `bool` and `string`; a `timestamp` or a `duration` is refused as a key like any other kind (`UnsupportedMapKeyType`, `unsupported map key type 'timestamp'`) and has no hash for a map. An `int` and a `uint` with the same value are one key and have one hash; strings hash by ordinal comparison. A lookup — index, `in`, `has` on a map, the equality of maps — with:

- an `int` finds an `int` key, or a `uint` key when it is not negative; a `uint` the other way round;
- a `double` converts first, without loss, to `int` when it has an integral value inside the open range of `int` (the limits page: `double` to `int`, bounds excluded), and looks that up, else to `uint` when it has an integral value in [0, 2⁶⁴); otherwise it finds nothing, so `{1: 'a'}[dyn(1.0)]` is `'a'` and `{1: 'a'}[dyn(1.5)]` has no key;
- any other kind, `timestamp` and `duration` included, finds nothing.

The collection, object and `JsonElement` rows are in "Collections of the application" and "`JsonElement`" below. `decimal` comes with its part; until then `ConversionRules` throws `NotImplementedException` for it, and `AddVariable<T>` and `AddFunction` report it as `TypeNotDeclared` (see [declarations](declarations.md)). The kinds of .NET types that are never read — the table of types not read of the type mapping page, such as `char`, `Int128` and the classes of `System` without a row — are `TypeNotDeclared` as well.

**CEL to .NET** — `ConversionRules.Result.cs`: the result rows of the type mapping table, which the facade describes with the expected type (see [facade](facade.md)), and the same rows for the parameters of delegate implementations: a refusal there is `ArgumentConversion` (3024) with the function, the overload identifier and the parameter. That is a refusal by the value only, such as an `int` outside `Int32`: the CEL type of a parameter is the one that the expected-type table derives from its .NET type, and a parameter whose type is not the declared one — `Guid`, `short`, `float`, an enumeration, `CelList` for `list(int)`, a typed collection nested deeper than one step ([facade](facade.md), "Expected type") — is `ImplementationSignatureMismatch` at `Build` ([declarations](declarations.md)). So `IReadOnlyList<long>` and `IReadOnlyList<int>` take `list(int)`, by the pairs of the list row. A declared `wrapper(string)` or `wrapper(bytes)` also takes `string` or `byte[]`, to which the `null` value passes as a `null` reference. The result rows of time: a `timestamp` is `CelTimestamp`, or `DateTimeOffset` when its nanoseconds are a multiple of 100 and otherwise a refusal; a `duration` is `CelDuration`, or `TimeSpan` when its nanoseconds are a multiple of 100 and otherwise a refusal; the `Nullable<>` of each takes the value, and `null` gives `null`; `object` gives `CelTimestamp` and `CelDuration`; `DateTime` has no result row. As a parameter of a typed delegate the same rows apply, a refusal is `ArgumentConversion` (3024) at the call, with the CEL type written `timestamp` or `duration`, and a `DateTime` parameter is `ImplementationSignatureMismatch` ([declarations](declarations.md)).

## `Any` and the known types in the value rules

The core decides few things about the known types of protobuf, and the protobuf package the rest; no kind of value or of type is added for them beyond `CelTypeKind.Any`, which the skeleton already has.

| What | Decided by |
| :- | :- |
| the CEL type that a name stands for — `Any`, `dyn`, `map(string, dyn)`, `list(dyn)`, the wrapper types ([types](types.md#well-known-names)) | the core, `WellKnownRules` |
| the type `Any` in the checker, assignability, the check of a literal and its plan, `has`, the cost of a literal | the core ([checking](checking.md), [evaluation](evaluation.md#message-literals)) |
| the value of a field of a known type: a wrapper or `null`, a map, a list or a `dyn` value of the JSON-like types, `CelTimestamp`, `CelDuration`, the unpacked content of an `Any` or `null` for one that is unset; a `NullValue` field is an enumeration, an `int` | the package, through public factories and views of the value model ([protobuf](protobuf.md#reading-a-field)) |
| the writing of such a value in a literal, the conversions to `Value` and `Any`, and the equality of messages | the package ([protobuf-messages](protobuf-messages.md)); the core only dispatches the equality ([objects](objects.md#members-for-protobuf-messages)) |

**Rows of the rule files for `Any`:**

- `ValueTypeRules.Fits(value, Any)` takes every value but an error value, as `dyn` does; at any depth the check of `list(Any)` or `map(string, Any)` descends and finds every element fitting. `ValueTypeRules.TypeOf` has no row: no value has the type, and a value that an `Any` field gave is typed by its content. `ValueTypeNames` has no row for the same reason; the text form `any` of the type is that of `CelType`.
- `ConversionRules`: the CEL type `Any` of a declared parameter or result of an application function maps to the .NET types of `dyn` — a parameter takes `CelValue` and `object`, a result of the type `Any` is checked as `dyn` is, which is not at all. The skeleton rows that reject `Any` as not yet supported are removed. The input rows have no row of their own: a .NET `Google.Protobuf.WellKnownTypes.Any` is not a type of the rows, so `AddVariable<Any>` is `TypeNotDeclared` and a value of that type in a `dyn` place is `TypeNotAccessible`, as for the other known types of `Google.Protobuf` ([protobuf](protobuf.md#the-known-types)).
- `EqualityRules` has no row for `Any`: nothing is of that kind. An object value whose description has an `EqualityCost` is compared by its own `CelEquals`, as [objects](objects.md#members-for-protobuf-messages) says; the rest of the rule is as above.

## Members implemented in this part

`CelValue`: `Kind`, `Null`, the factories and `TryGet…` methods of every kind on this page, `FromType` and `TryGetType`, `FromObject` and `TryGetObject` ([objects](objects.md)), `CelEquals`, and .NET equality — the same kind and content, NaN equal to itself, strings ordinal, bytes by content, types by `CelType.Equals`, lists, maps and errors by reference, objects by the instance and the description of a pair; evaluation does not use it, so it is no rule file. `CelList`: `Count`, the indexer, enumeration, `Create`, `CreateView`, `CreateCopy`, `CreateSorted`. `CelMap`: `Count`, `TryGetValue` by the key lookup above, enumeration, `Create`, `CreateView`. The members of time are implemented in this part ("Time"): `CelTimestamp` and `CelDuration` with their members, `CelValue.FromTimestamp`, `FromDuration`, `TryGetTimestamp`, `TryGetDuration`, and `CelType.Timestamp` and `CelType.Duration`. The members of `optional` are implemented by the section `optional` above; those of `decimal` keep throwing `NotImplementedException` until its part.
