# Simple entry: `CelExpression`, the registry of anonymous data and the hidden cache

`CelExpression.Evaluate<T>` evaluates a text on a dictionary or an anonymous object in one call, without an environment in the code of the application. The values it reads are the closed list of `docs/type-mapping.md` ("Data of the simple entry"); its numbers are in `docs/limits.md` ("Simple entry"). This page is the inside: the shape of the data, the hidden environments and programs, the registry, threads.

The files are in the directory `SimpleEntry/` and in the namespace `Great.Parts.Cel`, all internal. A namespace of their own would reference `Great.Parts.Cel` (the builder, the environment, `CelException`) and be referenced by it (`CelExpression`, `CelAnonymousData`), a cycle that `ARCH001` refuses; so `eng/layers.txt` has no row for them.

## One call

1. `expression` or `data` `null` — `ArgumentNullException`; the token is checked.
2. The shape. A dictionary (the dictionary overload, or `data` that is one of the dictionaries of the list) gives the shape "dictionary": the sorted list of pairs (name, CEL type of the value) by `string.CompareOrdinal`, the type from `SimpleValues` (for `IReadOnlyDictionary<string, X>` with `X` not `object` the one type of `X`). Anything else is looked up by `data.GetType()` in the registry, a dictionary read without a lock in O(1) that a registration replaces by a copy: found, the shape is "anonymous type" with that `Type`; not found, the call fails with `TypeNotDeclared` (4008) for `data`. A value outside the list fails with 4008 for its key before any environment is built; every key with such a value gives its error, in the order of the names (ordinal), and the exception carries them all.
3. The environment of the shape. An anonymous type goes to its environment through the entry of the registry: the entry keeps a reference to the environment of level 1 of its type; when the reference is set, belongs to this cache and the environment is not evicted, level 1 is not searched. Otherwise the environment is found in level 1 or built and inserted as before, and the reference is set. An environment is built with `new CelEnvironmentBuilder()` and the variables of the shape (a dictionary: `AddVariable(name, type)`; an anonymous type: its `declare` delegate, which for a shape whose properties have classes of the application first adds the type source that the generator wrote for that shape, with only the descriptions that its properties reach, and then the variables); `SetDefaultCostLimit` is not used — the limit is the one of the call (step 5). A build error (4016 for a key that is not a name; never 4000, since names are distinct) is thrown, and the shape is not cached.
4. The program of (environment, text, `T`) from the table of the recent programs of the environment, from level 2, or compiled and inserted; a failed compilation is cached as its errors (see "The cache").
5. The bindings are the instance of the thread: the call takes it from a thread-static field (the field is set to null), fills it, evaluates and, in `finally`, clears it and puts it back. A call that finds the field empty — a function of the application that calls `CelExpression.Evaluate` during an evaluation on the same thread, such as the getter of a member of a class in a property, or a call after an exception that left it taken — makes a new instance, which goes into the field when its call ends. A dictionary is bound value by value through `SimpleValues` (no second type check: the shape came from the same values); an anonymous object through its `bind` delegate. The program is evaluated with the limit of the call, `CelExpression.DefaultCostLimit` or the `costLimit` argument. In the steady state a call allocates nothing beyond the frame and the result, except for a shape with a property that is a list or a dictionary of classes: its binding allocates the view of the collection for each call, and each read of an element allocates the pair of the description and the instance; a property that is a structure of the application is boxed when it is bound, and a list or a dictionary of scalars allocates its view.
6. Success gives the value; a compilation or evaluation error, `CelException.FromErrors`; `OperationCanceledException` passes.

The shape of a dictionary is computed from its values on every call: it is the key, so it has to be. The list of pairs is kept in a pooled buffer and compared with the keys of level 1 without allocating a key when the environment is found; a new key is allocated only on insertion.

## The registry

`AnonymousRegistry` holds a dictionary `Type → Entry` that readers take without a lock and that is never changed once published (`Entry`: the `declare` and `bind` delegates, with `bind` stored as `Action<object, CelBindings>` that casts to `TData`). `Register<TData>` replaces the dictionary under a lock with a copy that has one more entry, unless the type is there: the first registration wins; a registration comes only from a module initializer, so the copy costs once for each type at the start of the process. A `FrozenDictionary` is not used: it would be built again at each registration and would make `browser-wasm` larger. An entry also keeps the reference to the current environment of its type (see "The cache"). The registry has no limit: its size is the number of anonymous types at call sites of the application assemblies, which the build of the application fixes, and not the data at run time.

The name of an unregistered anonymous type in the error is `Type.FullName`, as the compiler gave it (``<>f__AnonymousType0`2[…]``), and the hint of 4008 tells the application to pass the anonymous object to `CelExpression.Evaluate` directly or to pass a dictionary. No member of the type is read to name it.

## The cache

Two levels, both bounded, both with the clock algorithm of `CelCompilationCache` at insertion (a reference bit per slot, a hand that clears bits and evicts the first slot whose bit is clear):

| Level | Key | Capacity | Value |
| :- | :- | :- | :- |
| 1 | the shape | 64 environments | the hidden environment and the slot range of its programs |
| 2 | (environment, text by ordinal, `T`) | 1 024 programs and 100 000 UTF-16 code units of text | the `CelCompileResult<T>` as `object` |

Evicting an environment evicts its programs, so no program outlives its environment and at most 64 hidden environments are alive. The environment of an anonymous type is built once while its shape is in level 1; after an eviction (more than 64 shapes in turn) it is built again from the registry, which keeps the delegates and not the environment. A text longer than 100 000 code units is compiled and not kept. The two levels are `ConcurrentDictionary` maps, as in `CelCompilationCache`: reads take no lock (level 1 finds the environment of a dictionary through an alternate lookup by the pooled list of pairs, without a key); an insertion takes one lock, re-checks, evicts and adds. Two threads that miss the same key may both compile; the second insertion keeps the first entry. No thread, timer or finalizer is used.

Each environment of level 1 has a table of its recent programs: 8 places, the place chosen by `RuntimeHelpers.GetHashCode` of the text. A place holds an entry of level 2. A hit is the same string instance of the text and the same `T`: no Marvin hash and no comparison of strings, since the literal at a call site is one interned string. A miss looks level 2 up by the value of the text as before and then writes the place. A place is one reference written at once, so a reader sees the old entry or the new one, and checks the key against the fields of the entry it read. A text equal to a cached one but in another string instance still finds the same program. A hit of a table or of the reference of the registry sets the mark of the clock of the entry when it is clear, so an entry that is used only through a fast path is not taken for an unused one.

An entry of level 2 and an environment each have a flag "evicted". Evicting under the lock of the cache sets the flag first and then clears the place of the table or the reference of the registry entry. A reader that finds an entry with the flag set treats it as a miss. A writer stores the place or the reference with `Interlocked.Exchange` (a full barrier), reads the flag, and when it is set removes what it stored with `Interlocked.CompareExchange(place, null, entry)`. Either the writer stored before the eviction cleared the place, and the eviction clears it, or after, and then the flag is already set and the writer removes the entry itself. So an evicted entry is never handed out by a fast path and is never kept beyond the moment between the store and the second read of the flag; the numbers of `docs/limits.md` hold. The miss of a fast path takes no lock. The reference of a registry entry names an environment together with its cache and counts only for that cache: the cache of the process is the only one in an application, and the tests that make caches of their own share the registry.

The cache is a static field of `SimpleEntryCache`; nothing is public. Its calibration fills both levels to capacity — 64 shapes of 16 variables and 1 024 programs, whichever limit of level 2 comes first — and measures the live heap before and after — the size of the heap less its fragmentation that `GC.GetGCMemoryInfo` reports after a full compacting collection — in a test collection that does not run in parallel with others. The calibration of version 2.0 read `GC.GetTotalMemory(true)`, as the calibration of the compilation cache did; the test does not, since on the garbage collector with segments, which `net10.0` has on macOS, it reported 8.1 to 8.2 MiB for a cache that the live heap measures at 3.6 MiB. The measurement of version 2.0 was 3.70 MiB against the limit of 8 MiB of `docs/limits.md`, so the capacities stay. A second calibration fills the 64 environments with shapes that have classes: 16 variables, four of them classes of 8 members and one a list of a class, each environment built with a type source of the descriptions that the shape reaches and the descriptions shared by all shapes, and 16 programs on each; it prints its number to the output of the test, and the target is the same 8 MiB. The number is read from the run of the test, and if it is above the target the number of environments is made smaller.

## The type rules

`SimpleValues` is the only code that turns a value of the simple entry into a CEL value. It is one method with a `switch` over `is` patterns in the order of the list; the rows of the lists and the dictionaries are `ConversionRules.FromRuntimeValue`, the same function that the indexer of `CelBindings` uses ([facade-2.0](facade-2.0.md)), so the two have one rule and not two copies. A list of `object` passes only for `IList<object>` and `object[]` of exactly that type; an element of such a list is read later through the `object` row, so an object of the application there is `TypeNotAccessible` (3012) at the read in the simple entry, where no type source exists. No reflection, `MakeGenericType` or `Activator` (`ARCH007`).

## Classes of the application

A property of an anonymous type whose static type is a class, a structure or an interface of the application, or a list or a dictionary with string keys of such types, is an object variable (a `list(C)` or a `map(string, C)` for a collection). Its description is written by the generator of call sites ([generator-call-site](generator-call-site.md)) with the model and the output of the type context, so the evaluation reads the object as it reads an object of a context: by reference, lazily, without a copy. A single class or structure is bound by `CelBindings.Add<T>`. A collection of classes or structures is not: `Add<T>` has a closed list of collections that cannot name a dictionary of classes or a list of structures without building a generic type at run time, which Native AOT does not allow. The generator writes the declaration and the binding as closed generic code. A class passed as the data itself, an object in a dictionary and an object in a place of `object` are not described and give the errors of `docs/type-mapping.md` as before.

## Tests

The examples (`Examples/Facade/SimpleEntryTests.cs`, `SimpleEntryFastPathTests.cs`) cover the calls through a dictionary, through a registration made in the test, the errors and the limit, the same text in another string instance, a call after the eviction of its environment and of its program, a call after a failed call and a call from inside an evaluation. The developer tests take the rest:

- the capacities and the eviction of both levels, the fast paths through the internal members (a place of the table and a reference of the registry that a test plants are read before the levels, the same text in another instance finds the program by its value, an evicted entry is a miss, a hit marks the entry for the clock);
- the race of an eviction and the store of a place or of a reference, in both orders, made one after the other (the writer after the eviction takes its entry back, the writer before it is cleared by the eviction), and a stress test of 64 threads over more than 64 shapes and more than 1 024 programs, on one instance of the text and on copies of it, that checks the results, the capacities and that no evicted entry is reachable by a fast path;
- the registry read while modules register types;
- the bindings of the thread: the field is empty during a call and holds cleared bindings after it and after an exception, and a call inside a call has an instance of its own;
- the allocation of a call in the steady state: 0 bytes beyond the result for scalars, a string and a class, and the bytes of the forms with a list, a dictionary, a list of classes and a structure written to the output without a threshold;
- 64 threads on shapes with classes, `SimpleValues` row by row on the values the examples do not use, the reserve test of the built-in limit (100 times the cost of each scenario of the benchmark set) and the two memory calibrations.
