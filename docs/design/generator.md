# Source generator: the pipeline, the names and the diagnostics

`src/Great.Parts.Cel.Generator` turns a type context — a `partial` class derived from `CelTypeContext` with `[CelObject(typeof(T))]` attributes — into the descriptions of the .NET types it lists and of the types their members reach. This page covers what the generator reads, how it decides, what it reports and how it is built and tested; the text it writes is on [generator-output](generator-output.md). The public types that the application sees — the attributes, `CelTypeContext`, `CelNamingPolicy` — are described in [objects](objects.md) and in their XML documentation; the mapping of .NET values to CEL values is in `docs/type-mapping.md`: the table "Input: a .NET type to a CEL type" (the *input rows* below) and the section "Objects and collections" (the *collection rows*). That page has two sections that these pages refer to by their titles: "Names of fields" (the rules of "Names" below) and "Presence and null" (the rules of "Presence" and of the reading of `null` on [generator-output](generator-output.md)).

`CelTypeContextGenerator` is a `public sealed class`: the generator tests create it directly. The assembly is not part of the public API of the package, so no `InternalsVisibleTo` is added.

The generator is not part of the core and is not hot code: its speed matters in the editor of the application and is kept by the rules of "Pipeline", not by tuning. The code of `Emit/` is written so that the *created* code is fast ([generator-output](generator-output.md)). The assembly has one namespace, `Great.Parts.Cel.Generator`; the directories only group files, and `eng/layers.txt` does not change. The project keeps its present settings: `netstandard2.0`, `LangVersion` 14, `EnforceExtendedAnalyzerRules`, `Microsoft.CodeAnalysis.CSharp` 5.0.0 and `Microsoft.CodeAnalysis.Analyzers` 3.11.0 as build-time references. No other package is referenced: not `Great.Parts.Cel` (the generator recognizes every type of the library and of System.Text.Json by its full name) and not a package for JSON or for protobuf. The code uses no file, environment, time or random API (RS1035–RS1037), and writes line ends as `"\n"` only, never `Environment.NewLine`, so the text does not depend on the machine.

## The attributes

The attributes are markers that the generator reads from the symbols; the library never reads an instance. Their bodies are:

- `CelObjectAttribute(Type type)` stores `type` and throws `ArgumentNullException` for `null`; `Type`, `Name` and `IgnoreMembers` are plain properties, `Name` and `IgnoreMembers` `null` by default.
- `CelTypeContextOptionsAttribute()` sets `NamingPolicy` to `CamelCase` and `IgnoreJsonAttributes` to `false`.
- `CelIgnoreAttribute()` does nothing. `CelNameAttribute(string name)` stores `name`, `ArgumentNullException` for `null`; the name is checked by the generator (`GPCEL005`), not at run time.
- The XML documentation of `CelObjectAttribute.Name` and of the table of `docs/type-mapping.md` give the default name of a closed generic type as in "Names of types" below.

## Pipeline

`Initialize` registers two things.

1. **Contexts.** `context.SyntaxProvider.ForAttributeWithMetadataName("Great.Parts.Cel.Values.CelObjectAttribute", predicate, transform)` with `predicate` accepting a `ClassDeclarationSyntax` and `transform` reading everything about one context (below) into a `ContextReadResult`: a `ContextModel` or nothing, and an array of `DiagnosticModel`. The step is named for tracking: `.WithTrackingName("ContextRead")`. The two *facts of the compilation* are read inside the transform, not by a step of their own: the effective language version (`LanguageVersionFacts.MapSpecifiedToEffectiveVersion` of the parse options of the syntax tree of the context class, `default` and `latest` resolved) and whether `System.Numerics.Decimal128` exists, which is `GetTypeByMetadataName("System.Numerics.Decimal128")` of the compilation of the semantic model finding a public type. A step for them would save nothing: the transform runs again for a context whenever the compilation changes, since it reads the symbols of other files, and the two facts are one option and one lookup; what the model holds is equal when they are, so the steps after `ContextRead` stay cached.
2. **Two outputs from one step.** The result is split: `Select(r => r.Model)` named `"ContextModel"` feeds `RegisterSourceOutput`, which writes one file; `Select(r => r.Diagnostics)` named `"Diagnostics"` feeds a second `RegisterSourceOutput` that only reports, combined with `context.CompilationProvider` so that it can find the syntax tree of each place (below, "Places and arguments"); the `Combine` comes after the step `"Diagnostics"`, so its state is that of the step. Separate outputs matter because the diagnostics carry places, which move when the application edits a file above the context, while the model must stay equal then, so that the file is not written again for a change of a line number.

The rules that keep the pipeline incremental, by the Roslyn cookbook for incremental generators:

- **Models are values.** Every type of `Model/` is a `record` (or `readonly record struct`) whose members are strings, numbers, enumerations, other models and `EquatableArray<T>`: a small `readonly struct` over an array that compares by length and by element and has a stable hash. There is no `ISymbol`, `ITypeSymbol`, `SyntaxNode`, `Compilation`, `SemanticModel`, `Location` or `ImmutableArray<T>` in a model, nor a delegate: they would keep the compilation alive and compare by reference. The places of diagnostics are `LocationInfo(string FilePath, TextSpan Span, LinePositionSpan LineSpan)`, rebuilt into a `Location` only when a diagnostic is reported, by the rule of "Places and arguments".
- **The transform does all the reading** and returns values; the emitter gets a model and nothing else, so it needs no compilation.
- **No work for what has no attribute.** The predicate is syntactic and cheap; nothing runs for a class without an attribute list.
- **Determinism.** Everything the model holds comes out in an order that does not depend on the order of files, of partial parts or of the attributes: types by CEL name and fields by CEL field name, both ordinal ([generator-output](generator-output.md), "Order"). A model built twice from the same source is equal, and so is the text.
- **One file per context.** `AddSource(hintName, text)`, with `hintName` the full metadata name of the context, nested types joined by `+`, followed by `.g.cs`, for example `Acme.Sales.OrderContext.g.cs` and `Acme.Sales.Outer+OrderContext.g.cs`; the full name is unique in an assembly, so no two contexts share a hint name.

Observable behavior, which the tests check with `trackIncrementalGeneratorSteps`: with nothing changed between two runs every tracked step is `Cached` or `Unchanged`; a change in a file that no context reads leaves every step after `ContextRead` `Cached` or `Unchanged`; a change of a type that a context lists or reaches makes `ContextModel` `Modified`; moving the context down a file by inserting lines above it makes `Diagnostics` `Modified` and `ContextModel` `Unchanged`.

## What the transform reads

For a context class, in this order, so that every diagnostic that applies is reported:

1. **The declaration.** A class that is not `partial`, is generic, is nested in a generic type, or does not derive from `Great.Parts.Cel.Values.CelTypeContext` (found by walking `BaseType` and comparing the full name) is `GPCEL006`, reported at the declaration, and nothing else is read. A containing type that is not `partial` is the compiler's CS0260 at the application, as the created file declares each containing type `partial`.
2. **The facts.** A language version below C# 12 is `GPCEL008`, reported at the declaration with `{1}` the version written as C# shows it (`11.0` as `11`, `latest` and `default` already resolved); no code is written for the context. The reading goes on: the other diagnostics of the context, of its roots and of its members, are reported as they would be for a newer language, so that one build shows every error at once.
3. **The options.** The attribute `Great.Parts.Cel.Values.CelTypeContextOptionsAttribute` on the same class, found by full name in `TargetSymbol.GetAttributes()`: `NamingPolicy` (the numeric value of `CelNamingPolicy`; an absent argument is `CamelCase`) and `IgnoreJsonAttributes` (absent is `false`).
4. **The roots.** Each `[CelObject]` in `ctx.Attributes`: the first constructor argument as a type; the named arguments `Name` and `IgnoreMembers` (a string array). A `typeof` of an error type (the type is unknown to the compiler) is skipped: the compiler reports it. A root is `GPCEL001`, at the argument, when the type is one that the context cannot describe ("Which types are read"); the reason is in `{1}`. A root that is an enumeration is allowed and describes the enumeration. Two roots naming the same type are one root; a second attribute for the same type with another `Name` is `GPCEL004` at its argument. A `Name` that is not a CEL qualified name is `GPCEL005` at the argument.
5. **The closure** ("Closure and the limit") over the members of every root, with the names, the excluded members and the reasons, into `TypeModel`s and `EnumModel`s.
6. **The checks of the whole:** two types with one CEL name are `GPCEL004` at the argument of the second root (for a type reached by members, at the argument of the root that reached it first in the order of the sorted names); the limit is `GPCEL009`. Types with one CEL name are ordered by their display name `{t}`, ordinal, and the greater is the second; the order of the attributes in the text and of the parts of the class never decides. A type listed twice with different `Name` values is the same case: the greater `Name`, ordinal, is the second, `{0}` and `{1}` are that type and `{3}` is the `Name` that stays.

Diagnostics that do not stop the code: `GPCEL001` of a root (the root is left out and the rest is written), `GPCEL002` and `GPCEL007` (the member is left out), `GPCEL003` (the second member is left out), `GPCEL004` (the second type is left out), `GPCEL005` (the root or the member is left out). The code is not written for `GPCEL006`, `GPCEL008` and `GPCEL009`: the class is not a context the file could complete, the language is too old for the file, or the closure is too large to describe. For the other codes the file is written with what remains. A context without a file makes the application's compiler report that `Default` does not exist wherever the application uses it; those errors follow the generator's error, which names the cause, and the build fails anyway, as each of the three is an `Error`.

## Which types are read

The classification is one function over a `ITypeSymbol`, with one result: the CEL type and the shape of the reading ([generator-output](generator-output.md), "Reading a member"), or a *reason*, a fixed English text. For a root the reason goes to `GPCEL001` `{1}`; for a member it goes to `GPCEL002` `{2}` and, by `GetExcludedFieldReason`, into the text of the type checking error 2007. The order of the tests:

1. Type parameters and open generic types; pointers and function pointers; `ref struct`; `dynamic` is `object`.
2. `Nullable<T>` is `T` with the nullable flag. An array of arrays or a multidimensional array: the element rule below applies to the element type, so `int[][]` is a list of lists and `int[,]` has the reason below.
3. The input rows of `docs/type-mapping.md` ("Input: a .NET type to a CEL type"), by the full name of the type, a type from another assembly with the same name included: the numbers, `bool`, `string`, `Guid`, `Half`, `nint`, `nuint`, `byte[]`, `ReadOnlyMemory<byte>`, `CelTimestamp`, `DateTimeOffset`, `DateTime`, `CelDuration`, `TimeSpan`, `Decimal128`, `System.Decimal`, `CelValue`, `object`, `CelList`, `CelMap`, enumerations, `JsonElement`.
4. The collection rows of `docs/type-mapping.md` ("Objects and collections"), by the interfaces of the type, in this priority; the first that matches decides: an array, or a type that implements `IReadOnlyList<T>`; a type that implements `IList<T>` only; a set (`IReadOnlySet<T>` or `ISet<T>`); a dictionary (`IReadOnlyDictionary<K,V>` or `IDictionary<K,V>`); a type that implements `IReadOnlyCollection<T>`. A type that implements the interface of one family for two different element types has the reason `implements {interface} for more than one element type`. A class or a structure that implements `IEnumerable<T>` and none of the interfaces of this list (`Google.Protobuf.ByteString`) is an object type read by its members: only the interfaces `IEnumerable<T>` and `IAsyncEnumerable<T>` and the types that implement only the non-generic `System.Collections.IEnumerable` are refused by the reasons below. `string` and `byte[]` are decided before, by row 3.
5. A type of `Google.Protobuf.WellKnownTypes` (decided before the message classes, since these types are messages too).
6. A protobuf message class ([generator-output](generator-output.md), "Messages of protobuf").
7. The types that no row covers and that are not objects: a class, a structure or an interface of the namespace `System` or its sub-namespaces, or defined in the assembly `Great.Parts.Cel` or `Great.Parts.Cel.Protobuf` (the name of the assembly of the symbol decides, not the namespace: a project of the application, or a test project of the library, may use a namespace that begins with `Great.Parts.Cel`, and its types are read). A type marked `[Obsolete]`, `[Experimental]`, `[RequiresUnreferencedCode]` or `[RequiresDynamicCode]`.
8. Any other class, `record class`, structure, `record struct` or interface is an *object type*; its closure comes in "Closure and the limit". The enumerations are described as enumeration types.

The reasons, as they are written. `{t}` is the display name of the type, `Namespace.Outer.Name`, without `global::` and without the assembly. It is written in C# form: the keyword for the special types (`int`, `char`, `string`, `object`), `int*` for a pointer, `int?` for `Nullable<T>`, the parameter names for an open generic type (`Acme.Box<T>`, the original definition of the unbound `typeof(Acme.Box<>)`), the type arguments of a closed generic type in the same form (`System.Collections.Generic.IEnumerable<int>`); no `?` for a reference type, no `global::`, no assembly:

| Case | Reason |
| :- | :- |
| `ref struct` | `ref structs cannot be stored in a CEL value` |
| open generic type, type parameter | `open generic types and type parameters cannot be described without reflection; list a closed type` |
| pointer, function pointer | `pointers are not data` |
| delegate | `delegates are not data` |
| `System.Type` | `System.Type is not data` |
| `Task`, `Task<T>`, `ValueTask`, `ValueTask<T>` | `tasks are not data` |
| `Stream` and the types derived from it | `streams are not data` |
| `IEnumerable<T>`, `IAsyncEnumerable<T>`, an iterator interface with no size | `{t} has no size and no index; use an array, a list or a collection with a size` |
| a non-generic collection (`IEnumerable`, `ArrayList`, `Hashtable`) | `non-generic collections have no element type; use a typed collection` |
| `char` | `char is a UTF-16 code unit, not a code point; use string` |
| `Int128`, `UInt128`, `BigInteger` | `CEL has no integers wider than 64 bits; use long or string` |
| `DateOnly`, `TimeOnly` | `{t} is not supported; use DateTimeOffset or string` |
| `JsonDocument` | `JsonDocument is released by the application; use JsonElement` |
| `JsonNode` and the other types of `System.Text.Json.Nodes` | `JsonNode is mutable; use JsonElement` |
| a multidimensional array | `multidimensional arrays are not supported; use an array of arrays or a list` |
| another type of `System` or its sub-namespaces, or of the assemblies `Great.Parts.Cel` and `Great.Parts.Cel.Protobuf` | `{t} has no CEL type; use a string or your own type` |
| a type of `Google.Protobuf.WellKnownTypes` | `well-known protobuf types are read only as fields of messages` |
| an interface of the protobuf message, `IMessage` or `IMessage<T>` itself | `list the message class, not the interface` |
| a type or a member marked with an attribute of the list | `{t} is marked [{attribute}]` for a type; `the member is marked [{attribute}]` for a member, `{attribute}` one of `Obsolete`, `Experimental`, `RequiresUnreferencedCode`, `RequiresDynamicCode`. A member is marked when the attribute stands on the property or the field or on its `get` accessor (`RequiresUnreferencedCode` and `RequiresDynamicCode` have no target property, so they stand on the accessor). |
| an element, a key or a value of a collection that has a reason | `the element type {t} cannot be read: {reason}`; `the key type …`; `the value type …`, with the reason of that type |
| a dictionary key that is not `string`, an integer, `bool`, an enumeration or `Guid` | `dictionary keys must be string, an integer, bool, an enumeration or Guid` |
| an element, a key or a value, at any depth, that is a set, a collection without an index (`Queue<T>`, `Stack<T>`, `LinkedList<T>`) or a structure that is a collection other than `ImmutableArray<T>` | `the element type {t} cannot be read: {t} is copied at each read of an element, which the cost does not charge; use a list, an array or a dictionary` (`the value type …` for a value); decided by the first test that finds the type under a collection, before the reasons below it |
| elements of a set that CEL does not order | `set elements must be numbers, bool, string, bytes, timestamp, duration or decimal, which CEL orders` |
| `Decimal128` or `System.Decimal` without `Decimal128` in the compilation | not a reason: `GPCEL007` below |
| a root that is a collection, a primitive or `Nullable<T>` | `{t} is not an object type; list the element type` for a collection, `{t} has its own CEL type` for a primitive, `list the underlying type` for `Nullable<T>` |
| a protobuf message class as a root | `protobuf messages are described by Great.Parts.Cel.Protobuf, not by a type context` |

A member that has a reason is excluded with `GPCEL002`, unless it is hidden. A hidden member — `[CelIgnore]`, a name of `IgnoreMembers` of the root of its type, or `[JsonIgnore]` with the condition `Always` — is not a field and has no warning: selecting it is `NoSuchField`.

The members of an object type are the public instance properties with a public `get` and the public instance fields, including the inherited ones, except indexers, static members, members whose type is a `ref struct` and members that an interface implements explicitly. When a derived type hides a member (`new`) or overrides it, the member of the most derived type is the only one. The members of an interface are those it declares and those of its base interfaces. A `required` or `init` property is read like another. `IgnoreMembers` of a root hides the members of that root type by their C# names; it does not hide members of the same name in other types that the closure reaches.

## Diagnostics

The nine diagnostics are `static readonly DiagnosticDescriptor` fields of one internal class in `Diagnostics/`, one field for each code `GPCEL001`–`GPCEL009`, and `docs/generator-diagnostics.md` repeats their text for the reader: the identifier, the severity (`Error` or `Warning`), the title (`title`) and the message (`messageFormat`) of a descriptor are those of the page, with no word changed, and `isEnabledByDefault` is `true`. The two shared values are constants of that class:

- **Category.** `Great.Parts.Cel.Generator`, for all nine.
- **Help link.** `HelpPage` is the one constant of the address, `https://github.com/great-parts/great-parts-cel/blob/main/docs/generator-diagnostics.md`, the address of the page in the repository until the documentation has a site; `helpLinkUri` of each descriptor is `HelpPage + "#" + id.ToLowerInvariant()`, for example `…/generator-diagnostics.md#gpcel002`. The page `docs/generator-diagnostics.md` has a section for each code whose heading is the code, so the anchor that GitHub makes of the heading is the code in lower case. `lychee` checks the address as for the XML documentation ([eng-checks-source](eng-checks-source.md)), through the remap of `lychee.toml`. The diagnostics test checks, for each descriptor, the category, the anchor and that the page has the heading.

`AnalyzerReleases.Unshipped.md` lists the nine codes with category, severity and the title (rule RS2008); a code is never removed or renumbered ([generator-output](generator-output.md), "What is contract").

**Places and arguments.** A diagnostic is reported at the place of the table, built from `LocationInfo`: the declaration of the context for `GPCEL006`, `GPCEL008` and `GPCEL009` (the identifier of the class); the argument of the attribute for `GPCEL001`, `GPCEL004` and for `GPCEL005` of a root; a member for `GPCEL002`, `GPCEL003`, `GPCEL005` of a member and `GPCEL007` when the declaration of the member is in a source file of the compilation, and otherwise — a type of a referenced assembly, a member without a declaration in source — the argument of the root attribute that reached the type first. Every diagnostic carries a place that exists, so none is reported with `Location.None`.

The place of an argument is the whole attribute argument as written (`AttributeArgumentSyntax`): `typeof(T)` for the first, `Name = "x"` or `IgnoreMembers = new[] { … }` for a named one, the name and the `=` included. The place of a member is its identifier (the first location of the member symbol), not the whole declaration; the place of the declaration of a context is the identifier of its class.

A place becomes a `Location` in the source of the compilation: the reporting step finds the syntax tree whose `FilePath` is the `FilePath` of the `LocationInfo` and builds `Location.Create(tree, span)`, so that the location has a `SourceTree`. A location made only of the path and the spans (`Location.Create(path, span, lineSpan)`) has no tree, and the compiler applies `#pragma warning disable` and the per-file severity of `.editorconfig` only to a diagnostic that has one; a warning such as `GPCEL002` must be suppressible at its member, and the tests read the tree. A path that no tree has — which the places of this page never give, as every place is in a source file of the compilation — falls back to the location made of the path and the spans.

The arguments are strings made by the pipeline, so a message of a model is the same text on every machine. A type is written as the display name `Namespace.Outer.Name` of "Which types are read" (`{t}`); a closed generic type with its arguments in C# form, `Acme.Page<Acme.Order>`; a member by its C# name. `{1}` of `GPCEL001` and `{2}` of `GPCEL002` are the *reason* of the table above, the English text without a final period; the same text goes to `GetExcludedFieldReason`. `GPCEL003`: the two C# names of the members, the type and the CEL field name. `GPCEL004`: the two types, the source name of the context and the CEL name. `GPCEL005`: the text and `identifier` or `qualified type name`. `GPCEL006` and `GPCEL008`: the source name of the context, and for `GPCEL008` the version of the language as C# shows it. The source name is the simple name of the class, without the namespace, the containing types and the type parameters (`Ctx` for `Ctx<T>`). `GPCEL007`: the member and its type. `GPCEL009`: the source name and the limit, the constant of "Closure and the limit".

## Names

**Names of types.** The root's `Name`, when it is set, else the default: the full .NET name `Namespace.Outer.Name` with the `+` of a nested type written as `.`; a type in the global namespace has no prefix. A closed generic type gets its definition name followed by `_` and the default names of its type arguments joined by `_`, each with its dots replaced by `_`: `Acme.Page<Acme.Order>` is `Acme.Page_Acme_Order`, `Acme.Pair<int, Acme.Tag>` is `Acme.Pair_int_Acme_Tag` (a primitive is written by its C# keyword). The name has to be a CEL qualified name, since `CelObjectType` checks it, and the generic form `Page<Order>` is not one; two types that get one default name are `GPCEL004`, and `Name` is the way out. A closed generic type is read as any type, and an expression can write its default name. The CEL name of an enumeration is its default name, never `Name`, except for a root enumeration. A type that has a default name which is not a CEL qualified name — a name with a character outside `[_a-zA-Z0-9]`, a segment that is a keyword (`true`, `false`, `null`, `in`) or a first segment that is a reserved word — is `GPCEL005` at the root's argument for the root, and a member of such a type is excluded with `GPCEL005` too.

**Names of fields.** For each readable member, the first rule that applies, as in the section "Names of fields" of `docs/type-mapping.md`:

1. `[CelIgnore]` hides the member; `[CelName("x")]` gives `x`. A name in `IgnoreMembers` hides the member of the root type.
2. Unless `IgnoreJsonAttributes`: `[JsonIgnore]` with the condition `Always` hides the member — no argument or `Condition` the constant 1 of `JsonIgnoreCondition`; any other condition does not hide it. `[JsonPropertyName("x")]` gives `x`. The attributes are found by the full names `System.Text.Json.Serialization.JsonIgnoreAttribute` and `JsonPropertyNameAttribute`.
3. The naming policy applied to the C# name of the member.

The result must be an identifier `[_a-zA-Z][_a-zA-Z0-9]*`; a keyword and a reserved word are allowed (an expression writes them in backquotes). A result that is not — the name from `[CelName]` or `[JsonPropertyName]` with a hyphen or a space, or a member whose name has letters outside ASCII and no attribute — is `GPCEL005` at the member and the member is excluded. Two readable members with one field name are `GPCEL003` at the second, in the order of the C# names, ordinal; the second is left out. A member that is excluded with a reason is named the same way, and that name is the argument of `GetExcludedFieldReason`; when two excluded members get one name, the first by the C# names answers.

**Policies.** `AsIs` is the C# name. `CamelCase` and `SnakeCaseLower` repeat `JsonNamingPolicy.CamelCase` and `JsonNamingPolicy.SnakeCaseLower` of System.Text.Json of .NET 10, written in the generator because it cannot reference System.Text.Json of its own runtime. `CamelCase`: a name whose first character is not upper case stays; otherwise the leading run of upper case characters is lowered, except that, from the second character on, the run stops before an upper case character that is followed by a lower case one (`URLPath` is `urlPath`, `XMLHttp` is `xmlHttp`, `ID` is `id`, `Id` is `id`). `SnakeCaseLower`: a separator `_` is inserted before an upper case character that follows a lower case letter or a digit, and before an upper case character that is followed by a lower case letter when the previous one is upper case; then the whole name is lowered (`TotalAmount` is `total_amount`, `HTTPServer` is `http_server`, `Order2Line` is `order2_line`). Characters are classified by `char.GetUnicodeCategory` and lowered with `char.ToLowerInvariant`. The generator tests compare both with `JsonNamingPolicy` over a corpus of names that includes acronyms, digits, underscores, a single letter, leading underscores and a name in the upper case entirely; where the generator and the policy of the test runtime differ, the test fails and the generator is changed, not the corpus.

## Closure and the limit

The closure starts at the roots. For each object type it takes the readable members and the types they reach: the type of a member, the element of an array or a collection, the key and the value of a dictionary, the underlying type of a `Nullable<T>`, at any depth. An object type reached is added once, by its type symbol; an enumeration reached becomes an enumeration type; protobuf message classes, `CelValue`, `object` and the other rows are leaves. A member is classified before its type is followed, so a type that only an excluded member reaches is not described. Types are visited with an explicit stack, not by recursion, so a deep graph cannot overflow the compiler's stack; cycles are cut by the set of the visited types.

The limit is 250 object types for a context, counting the roots; enumeration types do not count, since they are leaves and cannot widen the graph. At the 251st object type the walk stops and `GPCEL009` is reported at the declaration with `{1}` 250; no code is written. The cost of the walk is therefore bounded by the limit times the members of a type. The value is the result of the calibration below: the first value of the series, 500, did not meet the bound of time for a dense graph.

**Calibration.** The value is checked by the generator test `LimitCalibration`, an explicit xUnit test (`[Fact(Explicit = true)]`) that runs only when asked. The test holds the current limit `L` as a constant and asserts that `GPCEL009` appears exactly for the N above it. For each N in 100, 250, 500, 1000 and 2000 and for two shapes of the graph — a chain, where each of N types has ten members of mixed kinds and refers to the next type, and a dense graph, where each type refers to five others — it builds a compilation in memory, runs the generator through `CSharpGeneratorDriver` twice to warm up, and then ten times, each after the edit that an editor faces: one member of one type changes its type, so `ContextRead` runs whole and `ContextModel` is `Modified`. It runs in a process that is warm: the measurement of the series starts after a first series that is not counted. It measures for each run the wall time (`Stopwatch`) and `GC.GetAllocatedBytesForCurrentThread()`, and reports the median of the ten. An N above `L` stops the walk at the type `L + 1`, writes no code, and is reported as such; it measures the cost of the stop, not of a larger context. The rule that follows from the numbers:

- the limit stays `L` when at N = `L` both shapes have a median time of at most 250 ms and at most 100 MB allocated;
- when they do not, the limit becomes the largest value in the series below `L` that meets both, and the page `docs/generator-diagnostics.md`, the message of `GPCEL009` (`{1}` is the limit, the text does not change) change with it, with the page of the limits where it names the limit;
- a limit is never raised because a larger N also meets the bounds: the limit exists to stop a graph of entities that a context pulled in by accident, not to be the largest size that works; a larger limit is a change in a later minor release, on demand, by raising the constant of the generator and of the test and running the series again, so that N above the old limit is measured whole.

**Result.** The first calibration, with `L` = 500 (a warm process; the median of ten runs): at N = 500 the chain took 209 ms and 55 MB, the dense graph 470 ms and 69 MB; at N = 250 the chain took 107 ms and 28 MB, the dense graph 144 ms and 35 MB. The time of the dense graph at 500 is over the bound, so by the rule the limit is 250, the largest value of the series that both shapes meet. The dense graph is not a rare case that the rule may overlook: the graph of the entities of an ORM, which the limit exists to stop, is dense. The limit is also the safe side of a change that is not symmetrical: a limit that is raised later is a change in a minor release, and a limit that is lowered is a break. The report of a later run states its own numbers and the verdict of the rule; the measurement is not a gate of the regular run.

## Shared types of two contexts

Two contexts of one environment can reach one .NET type, for example `Acme.Address` through two entities of two contexts. Each context writes its own description of it, so the type index would hold two descriptions of one .NET type, and `Build` would report `DuplicateType`. The rule of [objects](objects.md) ("Types that two generated contexts share") makes them one declaration when their form is equal; it is the part of the generator contract that lives in `Declarations/DeclarationChecks.cs`, and the generated code does what makes it work: a description is a function of the type, of the options and of the compilation facts only, so two contexts with equal options produce equal forms, and contexts with different options — a naming policy, `Name` — produce different forms and the build reports `DuplicateType`, which is right: the same type would answer to two names.

**The description that loses is still used.** The context whose description is dropped keeps naming it: its created code pairs an element of a list of a class that is not sealed, or of an interface, with its own `Description` ([generator-output](generator-output.md), "Place rule inside collections"), and a list of such a context must fit `list(Animal)` whichever context wins, since the order of the two `AddTypes` calls changes nothing. The decision is that the index keeps the dropped description as an alias of the one that stays, and the generator needs nothing for it: `Description` stays the context's own instance, and no created code asks the index. The rule that makes a pair of an alias fit and describe as the one that stays is on [objects](objects.md) ("Types that two generated contexts share"). The alternative — a limit on what a context may share — was rejected: it would make a list read by a context work or fail by the name of the other context, which no diagnostic of the generator could show, since the generator sees one context only. The cost of the decision is one rule file of the core, `Values/ObjectRules.cs` (`Describe`, one function), so the generator is not free of the core: the rule is part of the core, with the models and the checks of one.

## Created code and the language

The created code needs C# 12; the generator uses collection expressions for the arrays it passes to the base constructor and `static` lambdas, nothing newer, so the output compiles for every language version that is not below 12. It does not use `field`, `extension` members, interceptors or any preview feature.

## The two sides of the generator

The generator has a reading side and a writing side, and they meet in one value. The reading side — the pipeline, the models and the diagnostics — is `src/Great.Parts.Cel.Generator/` except `Emit/`, together with the bodies of the four attributes, `docs/generator-diagnostics.md` and `AnalyzerReleases.Unshipped.md`. The writing side — the created code — is `src/Great.Parts.Cel.Generator/Emit/`, and what it writes follows the sections "Names of fields" and "Presence and null" of `docs/type-mapping.md`, the rows of the generator on that page and `docs/cost.md`. The value that the reading side gives to the writing side is `ContextModel` and what it holds, written once in `Model/`; its shape is on [generator-output](generator-output.md), "The model".

The decimal members split between the generator and the library. The generator side is the rows of the type mapping, the finding of `Decimal128`, `GPCEL007` and the snapshots; the library side is `CelType.Decimal`, the bodies of `FromDecimal`, the refusal of a decimal field without the set (2007, in the type checker) and 3012 in the place of `dyn`. Neither side depends on the other ([generator-output](generator-output.md), "Reading a member").
