# eng/difftest

`eng/difftest` is the differential run against cel-go. It generates random cases, evaluates each with the library and with the oracle ([eng-oracle.md](eng-oracle.md)), shrinks every divergence to a subexpression that still diverges while its children agree, and reports divergences whose signature is not known yet. A change of the core is checked with it ([core.md](core.md)) in CI on every push to `main` ([Run on a push to main](#run-on-a-push-to-main)); the nightly run uses it with a longer budget.

## A run

1. Read `Profile/environment.json`; a manifest with `greatPartsCel` or `validators` is refused with exit code 2.
2. Library side: `new CelEnvironmentBuilder(CelStandardLibrary.V1)`, `CelEnvironmentJson.Apply` with the manifest, `UseTimeZones` with the database made from the zone data file of `Profile/` — every zone of the archive, the version `2026c` — and `Build` ([configuration.md](configuration.md#run-manifest-of-the-differential-run)); a build error, and a zone that `Create` refuses, is exit code 2, naming the zone.
3. Connect to `oracle:7070` within a minute and send the path of the same file; print the `log` lines unchanged. No connection, `failed` or a closed connection is exit code 2; on no connection the message names `docker compose -f eng/compose.yaml logs oracle` ([eng-oracle.md](eng-oracle.md#launcher)). After the handshake, a Go other than the `go` line of `eng/oracle/go.mod` is `ENG821`, and the run stops.
4. Run cases 0, 1, 2, … until the budget, counted from the handshake, is spent: `env.Compile<CelValue>(expr)` and `program.Evaluate(bindings)` on the library, the request `eval` on the oracle. A divergence is minimized and gets a signature. An answer to `eval` or `case` that does not come within 10 seconds is a failed oracle, exit code 2: a case of the profile takes the oracle milliseconds, and the run must not hang on a hung oracle. The steps of the oracle before the handshake have no such limit, since a cold module cache takes minutes; their `log` lines show where they are.
5. Write `pending.textproto` — the cases of new signatures, or its empty form without them — the findings and the journal line.

## Profile

The profile is what the generator produces: the standard library version 1, time and `matches` included, over the variables and the container of the manifest; in every third case — the cases 2, 5, 8, … — also the extension sets of the manifest ([Profile of the extension sets](#profile-of-the-extension-sets)). The other cases are those of the standard library alone, so the sets take a third of the run and the standard library the rest.

**The manifest** `Profile/environment.json` holds `name`, `description`, `container`, `extensions` and `variables`, in the format the oracle reads too ([configuration.md](configuration.md#run-manifest-of-the-differential-run)):

| Variable | Type record |
| :- | :- |
| `i1`, `i2`; `u1`; `d1`; `b1`, `b2`; `s1`; `y1` | `int`; `uint`; `double`; `bool`; `string`; `bytes` |
| `x1`, `x2` | `dyn` |
| `li`, `ls`, `lx` | `list<int>`, `list<string>`, `list<dyn>` |
| `ms`, `mx` | `map<string, int>`, `map<int, dyn>` |
| `wi` | `int_wrapper` |
| `gp.q`, `gp.test.r` | `int`, `string`, under the container `gp.test` |

Not in the manifest: `greatPartsCel` and `validators`, which the stand refuses; `functions`, which would need the same implementations in Go and in the library; variables of time, since a time value would travel to the oracle as a message and the profile makes its time values inside the expression. Objects of the application, types described at run time and `JsonElement` cannot reach the oracle: the properties of [tests.md](tests.md) cover them.

| Node | Forms |
| :- | :- |
| `int` literal | decimal or hexadecimal; a negative value as `-` and its magnitude, including `-9223372036854775808` |
| `uint` literal | decimal or hexadecimal with `u` or `U` |
| `double` literal | the shortest decimal that reads back to the same finite value, with or without an exponent, also with a leading `.`; a negative value as `-` and its magnitude |
| `string` literal | single, double and triple quotes; the raw prefix `r` or `R`; the escapes `` \a \b \f \n \r \t \v \\ \' \" \` \? ``, `\x`, octal, and `\u` and `\U` for Unicode scalar values; any Unicode scalar value. A carriage return (U+000D) is printed only as an escape, so a literal that holds one is never raw: cel-go turns CR and CRLF in the source of a literal into LF, the library keeps the text |
| `bytes` literal | the prefix `b` or `B` on the string forms; `\x` and octal escapes give single bytes; no `\u` and `\U` |
| `bool`, `null_type` literals | `true`, `false`, `null` |
| identifier | a variable of the manifest; a type identifier `bool`, `bytes`, `double`, `int`, `uint`, `string`, `null_type`, `type`, `list`, `map`, `google.protobuf.Timestamp`, `google.protobuf.Duration`; the iteration variable `v` or `w` inside its macro |
| qualified name | `gp.q` as `q`, `gp.q` or `.gp.q`; `gp.test.r` as `r`, `test.r`, `gp.test.r` or `.gp.test.r` — resolved through the container |
| list literal | `[e, …]` with 0–3 elements, sometimes a trailing comma, also `[,]` |
| map literal | `{k: v, …}` with 0–3 entries, sometimes a trailing comma, also `{,}` |
| selection, presence | `e.f` and `has(e.f)` on an operand of type `map` or `dyn`; `f` is `a`, `b` or `f`, which map literals also take as string keys |
| call | `!_`, `-_`, `_&&_`, `_\|\|_` (chains of 2–4 operands), `_?_:_`, `_==_`, `_!=_`, `_<_`, `_<=_`, `_>_`, `_>=_`, `_+_`, `_-_`, `_*_`, `_/_`, `_%_`, `_[_]`, `@in`, `size` global and on a receiver, `contains`, `startsWith`, `endsWith`, `type`, `dyn`, `int`, `uint`, `double`, `string`, `bytes`, `bool` |
| macro | `all`, `exists`, `exists_one` on an operand of type `list`, `map` or `dyn`; `map` (2 and 3 arguments) and `filter` on a range of fixed order: a list literal, also in `dyn()`, a typed list variable `li`, `ls` or `lx`, or a map literal of 0–1 entries, which is also in `dyn()` when empty (cel-go iterates a map in no fixed order); the iteration variable has a static type that the generator knows and that is not `type`, else the range is in `dyn()`, and a macro whose range has no room for `dyn()` is not built: cel-go plans a variable of the static type `type` as a type name (`[int].map(v, v)`: `reference to undefined type: v`), and the variable over an empty literal or another range of unknown element type has a free type variable that the body binds to `type` (`{}.filter(v, v == int)`: the same error); at most two macros nested |
| time call | `timestamp(e)` with `e` of type `string` or `int`, `duration(e)` with `e` of type `string`, `timestamp(timestamp)`, `duration(duration)`; `int` and `string` of a timestamp and of a duration; `_+_`, `_-_`, `_<_`, `_<=_`, `_>_`, `_>=_`, `_==_`, `_!=_` over timestamps and durations as the overloads of the standard library allow; the ten receivers of a timestamp, each without a zone argument and with one, and the four receivers of a duration |
| parentheses | where precedence needs them, and around any node at random |

The generator builds an expression for a target type — any type of the profile, `dyn` included — so every expression type checks; a `dyn` operand may stand wherever a function takes one. The profile has every overload of the standard library, so both sides choose among the same overloads. A string argument of `int`, `uint`, `double` or `bool` is, half the time, a number or a `bool` in the text forms of the standard library page, with signs, `_`, hexadecimal, `inf`, `nan` and spaces; one of `timestamp` or `duration` is, half the time, a time in the forms below.

**Time.** `timestamp` and `duration` are types of the profile, so every function above can take a time operand and an expression of either type can be the root. No variable holds time: the values are made in the expression, by the two constructors from a string and from an `int`, so the manifest and the bindings carry no message of time, and a `dyn` variable holds none.

- **Strings of timestamp.** `YYYY-MM-DDThh:mm:ss`, a fraction of 0 to 12 digits, and `Z` or an offset, each field drawn from its boundaries: the year `0000`, `0001`, `1900`, `2000`, `2023`, `2024`, `9999`; the month `00`, `01`, `02`, `12`, `13`; the day `00`, `01`, `28`, `29`, `30`, `31`, `32`; the hour `00`, `23`, `24`; the minute and the second `00`, `59`, `60`; the offset `Z`, `+00:00`, `-00:00`, `+23:59`, `-23:59`, `+24:00`, `+03:60`. A string is also mutated: a lower case `t` or `z`, a space for `T`, no zone, a `.` with no digit, an extra character, a missing sign. The `int` of `timestamp(int)` is 0, ±1, −62 135 596 800, 253 402 300 799 and the numbers next to them, `long.MinValue`, `long.MaxValue`, or a random 40-bit number.
- **Strings of duration.** An optional sign and one to three terms of a number and a unit, or the bare `0`, `+0`, `-0`; the number is `d`, `d.`, `.d` or `d.d` with up to 20 digits, among them `9223372036854775807`, `9223372036854775808`, `2562047`, `2562048`; the unit is `ns`, `us`, `µs` (U+00B5), `μs` (U+03BC), `ms`, `s`, `m`, `h`, or a wrong one — `H`, `d`, `x`, none — and a term repeats a unit now and then.
- **Zone arguments** of the receivers: a zone name of the data file; `UTC`; a fixed offset `+05:30`, `-03:00`, `00:00`; a form outside the grammar `+1:5`, `+001:30`, `+24:00`, `+03:60`, `:`; `""` and `Local`; a name of the file with the case changed; a name no file has, `Mars/Base`. The zone is a literal, or, one case in ten, the variable `s1` bound to such a name.
- **Limits.** A string of time has up to 40 code points; the other limits of the profile are unchanged.

The 13 records of time of the registry of known differences need no change of the profile: the expression of each is a call that the profile builds, so a case with it has a known signature and is not new.

Map keys are literals of `int`, `uint`, `bool` and `string`, pairwise unequal by CEL equality: repeated keys and keys of other types are known differences, covered by registry records. A presence test or a selection on a value that is not a map is an error on both sides, since the oracle has `EnableErrorOnBadPresenceTest` as the cel-go conformance runner does.

A variable is bound to a value of its type, a `dyn` one to a scalar, `null`, a list of 0–3 scalars or a map of 0–3 entries with keys as in literals; one in ten stays unbound. A typed list gets 0–3 elements of its element type, `lx` scalars; `ms` gets 0–3 of the keys `a`, `b`, `f`, so selections and `has()` find them; `mx` integer keys and scalar values; `wi` an `int` or `null`. The typed variables are operands of the forms whose parameter types they fit — indexes, `size`, `in`, `+` on lists, macros, selections on `ms` — as `dyn` variables are. Numbers favour boundaries: 0, ±1, the limits of `int` and `uint`, powers of two; a bound `double` is also NaN, ±infinity or -0.0, and travels to the oracle, also inside a list or a map, as its shortest text, read back bit for bit. Limits: depth 6, 40 nodes, 8 code points per string, 8 bytes per `bytes` value; no cost limit and no token. The pattern of a call of `matches` is the one string that may be longer, up to its 20 atoms (the section "Profile: `matches` and `matches_string`" below).

**Extension.** The extension sets have their own section below. A later part of the library that brings functions, kinds of nodes, variable types or sets adds their rows there and to `Profile/`, and their sets to the manifest. A `dyn` operand is restricted for a function while the oracle has an overload of it that the profile lacks and a value of the profile reaches. In the end the profile covers the whole standard library and the extension sets except `decimal`, which cel-go lacks, and the internal `block` set.

## Profile: `matches` and `matches_string`

The profile gains the two overloads of `matches`, `(string, string) -> bool`, in the global form `matches(subject, pattern)` and in the form from a receiver `subject.matches(pattern)` — `ProfileTables` has the rows `matches` and `matches_string`, and the manifest and the oracle stay as they are, the oracle's environment already turning on `ValidateRegexLiterals()` ([eng-oracle](eng-oracle.md)). The oracle has these two overloads and no other of `matches`, so a `dyn` operand may stand in either place. A call is one of the forms that a target type `bool` takes, with the weight of any other function; it also stands as the predicate of `all`, `exists`, `exists_one` and `filter`, over a range of strings, with the iteration variable as the subject.

**The same pattern on both sides.** Both sides read the same text of the expression, so the pattern reaches them as the same string value after the escapes of CEL. The printer writes the text of a pattern as a raw literal two times in three when it can — when no code point of it is one that raw quotes cannot hold: a carriage return, the delimiting quote, a line feed outside triple quotes — and otherwise, and the third time, with the escapes `\\`, `\'`, `\n` and `\U…` of its string forms. No other channel exists: the profile has no function of the library that makes a pattern outside the text.

**The pattern.** Drawn from the grammar of RE2 as `syntax.Perl` reads it, to depth 4 and at most 20 atoms, so that the size of the program stays below 6 000 and the limits are not reached by chance:

- atoms: the letters `a`, `b`, `c`, a digit, `_`, a space, `é`, `ſ`, `K` (U+212A), `ß`, `😀`, `.`, an escaped metacharacter, `\d \D \s \S \w \W`, `\pL`, `\pN`, `\PL`, `\p{Greek}`, `\p{^Lu}`, `\p{Any}`, a class `[a-c]`, `[^ab]`, `[[:alpha:]]`, `[\d_]`, `[\pL_]`, `[é-ſ]`;
- anchors `^ $ \A \z \b \B`; groups `(…)`, `(?:…)`, `(?P<n>…)`; flag groups `(?i)`, `(?s)`, `(?m)`, `(?i:…)`, `(?i-s:…)`;
- repetitions `* + ?`, their lazy forms, `{n}`, `{n,}`, `{n,m}` with counts of 5 at most, and now and then a count up to 1 000 on one atom that is not nested in another count;
- alternatives `a|b`, with an empty alternative sometimes.

One pattern in twelve is refused, by one fault drawn from: a construct of the list NOT SUPPORTED (`(?=`, `(?!`, `(?<=`, `(?>`, `x*+`, `\1` (written `\1(?:)`, so that a digit after it cannot make it an octal escape), `\Z`, `\G`, `\K`, `\X`, `(?R)`, `(*FAIL)`), `\C`, `a**`, a count over 1 000, a product of nested counts over 1 000, an unclosed `(` or `[`, a lone `)`, an unknown `\p` name, a bad range. Patterns over the size limit and lone surrogates are not generated: the first is in the registry and the limit of the size is a decision of the library, the second cannot travel to the oracle, whose channel is UTF-8, and cannot be written in a literal of CEL.

**Constant or not.** 60 of 100 patterns are a string literal, which is prepared at compilation on our side; 40 are not, in one of the forms `dyn('…')`, `'…' + '…'` cut at a random place, `string('…')`, `true ? '…' : '…'`, or the variable `s1`, which that case binds to the text of the pattern.

**The subject.** A literal, a variable or any expression of type `string` of the profile, with the strings of the profile — at most 8 code points — drawn from the letters `a`, `b`, `c` of the pattern atoms in both cases, `k` and `K`, a digit, `_`, a space, the line feed, the characters `é`, `ſ`, `K` (U+212A), `İ`, `ß`, `ẞ`, `😀`, `(`, `\` and `^`: the metacharacters are in subjects too, since a subject is a pattern for the oracle in one form (below). `s1` is bound to a subject, or to the text of a pattern.

**The classes of the outcome.** A pattern that is refused, or outside RE2 or beyond a limit, gives an error in every case; the stage of the error is what two sides can differ in:

| Form | Library | cel-go | Verdict |
| :- | :- | :- | :- |
| receiver form, literal pattern | compile error | compile error (its validator reads the first argument, which is the pattern) | agree |
| global form, literal pattern | compile error | evaluation error (the validator reads the subject) | `matches(string, string) stage-mismatch`, known |
| global form, literal subject that is not a valid pattern, pattern valid | a value, or an error of evaluation | compile error | `matches(string, string) we-value` or `stage-mismatch`, known |
| pattern not a literal | evaluation error | evaluation error | agree |
| the literal is in a branch that is not evaluated | compile error | none, or a compile error in the receiver form | the descent goes to the call and finds the first two rows |

The known signatures are `matches(string, string) stage-mismatch` and `we-value`, and the forms of the same two causes with another type of argument, which minimization keeps: `matches(double, string)` and `matches(error, string)` for a constant pattern that RE2 refuses, `matches(string, error)` for a literal subject that is not a pattern. They are records of the registry of the class `cel-go-bug` — a validator that checks the wrong argument is a defect of cel-go — and the profile does not avoid them: it does not keep a literal subject free of metacharacters or the pattern out of a global call. Hiding the forms would leave the global call with a literal pattern, and a literal subject with a metacharacter, uncovered by the run. A global call whose literal subject is not a valid pattern is replaced at the root by a known signature and hides what else is in that expression; that is the price, and the run still compares every other form, every call with a variable subject and every call from a receiver.

**What the profile does not do:** a cost limit or a token; a pattern over the size limit; a lone surrogate; patterns of more than 20 atoms; the time of a match. The limits of the size, the cache and the engine's linearity are in the examples and in the tests of [tests](tests.md).

## Outcomes and signatures

Each side gives a compile error (parse, check; in cel-go also creating the program), an evaluation error or a value. An exception from the library counts as an error of the step it escaped from, and the message names its type; `Compile` parses and checks in one call and does not tell which of the two threw, so an exception from it is a compile error of the stage `check`. Values are equal when their `cel.expr.Value` messages have the same kind and value: lists element by element, maps as sets of entries, doubles by `==` or both NaN, a time value — an `Any` of `google.protobuf.Timestamp` or `google.protobuf.Duration` — by the type and the seconds and the nanoseconds.

| Library | cel-go | Kind | Severity |
| :- | :- | :- | :- |
| value | another value | `value-mismatch` | S1 |
| value | error | `we-value` | S1 |
| error | value | `we-error` | S2 |
| compile error | evaluation error, or the reverse | `stage-mismatch` | S2 |

Two errors of one class, or equal values, agree; error messages are not compared. The signature is `<node>(<types>) <kind>` of the root of the minimized case:

| Root | `<node>` | `<types>` |
| :- | :- | :- |
| call, `_[_]`, `_?_:_` included | the profile overload whose parameter types fit the argument types, a type parameter and `dyn` fitting any type but `error` at each place alone (`equals(int, string)`, `json_encode_dyn(duration)`); the function name when none fits | the types of the argument values, the receiver first |
| selection; presence test | `select`; `has` | the type of the operand |
| macro | `comprehension` | the type of the range |
| list literal | `list` | the types of the elements |
| map literal | `map` | key and value types, entry by entry: `map(bool, int, bool, int)` |
| other literal | `literal` | its type |
| identifier | `ident` | the type of its value |
| either side fails to parse | `parse` | none |

Types are the CEL type names that `type()` gives, without parameters: `int`, `uint`, `double`, `bool`, `string`, `bytes`, `null_type`, `list`, `map`, `type`, and `timestamp` and `duration`, the short names of the standard library page that the registry uses too; an argument that is an error on both sides is `error`. A node without types keeps its parentheses: `parse() we-error`, `list() value-mismatch`. An overload that differs from another only in the element type of a list parameter (`sort`, `math.greatest` and `math.least` of a list) is named by the first of them; the case text names the divergence exactly. A call of `math.greatest` or `math.least` with three or more arguments, which the macro turns into a call with a list, is named by the function, `math.greatest(int, int, int)`.

**Minimization.** A deterministic descent: while a child of the root still diverges with the same bindings, the first such child becomes the case. The children of a call are its arguments, of a list literal its elements, of a map literal the key and the value of each entry, in the order of the source; of a selection and a presence test the operand; of a macro the range only, since its other arguments are taken as instances below. When no child of the root diverges, the descent looks under each child on which both sides give an error, in the order of the source: two errors agree whatever their causes, so such a child can hide the node that diverges. In `{'k': x2 in mx}[''] || true` with a `bytes` value of `x2`, cel-go fails in `x2 in mx` and the library at the index, so the index agrees, and the root diverges only because the failure of cel-go is not absorbed by `||`. Under such a node the first child that diverges becomes the case, as a child of the root does; when none does, the descent looks in the same way under those of its children on which both sides give an error, depth first, before the next child of the root. The children are those above, so under a macro only its range is searched. A node found so diverges on its own, so its divergence is one to report in any case, known or not. When nothing diverges by these rules and the root is a macro, its range agrees and the descent goes into the bodies. The instances of the bodies are taken for each argument after the iteration variable (the predicate, the filter and the transform of `map`), in the order of the source. An argument that does not read the variable has one instance, the argument itself, whatever the range holds — elements, none, or an error: it does not depend on an element, and a divergence that shows only in it is one of a node that runs for no element, or of a check made when the expression is compiled, such as the constant pattern of `matches` (cel-go fails at the evaluation of the call, or does not evaluate it at all, where the library fails at compilation). An argument that reads the variable has an instance for each element of the range in its order, the key for a map: the body with each free read of the variable replaced by a node that stands for the element and fits wherever the variable does. For a list or map literal, or such a literal in `dyn()`, the node is the element in parentheses, or `dyn(element)` when the range is in `dyn()`, so that the static types stay. In a literal that is not in `dyn()`, each element that is a string literal has one more instance, `dyn(element)`, after those of all the elements: the validator of regular expression literals of cel-go reads a string literal that is the first argument of `matches` as a pattern, so with the element in parentheses in place of the variable cel-go may refuse the call when the expression is compiled, where the variable let the evaluation reach the pattern, and the two sides agree in a compile error; `dyn(element)` is not a literal for the validator. In `['?'].exists(v, matches(v, '('))` the instance `matches(('?'), '(')` agrees, as cel-go reads `?` as a pattern and refuses it, and `matches(dyn('?'), '(')` diverges by a known signature. For any other range — a variable, `dyn(x1)`, `lx + []`, the result of `map` or `filter` — the elements are those of its value, which both sides give alike since the range agrees, read from the outcome of the library: for a list, the index `range[i]` for each position `i` from 0, whose static type is the element type of the range and which needs no literal of the element (NaN, ±infinity and the values inside a list have none in the profile); for a map, `dyn(k)` for each key `k` in the order the library iterates the map, `k` a literal of the profile, since a key is an `int`, a `uint`, a `bool` or a `string`. A range whose value is not a list or a map — an error, an unbound variable, a scalar under `dyn` — gives an argument that reads the variable one instance for each zero literal of the profile, `''`, `0`, `0u`, `0.0`, `false`, `b''` and `dyn('')` in this order, whatever the type of the variable: the range may be any node, such as an index into a map literal or a conditional, and its type is not known to the descent. An instance of another type than the variable does not compile on either side, so the two agree and it is dropped. Like the instances of an empty range, which come next, it is a guess that is judged as any instance. In `ls.exists_one(v, matches(v, '('))` with `ls` unbound, the instance `matches('', '(')` diverges by a known signature although the pattern is never reached by an element. A range without elements — a literal without elements, in `dyn()` or not, a variable with an empty value, an empty map, or any other range whose value is an empty list or an empty map — has no element to put in place of the variable, so an argument that reads the variable has one instance for each zero literal of the profile that fits the static type of the variable: `''` for `string`, `0` for `int`, `0u` for `uint`, `0.0` for `double`, `false` for `bool`, `b''` for `bytes`, `dyn('')` for `dyn`. This is a guess, and it is judged like any instance: it replaces the macro only when it diverges by a known signature or by that of the macro, and is dropped otherwise. The static type of the variable is the element type of the list, or the key type of the map, that the range declares: `dyn` for a range in `dyn()`, the declared type of a variable of the manifest; a variable of the manifest of another type, or of an element type without a zero literal, has no instance. For a range whose type the descent does not know — a conditional, a sum, an iteration variable of a macro above, an empty literal that is not in `dyn()` — each zero literal of the profile is tried, in the order above, as for a range that is not a list or a map: the instance of another type than the variable does not compile on either side, so the two agree and it is dropped. In `(b1 ? ls : dyn([])).exists(v, matches(v, '(?<=a)b'))` with `b1` false the range is an empty list, cel-go gives `false` where the library refuses the constant pattern when the expression is compiled, and the instance `matches('', '(?<=a)b')` diverges by a known signature. In `ms.exists_one(v, matches(v, '(?<=a)b'))` with an empty `ms`, a map with `string` keys, the instance is `matches('', '(?<=a)b')`, which diverges by a known signature although no element of the range ever reaches the pattern. After the instances for the elements, or for the zero literals, an argument that reads the variable has one more instance for each of its closed nodes, in the order of the source: a maximal node that reads none of the iteration variables of the macros above it, those of the macros nested in the argument included. The node is evaluated by itself, once, with the bindings of the case and without any substitution, so a divergence that is in the node and not in what an element does to it is found as it is found outside the macro. In `dyn([]).filter(v, v.exists(w, matches('(?<=a)b', '')))` the argument reads `v` and the range is empty, and the closed node `matches('(?<=a)b', '')` reads neither `v` nor `w`. An instance that diverges is minimized itself, by the same descent, and replaces the macro only when its signature is the signature of the macro or a known one ([Known signatures and the corpus](#known-signatures-and-the-corpus)); an instance that agrees, that does not make the case smaller, or whose signature is unknown is dropped, so a divergence under a macro that nobody knows stays the signature of the macro, `comprehension(list) we-error`, and a known one is found under the macro as it is found outside it. A case is smaller than another when it has fewer macro nodes, or as many and a shorter text: an instance lacks the macro of its root, so over a range without a macro it is smaller even when its text is longer, as when `lx[0]` replaces `v` in several places; an instance that copies a range with a macro into more than one place may not be smaller and is then dropped. Minimization evaluates only the divergent case, its nodes and the instances of its macro bodies, with its bindings: it generates no other case and has no time limit, so the same seed and case number give the same minimized case and the same signature. Without macros the descent evaluates each node below the first root at most once — the children of a node are evaluated together, and the case moves only into a node whose children have not been evaluated yet — so a case of 40 nodes without macros takes at most 39 evaluations on each side; the instances under macros come on top, and every step makes the case smaller — a child, or a node under it, has no more macro nodes than its root and a shorter text, an accepted instance is smaller by the rule above — so the descent ends. A run ends the case it started within the budget together with its minimization. The arguments of the final root agree, so their types are defined. The whole tree is not reduced further.

`cel.bind`: the name stands for its value, which is the one instance of the body. A macro of two variables: a body that reads neither variable is itself an instance; otherwise only the closed nodes of the body are, since an element and its index or key are not replaced one by one; a divergence of a body that reads a variable then stays the macro with the signature `comprehension(…)`.

## Known signatures and the corpus

A signature is known when the column `Signature` of the registry of known differences `tests/Great.Parts.Cel.Conformance/Regression/known-differences.md` or of the corpus skip list `Regression/skips.md` has it. The run keeps the first case of each new signature.

These cases go to `tests/Great.Parts.Cel.Conformance/Regression/pending.textproto`, which every run without `--case` rewrites. The oracle writes them (request `case`) with the answer of cel-go as the expectation, named `pending/new/<seed>-<n>`. The file is part of the corpus, so `eng/test` fails with `ENG801` until each case is fixed or recorded. A compile error of cel-go goes into `eval_error`: a `SimpleTest` cannot expect a compile error. So a library that gives an error of evaluation passes such a case, and a case of a signature with a compile error of cel-go and an error of evaluation of the library, as `matches(string, error) stage-mismatch`, is not recorded in the skip list, since an entry for a passing case is `ENG802`: the registry has the signature and the corpus keeps the case, which the library passes.

The file is committed in its empty form, without cases, byte for byte as below, with LF line ends. A run without new signatures writes exactly this form, so the working copy stays clean. A run with `--numbers-only` does not touch the file.

```text
# Written by eng/difftest: the cases of new divergence signatures of the last run. Committed without cases.
name: "pending"
description: "New divergence signatures of the last run of eng/difftest"
```

With cases, the empty form is followed by one section: the line `section {`, the line `  name: "new"`, and for each case, in the order the run found it, the line `  test {`, the text of the `case` answer as it is, and the line `  }`; the line `}` ends the section and the file. The description of a case is its signature. The first case thus starts at line 6, and the place of its `ENG820` is the `test` token, column 3.

An entry of the corpus skip list moves its case from `pending.textproto` to a corpus file, since the next run rewrites `pending.textproto` without it. A registry record and its case enter with the change that implements the behavior of the record: the skip entry carries the class of the record as the verdict and the same signature, and the oracle checks the answer of cel-go again.

## Profile of the extension sets

The profile adds the extension sets of the part that brings them — `strings` 5, `math` 3, `lists` 4, `sets` 0, `encoders` 1, `bindings` 1, `two-var-comprehensions` 0 and `network` 1 — to the manifest and their functions and macros to the generator. `decimal` and the internal set `block` are not in the manifest.

**The cases.** The generator has two profiles. A case of the standard library profile is built from the forms above, as before. A case of the extension profile adds the forms of the sets to the forms of every target they give a value of — one form in about three is one of the sets — so a node of a set stands among nodes of the standard library: its arguments are any node of the target type, and its result stands wherever its type is wanted. The rows of the sets are in `ProfileTables` with the overload identifiers of cel-go; each call of a set carries the identifier of the overload that it aims at, which `GeneratorTests` read. A call that is refused on purpose — a call of `math.greatest` or `math.least` that the macro refuses, a constant format string with a constant list that the check of `format` refuses — carries a fault, and the whole expression then fails on both sides, so it is no case of the test that every expression type checks. The cases of the standard library profile and those of the sets share one manifest and one environment: a standard case runs in the environment with the sets, and the overloads that the sets add do not change the expressions of a standard case. The standard cases for the same seed and number stay as they were, since the stream of random numbers did not change, so a reproduction by `--seed` and `--case` and a signature that it found do not move; the sets take the cases 2, 5, 8 and so on, about a third of a run.

**The manifest** gets `extensions`, the entries `{"name": "strings", "version": "5"}` and so on for the eight sets, in the order above. Both sides read the file: the library through `Apply` and the catalog, the oracle through `cel.FromConfig` with `ext.ExtensionOptionFactory`, and for `network`, which cel-go v0.32.0 does not know by name, through the factory of the oracle ([eng-oracle.md](eng-oracle.md#environment-from-the-manifest)). `ManifestTests` asserts that the names and versions of the manifest are those of the catalog, so the two sides cannot hold different sets. The code of the oracle does not change.

**Nodes.** The generator builds every function and macro of the sets for the argument types it fits, at the limits of the profile; a `dyn` operand is allowed wherever the oracle's overloads fit the values that reach it.

**Nodes of an abstract type.** The oracle returns a value as `cel.expr.Value`, which has no form for `net.IP` or `net.CIDR`: a result of that type ends the oracle with exit code 1. So the generator confines such values: a node of type `net.IP` or `net.CIDR` stands only as an argument of `string`, `==`, `!=`, `type`, `containsIP`, `containsCIDR`, or as the receiver of the predicates, `family`, `isMask`, `masked`, `prefixLength` and `ip()`; never as the root, under `dyn()`, `?:`, a list or map literal, a comprehension or `in`. A node whose value can be abstract has an abstract static type. The minimizer, when it evaluates such a node as a case of its own, evaluates `string(<node>)` on both sides and compares the texts, so an abstract node is a child like any other.

**Known signatures.** Six records of the registry belong to the sets. Four are `string_index_of_string_int(string, string, int) we-error` and `string_last_index_of_string_int(string, string, int) we-error` for an offset above the length, which is an error here and `-1` in cel-go, and `string_to_ip(string) stage-mismatch` and `string_to_cidr(string) stage-mismatch` for a literal argument that is not an address, which cel-go rejects at compilation and the library at evaluation. The generator makes each of the four at about one case in twenty of its function, and a literal argument that fails and a `dyn` or variable argument of the same text both occur: the second agrees on both sides. Two belong to `json.encode`: `json_encode_dyn(duration) value-mismatch` and `json_encode_dyn(timestamp) value-mismatch`, which come from the text of `string()` that cel-go writes for a time value in JSON (the seconds of a duration through a 64-bit float, the offset of a parsed timestamp kept); a list or a map that holds such a value is another signature, which the descent does not take apart, since its elements agree. A new signature of these functions is a finding like any other. The profile makes no map with a key of another kind than `int`, `uint`, `bool` and `string` and no repeated key, as before.

**`ExtensionGeneratorTests`** check, for fixed seeds: every overload of every set occurs, by the identifier that a call carries, and every macro and special form of the table above, with each of its refused forms; no case has a root, a child or a macro range of an abstract type, and an abstract node stands only as an argument of `string`, `==`, `!=`, `type` or of a method of the set; no list of `sort` or `sortBy` has more than 12 elements; no element of a format list is bytes that are not valid UTF-8 or a variable of `dyn`, and a case whose format call takes `lx` binds `lx` to bytes of valid UTF-8 (`WithValidUtf8Bytes` replaces each byte of an invalid sequence with `?`, keeps valid sequences, and reaches into lists and maps); no `cel.bind` binds a value of the static type `type` — an identifier of a type or `type(x)` — without `dyn()`, and such a value in `dyn()` occurs, among the cases of a sample and the 26 cases of seed 277579806 that the run on `108b881` reported, where `cel.bind(bn1, (list), …)` was a program error at cel-go; the limits of depth, nodes and nested macros hold, and each name of a macro is read inside it; the whole run type checks except the cases that fault on purpose, which the generator marks; each call marked with the fault `format` is refused when the library compiles it, with the code 2010, and the format calls without the fault compile; the texts of `ip` and `cidr` have every form that the page lists, and the library tells valid ones from invalid ones among them.

## Findings and output

| Code | When | Place |
| :- | :- | :- |
| `ENG820` | a new signature | the `test` token of its case in `pending.textproto` |
| `ENG821` | the Go of the oracle, named by the handshake, differs from the `go` line of `eng/oracle/go.mod` | that line, column 1; the message names both versions |
| `ENG822` | a time zone offset differs from Go | the time zone data file of the repository, `(1,1)`; its path is a constant of `Profile/` |

`ENG822` compares the offsets of every zone of the time zone data file at generated instants: `ICaseSide.ZoneOffset(string zone, DateTimeOffset instant)` gives the offset from UTC as a `TimeSpan`. The message is `time zone offset differs from Go: zone '<zone>' at <instant>: Go <offset>, we <offset>`, with the instant in UTC in ISO 8601 and the offsets as `±hh:mm` or `±hh:mm:ss`. The file is `tests/Great.Parts.Cel.Conformance/ZoneInfo/zoneinfo.zip`, the constant `ZoneInfoPath` of `Profile/` ([tests.md](tests.md#time-zone-data)); the comparison takes the path as a parameter. Every entry of the archive that is not a directory is a zone, in the order of the archive.

- **Instants.** `ZoneOffsets.Instants(seed, 256)`: whole seconds in the years 1800 to 2199, drawn from the seed alone, so the same seed gives the same instants; the range begins before the first transition of the zones that have transitions in the 1800s, where Go and the library may differ, and reaches past the last transition of every zone, where the rule of the footer decides. Five fixed instants join them: 1800-01-01, 1900-01-01, 1970-01-01, 2037-01-01 and 2100-01-01 UTC.
- **One divergence** is one zone: its first instant, in that order, at which the offsets differ is the finding, and the other instants of the zone are not compared.
- **When.** After the handshake and before the cases, inside the budget. For some six hundred zones it is about 160 000 pairs: a few seconds on the library side, and the answers of the oracle in well under a minute. A run with `--case` does not run it.
- **Oracle side.** `ICaseSide.ZoneOffset` is the request `offset` of the oracle ([eng-oracle.md](eng-oracle.md#protocol)): the offset in seconds that `time.LoadLocation` gives for the zone at the instant. `ZONEINFO` names the same file, so a zone is the same bytes there as here.
- **Library side.** `ICaseSide.ZoneOffset` goes through the public API, with no member of the library for it: one expression `[timestamp(s).getFullYear(z), timestamp(s).getMonth(z), timestamp(s).getDate(z), timestamp(s).getHours(z), timestamp(s).getMinutes(z), timestamp(s).getSeconds(z)]` over the variables `s` (`int`) and `z` (`string`), compiled once per run and evaluated for each pair. The local time is built from the six fields with `DateTime`, a calendar that is not the library's, and the offset is its seconds minus `s`; so a fault of the library's calendar shows as a divergence too. An error of the evaluation is `SideFailureException`, exit code 2: the library must answer for every zone of its archive at every instant of the range.

```text
tests/Great.Parts.Cel.Conformance/Regression/pending.textproto(6,3): error ENG820: new divergence signature 'add_int64(int, int) we-value' (S1): cel-go returns error 'integer overflow', we return int -9223372036854775807; seed 20261104, case 1207
difftest seed=20261104 commit=9f8e7d6c oracle=0.32.0 cases=412345 signatures new=1 (S1=1, S2=0) known=0 new-cases=1207
```

In the message of `ENG820` an outcome is one line: a value as its type and its value, `int -9223372036854775807`; an evaluation error as `error '<message>'`; a compile error as `<stage> error '<message>'`, with the stage `parse`, `check` or `program`. A message is cut at its first line break.

The journal line comes last; `commit` is the start of `HEAD`. `new-cases` lists the numbers of the kept cases, separated by commas without spaces, and stays empty without new signatures: `new=0 (S1=0, S2=0) known=0 new-cases=`. Exit code: 0 without new signatures, 1 with a finding with `error`, 2 for an invalid invocation, a refused manifest, a failed oracle, its steps included, or a minimized case that agrees when it is run again, since a side is then not deterministic. The messages of exit code 2 go to standard error, the rest to standard output. `eng/run` passes the code on; its failed `dotnet build` of `eng/difftest` is 1 ([eng-test.md](eng-test.md#engrun)).

With `--numbers-only` standard output has the journal line alone: no `log` line and no finding, `ENG821` included. The journal line comes after `ENG821` too, with `cases=0` and exit code 1, a pair that no other finding gives. A message of exit code 2 quotes no case and no line or answer of the oracle, since those can carry expressions and values: a minimized case that agrees again is named by the seed and its number, which `--case` reproduces, and so is the case in progress when the oracle fails or closes the connection: `case <n> of seed <s>: the oracle closed the connection before the answer to request <r>; the log lines above say why`. The log lines of the oracle are not in the public log with `--numbers-only`, so the number is what a maintainer takes to the generator (`CaseGenerator.Case(seed, n)`) and to a probe of the oracle.

## Provider of protobuf on the library side

The stand adds a protobuf provider to the library side of every run, with no file of its own: the environment of step 2 gets `AddTypes(new CelProtobufTypesBuilder("difftest").Build())`, a provider that describes the known types of protobuf and nothing else, and `eng/difftest` references `src/Great.Parts.Cel.Protobuf` for it, through its public API like the rest of the library. The oracle needs no change: the environment of cel-go has `Any`, `Struct`, `Value`, `ListValue` and the wrappers by default, so a manifest that names the type `any` resolves on both sides — on the library side only with the provider, since `any` without one is `TypeNotDeclared` ([configuration.md](configuration.md#protobuf-names-and-the-set-protos)). That is why the stand adds it always and not by the profile.

The profile does not change: it has no message type, no variable of the type `any`, no message literal and no `protos` macro, so the run draws no case that the provider changes, and a new signature after this part is not expected from it. The manifest lists no set `protos`; messages and their extensions are tested by the conformance runner, which has the test messages ([conformance.md](conformance.md#messages-any-and-the-provider-of-the-cases)), and by the examples and property tests of the library. A later profile that generates messages needs a message that both sides know — a `.proto` compiled for the library and a descriptor set for the oracle — and comes with its own part.

`LibrarySideTests` get two tests: the library side of the manifest of the profile has the provider, so a test manifest with a variable of the type `any` builds, and `google.protobuf.Int32Value{value: 1} == 1` and `google.protobuf.Any{}` give `true` and the error `InvalidAny` through `ICaseSide`. `ManifestTests` still assert that the manifest of the profile builds on the library side without errors.

## Nightly run

`.github/workflows/difftest-nightly.yml` runs `eng/difftest` every night and, by hand, for the long run before a release, with the command of the container check, so the run on GitHub is the run on a developer machine; the oracle is the service `oracle` of Compose, so the workflow has no Go setup.

| Item | Value |
| :- | :- |
| Triggers | `schedule` at 01:17 UTC every night; `workflow_dispatch` with the inputs `budget` and `seed` |
| Branch | `main` only: a manual run from another branch is skipped |
| Runner | `ubuntu-latest` |
| Command | `docker compose -f eng/compose.yaml run --rm -T difftest --numbers-only --budget <budget> [--seed <n>]` |
| Checkout | the whole history, so `eng/run` reads the commit and the state of the tree |
| Budget of the night | `20m`. With the image build and a cold module cache of Go the job takes 20 to 30 minutes; its time limit is 60 minutes, which holds the limit of `eng/run` for the run (24.6 minutes, [Invocation](#invocation)) |
| Budget of a manual run | the input `budget`, `2h` by default: the long run before a release is 2 hours or more. The job limit is 360 minutes, the longest a job may take. The input is a whole number and `s`, `m` or `h`, as `--budget`; another form fails the run with exit code 2 before it starts |
| Seed | the input `seed`, a whole number; without it the date in UTC as `yyyyMMdd`, as locally |
| Concurrency | one run at a time; a started run is not cancelled |

The log of the workflow is public, and a divergence can be an input that crashes a parser. So the run has `--numbers-only`: standard output holds the journal line alone ([Findings and output](#findings-and-output)), and the step summary of the run holds that line and the budget, nothing else. A new signature shows in the line as a count and the numbers of its cases (`new=2 (S1=1, S2=1) known=3 new-cases=1207,88391`); the case itself is reproduced on a machine of the maintainers with the same seed and `--case <n>`, and the text of a case reaches an issue only after the divergence is fixed.

The result of the workflow is the exit code of `eng/difftest`, passed through `eng/run` unchanged: 0 without new signatures is green; 1 (a new signature, a failed build or a step that ran out of time) and 2 (a failed oracle or an invalid input) are red. A run that ends with 0 and no journal line is red too. The release takes a green manual run, 2 hours or more, on the commit of the tag.

## Run on a push to main

`.github/workflows/difftest-main.yml` runs `eng/difftest` on every push to `main`, with the command of the container check, as the nightly run does. A change of the core is checked against cel-go here, in CI, and not on a developer machine: the run is not made before the push, on a branch or on a pull request, and the commands of this page stay for a manual run and for the reproduction of one case ([Reproducing a case](#reproducing-a-case)).

| Item | Value |
| :- | :- |
| Trigger | `push` to `main`; no `pull_request`, no `schedule`, no inputs |
| Runner | `ubuntu-latest` |
| Command | `docker compose -f eng/compose.yaml run --rm -T difftest --numbers-only --budget 10m --seed <seed>` |
| Checkout | the whole history, as in the nightly run |
| Budget | `10m`. The run replaces the run of the closing of a change of the core, which a developer machine made with the default budget of 5 minutes; the budget is twice as long, so a push draws at least as many cases as the run it replaces even on a slower runner. A push is checked after it has landed, so a long run costs only time: the job does not hold up another job of `ci`. The value is the variable `BUDGET` of the workflow; the first runs show the number of cases, and the budget changes there |
| Time limits | `eng/run` limits the run to 12.6 minutes (budget × 1.2 + 36 s, [Invocation](#invocation)); the job limit is 40 minutes, which holds the build of the image, the build of `eng/difftest`, a cold module cache of Go as well; the wait for a quiet host is off in CI ([eng-test.md](eng-test.md#waiting-for-the-host)) |
| Seed | the first 8 hex digits of the commit read as a whole number, from 0 to 4 294 967 295. Every push draws other cases, where the date of the nightly run would give the same cases to every push of a day. The seed is in the journal line and in the title of the step summary |
| Concurrency | one run at a time; a started run is not cancelled, and of the pushes that wait only the newest runs |

The log is public, so the run has `--numbers-only` and the step summary holds the journal line alone, as in the nightly run ([Nightly run](#nightly-run)). The result is the exit code of `eng/difftest`: 0 without new signatures is green; 1 (a new signature, a failed build or a step that ran out of time) and 2 are red; 0 with no journal line is red too. A red run on `main` is fixed by the next commit, as any red job of `ci`.

### Reproducing a case

The journal line of the summary has what a maintainer needs: `seed`, `commit` and `new-cases`, the numbers of the kept cases. Case `n` depends on the seed and `n` alone, so the maintainer checks out `commit`, runs `docker compose -f eng/compose.yaml run --rm difftest --seed <seed> --case <n>` and gets the same minimized case and the same signature, with the text of the case on standard output (the working tree stays clean) and the finding that `--numbers-only` kept out of the public log. Nothing else of the run is needed. A run that ends in `ENG821` has `cases=0` and no case to reproduce: the Go of the oracle is wrong.
