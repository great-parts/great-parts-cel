# CEL Policy conformance skip list

Cases of the pinned commit of the CEL Policy suite (tests/cel-policy/VERSION) that may fail in the given scope. Every entry has a reason and, before a release, an issue. An entry is a difference of this library from the implementation that the suite was written for, or an input of the suite that the runner cannot give.

| Case | Scope | Reason | Reference | Issue |
|---|---|---|---|---|
| compile_errors/aggregate_false_condition/compile/false_condition | * * * | The suite was written for a newer implementation than the pinned cel-go v0.33.4. The case expects the substring 'condition is always false'; the library reports 'Condition is always false', the text of cel-go v0.33.4 (its tests in compiler_test.go expect the capital letter), so the oracle itself gives the text of the library. The policy is rejected as the case expects. | Minimal case: tests/cel-policy/compile_errors/aggregate_false_condition/policy.yaml; the error text differs from the expected substring in its first letter only. | https://github.com/great-parts/great-parts-cel/issues/8 |
| compile_errors/aggregate_heterogeneous_outputs/compile/incompatible_types | * * * | The suite was written for a newer implementation than the pinned cel-go v0.33.4. The case expects the error of the third output of an aggregate rule (map(string, string) against int); the library reports the first disagreement only, as checkMatchOutputTypesAgree of cel-go v0.33.4 does, so the oracle itself gives the text of the library. The policy is rejected as the case expects. | Minimal case: tests/cel-policy/compile_errors/aggregate_heterogeneous_outputs/policy.yaml, three outputs of three types; one error is reported. | https://github.com/great-parts/great-parts-cel/issues/8 |
| compile_errors/syntax/compile/syntax_error | * * * | The suite was written for a newer implementation than the pinned cel-go v0.33.4. The case expects the message of the ANTLR parser, mismatched input 'resource'; the library has its own parser, as in every release, and reports "syntax error: expected ')', found 'resource'" at the same place, so the oracle v0.33.4 gives the text of the library. The policy is rejected as the case expects. | Minimal case: tests/cel-policy/compile_errors/syntax/policy.yaml, the expression variables.want.filter(l, !(lin resource.labels)). | https://github.com/great-parts/great-parts-cel/issues/8 |
| context_pb/invalid/bad spec | * * * | The key context_variable is outside the format of the environment description. The category declares its inputs with it: the fields of a protobuf message are the variables of the environment, and a test gives the message in context_expr. The environment description of the library has no such key, so the variables are undeclared and the policy does not compile. | Minimal case: tests/cel-policy/context_pb/config.yaml, context_variable of the message cel.expr.conformance.proto3.TestAllTypes. | https://github.com/great-parts/great-parts-cel/issues/9 |
| context_pb/valid/good spec | * * * | The same as context_pb/invalid/bad spec. | Minimal case: tests/cel-policy/context_pb/config.yaml, context_variable of the message cel.expr.conformance.proto3.TestAllTypes. | https://github.com/great-parts/great-parts-cel/issues/9 |
| k8s/invalid/restricted_container | * * * | The policy is a ValidatingAdmissionPolicy of Kubernetes, which cel-go reads with a tag handler of its own (test_tag_handler_k8s.go, a TagVisitor). The library has no handler of tags, so the document is rejected: unsupported policy tag: kind. | Minimal case: tests/cel-policy/k8s/policy.yaml, the keys kind, metadata and spec at the top. | https://github.com/great-parts/great-parts-cel/issues/10 |
